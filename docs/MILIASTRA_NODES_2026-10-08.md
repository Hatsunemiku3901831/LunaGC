# 千星节点 GIA 与结构化 JSON

## 操作流程

GM「千星资产」导入节点 GIA 后，点击「转为节点结构 JSON」。新 `.gia.json` 文件进入归档目录。
点击「导出原文件」，用文本编辑器修改内容，再以 `.gia.json` 后缀导入，点击「转为 GIA」下载生成结果。
相同内容按 SHA-256 去重；未修改的 JSON 转回 GIA 时，恢复来源文件的完整字节。
本页无需玩家 UID，授权与存储上限沿用资产库。

该结构文件和 WebMiliastraNodesEditor 的画布 JSON 是不同格式。
画布 JSON 使用字符串节点 ID、端口名称、界面控件与 overrides；本文件使用 proto 的节点编号、引脚与变量结构。
画布格式作为 `GRAPH_JSON` 归档，已接入带明确诊断的正向编译，见 [画布 JSON 转 GIA](MILIASTRA_CANVAS_2026-10-08.md)。
本页结构格式与画布格式仍分别处理；GIA 反向转换为画布、剩余节点与类型映射仍需继续接入。
实体和像素画集合也使用 GIA，但应通过实体生成器处理，不作为节点图合并。

## 格式

```json
{
  "format": "lunagc.gia.v1",
  "version": 1,
  "data": {
    "graph": {
      "id": {"class": 5, "id": 1073741824},
      "name": "节点图",
      "which": 9,
      "graph": {
        "inner": {
          "graph": {
            "id": {"class": 10000, "type": 20000, "kind": 21001, "id": "1073741824"},
            "name": "节点图"
          }
        }
      }
    }
  }
}
```

自动转换输出还包含 `source`，为原始 GIA 的 Base64。它不是优先于编辑内容的缓存：
只有结构内容与版本均未改变时才直接返回来源字节；修改后重新编码。
可以移除 `source`，按 `data` 创建文件。这样只保证 protobuf 内容一致，不保证字段原始排序或非规范 varint 字节一致。
文件名和 proto 中的 `filePath` 只作为元数据，后者不会作为磁盘路径使用。

每层使用 proto 定义的字段名；重复字段为数组，消息为对象，bytes 为 Base64，枚举为数值。
int64／uint64 输出十进制字符串，避免浏览器浮点数精度损失；导入支持范围内的整数或十进制字符串。
int32、uint32、float32、float64 均检查范围，拒绝分数整数、错误类型及非有限浮点数。
未知枚举编号保留；optional 的显式零值保留，oneof 同时出现多个属性会拒绝。

每层的 `$unknown` 是该消息未识别 protobuf 字段的 Base64。
它可保留未来字段和已知字段编号下不匹配的 wire type；不能注入能够被当前描述符识别的字段值。
修改已知字段时保留各层未知字段。修改后 protobuf 会重新编码，字段顺序和非规范编码可能改变。

结构化 JSON 与 GIA 各最多 32 MiB，嵌套最多 64 层，JSON／投影／恢复各最多 200 万个值。
因为 `source` 和可读结构会扩大文件，部分大型 GIA 转换结果可能超限；此时拒绝转换，原始归档继续保留。
生成的 JSON 会先验证可还原再归档。原归档的 2000 个文件、512 MiB 原文件总量及 4 MiB 元数据限制仍适用。
节点 GIA 要求单个主图，识别实体／状态／职业／道具图、客户端技能／布尔／整数过滤器、复合图与结构定义。
此处验证结构和数据类型，不解释技能玩法或保证图在客户端能执行。

## 协议依据

使用 [WebMiliastraNodesEditor 配套工具](https://github.com/Wu-Yijun/Genshin-Impact-Miliastra-Wonderland-Code-Node-Editor-Pack/tree/5d85fc474428686c6705be03ebd8b3139f1952f3)
的 MIT proto 1.5.1，其源码标注游戏 6.2.0。修改仅为包名、Java 生成类选项与来源注释。
描述符由现有 protoc 构建，不新增运行依赖；许可全文随 JAR 打包。
网页侧 1.3 导出器会跳过客户端节点和输入常量，不能直接用作完整转换器。
配套 1.5 中客户端 Boolean／Float／String 的类型分别为 5／7／9，服务端分别为 4／5／6；不混用类型映射。
新版还记录客户端执行引脚、过滤器输入、复合引脚编号和图的可选字段。

## 接口

`POST /gm/api/miliastra/{SHA-256}/convert` 转换已归档的节点 GIA 或结构 `.gia.json`，无需请求体。
新结果返回 201，已有相同内容返回 200；身份校验 403，参数／结构错误 400，资产不存在 404。
结构文件类型为 `GIA_JSON`，普通画布 JSON 类型继续为 `GRAPH_JSON`。
原始上传和下载接口不变；GIA_JSON 的全部主资产 GUID 纳入归档冲突与自动编号检查。
