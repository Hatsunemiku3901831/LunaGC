# 分离服务的请求与响应匹配

## 来源与复现

继续核对 AstaPS 固定提交 `7cc148d1f752a43d4b9146b3b73f26875902546f`
与本地 `IDispatcher`、Dispatch 客户端／服务端和账号传递路径。
两边原有调用只按响应包号登记回调；第一份响应会调用该包号下的所有回调。
这会使并发账号查询、令牌校验或其他同类请求收到同一份结果，超时后回调也没有清理。

首轮 13 项检查中，11 项断言失败、2 项对照通过，错误和跳过均为零。
另外分别用单项断言复现了已中断调用仍发送、一个旧式回调异常影响其他回调，
以及中间实现错误拒绝负数内部包号的问题。

## 请求与响应

每次 `async`／`await` 请求都有独立 UUID。内部 JSON 包新增：

| 字段 | 用途 |
| --- | --- |
| `requestId` | 本次请求的 UUID |
| `replyId` | 本次请求期望的响应包号 |
| `responseTo` | 响应所对应的请求 UUID |

响应必须同时匹配当前 dispatcher、请求 UUID 和响应包号，才会完成对应 future。
其他请求、重复包、取消后的迟到包和未知 UUID 不会消费新请求的回调。
未带关联标识的旧式响应也不能完成新的关联请求。
保留现有有符号内部包号，包括 GM 请求 `-157`；拒绝零值和越界／非整数编号。

现有同步处理器在请求上下文中回包时，客户端和服务端都会带回对应标识。
上下文同时核对目标连接和期望包号；其他通知不带该请求的响应标识。
嵌套请求结束后恢复上一层上下文，处理器抛异常后也会清理。

## 等待与回调生命周期

- 默认等待上限仍为 5 秒，异步调用也有截止时间；可显式传入正数 `Duration`。
- 完成、超时、取消、解析失败或发送失败都会移除本次回调。
- 客户端连接关闭时，该客户端的待决请求会异常结束。
- 已中断的同步调用不发送请求；等待期间中断会保留中断标记并取消等待。
- 回调登记、选择与删除在同一映射锁下执行；先取出本次回调，再调用用户代码。
- 旧式通知回调仍可使用 `registerCallback`，一次调用后移除。
  回调可登记下一次监听，一个回调的运行异常不阻止其他已选回调执行。

超时或取消只终止本地等待，不代表远端操作已经取消，也不是对远端副作用的回滚。
调用方不能因为没有收到响应就假定有副作用的操作尚未执行。

## 接入的调用方

现有账号查询、玩家字段查询沿用统一的 `await`。
原来自行登记回调的游戏令牌校验、抽卡记录查询和 GM Handbook 操作也改为统一入口。
令牌校验还会检查响应账号 ID 和登录令牌是否对应本次请求，
不能只凭响应中的 `valid=true` 接纳另一账号或令牌。

源码中这些 RPC 调用方已不再直接登记宽泛包号回调。
这一步先保证账号副本传递不会因并发响应混淆；JSON 账号副本的可写绑定仍需继续接入。

## 部署和适配边界

分离部署需要同步升级请求端和响应端。旧构建不会回传这些关联字段；
新调用不会退回仅按包号匹配，混用时可能得到超时或未收到响应。

自动回传覆盖现有同步处理器。自定义异步处理器的显式上下文传递、
完整重连生命周期、多游戏服定向路由、远端账号可写副本、缓存账号刷新和并发登录跨重置边界，
仍需继续适配。现有连接鉴权也没有因此变成新的跨服身份体系。

本轮没有启动游戏；此前反馈的游戏错误仍待实机复验。
