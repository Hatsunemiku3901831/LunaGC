# 千星镜头提取、编辑与原始来源保留

## GM 操作

1. 在「千星资产」导入或选择镜头 GIA，点击「提取镜头 JSON」。
2. 筛选「镜头配置 JSON」，选择生成的 `.camera.json`，点击「编辑镜头 JSON」。
3. 修改镜头列表中的 `assetName` 或 `data`，点击「保存镜头副本」。
4. 选择新归档并点击「转为 GIA」，再「导出原文件」。原始 GIA 和配置均保留。

编辑窗口只显示镜头列表，完整来源由服务端提取后自动携带；没有将 Base64 内容塞入编辑窗口。
也可以下载完整 `.camera.json`，在外部编辑器修改后重新导入。
操作不需要玩家 UID；沿用 GM 令牌与回环限制。桌面与手机均支持编辑、错误提示和关闭。

原文件的前 100 项预览没有覆盖所有资产时，仍提供提取操作；服务端扫描完整 GIA。
没有可识别镜头的文件会返回诊断，不会发布空配置。

## 文件与字段

镜头文件类型为 `CAMERA_JSON`，扩展名为 `.camera.json`，格式标记为 `lunagc.camera.v1`：

```json
{
  "format": "lunagc.camera.v1",
  "source": "完整原始GIA的Base64",
  "cameras": [
    {
      "assetIndex": 0,
      "detailIndex": 0,
      "assetGuid": 1100000000,
      "cameraGuid": 1100000000,
      "assetName": "资产名称",
      "data": {"name": "镜头名称"}
    }
  ]
}
```

上例仅示意结构。实际提取的 `data` 包含原协议全部已知字段；重新导入须保留完整字段集。
`assetIndex` 是主资产与关联资产的顺序索引，`detailIndex` 是该资产内部的镜头详情索引。
两类索引、编号、镜头数量和顺序不能在此文件中修改。创建新镜头使用生成器；
复制并重新编号先转回 GIA，再使用已有 GUID 工具。

`assetName` 是资产名称，`data.name` 是镜头名称，可分别修改。
同一资产有多个镜头详情时，各行的 `assetName` 必须一致。
新名称须为合法 UTF-8、最多 4096 个 Java 字符；源文件中的未修改名称按原样保留。

`data` 使用 proto 对应的 camelCase 字段：

| 字段 | 编辑规则 |
| --- | --- |
| `cameraMode` | 原生模式 0–4，经典模式为 0；与生成器中的模型模式 5 区分 |
| `defaultDistance`, `minDistance`, `maxDistance` | 修改值为 0.1–50；修改视距后检查最小 ≤ 默认 ≤ 最大 |
| `fieldOfView` | 修改值为 30–60 |
| `horizontalAngle`, `minHorizontalAngle`, `maxHorizontalAngle` | 修改值为 -180–180；修改范围后检查下限 ≤ 上限 |
| `minPitchAngle`, `maxPitchAngle` | 修改值为 -89–89，修改范围后检查下限 ≤ 上限 |
| `viewpointOffset.x/y/z` | 有限 float32 |
| `followRotation` | 布尔值 |
| `ignoreCollision` | 原始协议中的数值，修改值为 0–1，保留小数；与新镜头生成器的布尔开关区分 |
| `field14` | 未知字段，仅检查有限 float32，不猜测既有配置的含义或范围 |

未知模式、旧范围或省略后为零的原值可以保持，修改其他字段不会重置它们。
原始默认 `camera_data` 或偏移消息被省略时，提取显示默认值；未修改时不补写消息，
确实修改后才写入对应配置。非有限数值、float32 溢出和非零下溢拒绝。

## 保留与限制

未修改时恢复完整原始 GIA 字节，包括非规范 varint、字段顺序、未知字段和消息存在性。
修改后只重新编码改变的镜头资产；其他根字段与资产继续使用原始字节。
镜头元数据、依赖、详情编号及各层未知字段保留；未改变的镜头详情保留原生内容。
改变的镜头资产内 protobuf 字段顺序或 varint 编码可能规范化，不声称修改后仍逐字节相同。

完整主镜头和关联镜头均可提取；仅元数据的关联条目保留在来源中。
只支持容器版本 1 的已知镜头协议，不解释同文件中的其他复杂资产或未知字段。
源 GIA 的容器、元数据及边界继续校验；缺少配置／详情的镜头资产、损坏 protobuf 会拒绝。
错误类型、缺字段、未知 JSON 属性、重复 JSON 属性和编号／索引篡改都会拒绝。
GM 编辑窗口保留用户原始 JSON 文本，重复属性也交由服务端严格检查，不能被前端解析悄悄覆盖。

JSON 与输出 GIA 各最多 32 MiB，镜头详情最多 100000；JSON 值数量另有 2000000 上限。
来源 Base64 和字段展开会增大 JSON，因此部分接近 32 MiB 的 GIA 无法投影；原文件保留。
归档存储和元数据使用原有容量限制。编辑文件沿用原编号，会出现与原归档的冲突提示；
两个版本应择一导入编辑器，不应把它们同时合并为两套同编号资产。

只有 `.camera.json` 时，镜头生成和 GUID 复制也扫描它编码后的已知编号与依赖，避免占用来源中的编号。
归档导入按完整 SHA-256 去重；未修改配置转回 GIA 会复用原归档。

## 接口与来源

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/gm/api/miliastra/{SHA-256}/camera` | 提取镜头配置并归档 |
| POST | `/gm/api/miliastra?name=文件.camera.json` | 校验、导入配置或保存编辑副本 |
| POST | `/gm/api/miliastra/{SHA-256}/convert` | 镜头配置转回 GIA |
| GET | `/gm/api/miliastra/{SHA-256}/download` | 完整文件下载 |

新归档为 201，重复为 200，格式／参数错误为 400，未授权 403，不存在 404，超限上传 413。
具体镜头生成路由在通配提取路由之前注册，避免 `/generate/camera` 被当作资产 ID 请求。

行为参考固定 [UGC-File-Generate-Utils](https://github.com/luern0313/UGC-File-Generate-Utils/tree/fba7c267a3752d3f0108b30020c46868d56acdd5)
的镜头提取与模型，二进制使用其 MIT proto 子模块 `c56862b4fe2cb1d8dac5fdb6fb738ad559641ca2`。
独立实现直接读取 GIA，未执行参考 Python 的文本转储解析器。
许可和固定来源仍随原有资产协议、镜头模板资源打包。
