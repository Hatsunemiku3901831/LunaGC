# 燃素倍率控制

## 接入与计算

- 普通动作及周期 mixin 保留原始 `JDIMELLBMFO` 开关；可读配置名 `useRatio` 优先，明确 false 不被原始 true 覆盖。
- 当前周期 Cost 的扣除量为 `speed × interval × 当前所选燃素存量`，每次读取更新后的值。关闭倍率时仍按绝对点数执行。
- 补充和普通动作设值的倍率按池容量计算：队伍 100、龙 50；倍率 1 的 Add 可从空池补满，不再只补 1 点。Cost／Sub 倍率使用当前存量。
- 倍率计算与燃素写入在同一锁内执行，保留零值、上限及无限燃素控制。负倍率不反向产生奖励，无效表达式不执行。
- 周期 mixin 兼容原始目标 `BBIPIGDBGFJ`，可读 `targetType` 优先。Team、Vehicle、Self、Auto 使用各自所选池；空 Vehicle 不转扣队伍，Auto 可回退。
- Auto 遇到车辆存量为 NaN／无穷数会拒绝，不能把坏状态当作空池后转扣队伍；明确 Team 不读取无关车辆存量。
- 原来的旧 ratio/determineType 配置继续按绝对数值处理；这里的 `useRatio` 是百分比模式，和动态表达式操作数 `ratio` 分开。

## 依据及边界

当前经 SHA-256 校验的配置 31489 在 `+0x50` 持有倍率开关、`+0x54` 持有目标；
`0x151fa0d50` 将两者传入 `0x151a1a9a0`。
该方法在开关为 true 时读取所选池 `+0x20` 乘以扣除量；
池类型 84642 的 `0x14aa4ec20` 读取同一当前值，`0x14b4da140` 则将它除以 `+0x18` 的上限。
因此周期 Cost 使用当前存量，不应误写成消耗效率或上限倍率。

动作配置 87220 的倍率开关为 `+0x6c`。当前资源有 20 处原始开关，均为 Add=1，
包括活动 InfinitePhlogiston 初始化和场景补满燃素。
这些补充配置使用容量基准，是从资源用途得出的兼容实现；其动作原生入口 `0x147b469f0` 只转交 ILFix，
本次没有宣称已解出客户端热修复中的全部 Add／Set 计算分支。
普通 Set 的容量倍率及周期 Add 倍率已提供服务端语义；当前资源没有开启该开关的对应实机样本。

持续 Set 的 timer 语义仍未配对，继续拒绝执行。吸附动画、龙技能和完整当前客户端流程仍需实机验收。
日常运行服务未替换。
