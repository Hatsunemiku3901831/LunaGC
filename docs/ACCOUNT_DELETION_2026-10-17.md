# 账号删除的退出、写入排空与清理确认

## 来源与复现

继续核对 AstaPS 固定提交 `7cc148d1f752a43d4b9146b3b73f26875902546f`
的 `AccountDeletionService`、`DatabaseWriteBarrier` 和写入管理器的准入／排空行为。
本地删除在没有角色时直接返回，并把清理作为另一项异步工作提交，
无法在返回时确认完成，日常委托、场景组和曲谱等数据也没有纳入清理。

隔离 Mongo 首轮 20 项检查中，8 项断言失败，12 项正向对照通过，错误和跳过为零。
随后另用 1 项检查复现了“UID 归属已确认但角色文档缺失时，账号下的物品未被清理”。

## 删除入口

GM／控制台继续使用 `account delete <username>`，权限与命令参数没有改变。
该入口现在等待本次删除确认完成后才返回；失败会传回调用方，不发送完成提示。

流程固定当时的游戏 Datastore、账号 Datastore、账号 ID 与服务器注册表：

1. 请求目标账号当前在线会话退出，等待注销及退出保存提交，默认最多 10 秒。
2. 暂停新的数据库写入准入，排空已经接收的队列、调用线程执行和确认写入，默认最多 30 秒。
3. 重新检查在线状态，只读取得角色 UID 和已有 UID 归属。不会为清理而解码完整 Player 或触发加载回调。
4. 先校验所有 UID 与归属，再清理已知数据，最后删除角色与账号并核对结果。

没有角色的账号仍会删除。已有持久 UID 归属时，即使角色文档已经缺失，
也可以清理该 UID 下的已知数据；归属记录本身继续保留。
旧账号存在多个合法角色文档时一并处理，不只删除第一份。
零／负数、控制台、超出 int32 的编号，以及与另一账号归属冲突的记录，均在删除前拒绝。

当前 KCP 退出回调由游戏逻辑线程执行。在线账号的删除不能在该线程内等待自己的注销回调，
因此会直接拒绝；控制台与 GM HTTP 命令线程可以正常等待。

## 清理范围

| 数据 | 归属字段 |
| --- | --- |
| 成就、活动 | `uid` |
| 家园、持久建造、邮件、任务、纪行、日常委托、场景组 | `ownerUid` |
| 角色、抽卡记录、物品 | `ownerId` |
| 玩家曲谱 | `authorUid` |
| 历史 `open_world_spawns` 记录 | `ownerUid`；兼容参考旧记录，本地没有因此新增生成系统 |
| 好友关系 | 同时处理 `ownerId` 与 `friendId` |
| 角色文档、账号文档 | 固定账号 ID 和已经核对的 UID |

保留 `account_uid_owners`、`player_uid_reservations` 与全局编号，
避免删除账号后重置计数器把 UID 交给另一身份。
其他账号、其他 UID 的记录及非目标好友关系均保留。

## 写入屏障

`DatabaseWriteBarrier` 给现有 `DatabaseWriteQueue` 增加统一准入计数：

- 包含排队工作、队列饱和时在调用线程执行的工作，以及已确认的直接写入。
- 对普通保存的合并入口也先检查准入，不能借已有队列快照绕过暂停。
- 已接收的写入可以完成其嵌套或后续队列写入，屏障等待这些工作一起结束。
- 屏障持有者可以同步执行维护操作；其他线程的新写入会被拒绝，持有者也不能再派发异步写入。
- 超时、异常和中断会释放准入暂停，中断标志保留；维护者身份和嵌套关闭均有检查。
- `DatabaseHelper.awaitIdle` 也检查已接收的直接写入，不只查看线程池。

接入了正式保存队列、`saveGameSync`、账号创建、编号／UID 预留及首次建档入口，
以及 Player、Item 和 Activity 版本保护的实际 Mongo 写入。
没有替换现有的版本校验、保存重试与按对象／Datastore 合并规则。

此屏障是本进程全局维护操作，持有期间会短暂拒绝其他账号的新写入，适合在维护时执行删除。
它没有自动拦截任意原始 Mongo／Datastore 直写。

## 保留的边界

多个集合的删除不是一个分布式事务。中途失败可能已经清理部分数据，
但角色与账号保留到后面处理，允许按原目标重试；结果不明不会按当前数量猜测成功。
旧档还没有 UID 元数据时，只能依据当前配置的账号库与角色 `accountId` 处理，
不能从旧文档推断原账号库；切库前仍需核对归属。

普通 Account 后续更新、删除后旧对象再次保存、尚未纳入正式入口的直接写入、
首次登录后半段与重连接管、其他服务进程以及真实网络／主从切换，仍需继续核对。
本轮没有宣称永久阻止所有来源的数据重建，也没有移植参考管理器的全部排序和关闭策略。
当前客户端退出画面及用户此前反馈的游戏错误仍未实机复验。
