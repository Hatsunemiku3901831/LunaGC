# 账号创建与原子编号分配

## 来源与复现

继续核对 AstaPS 固定提交 `7cc148d1f752a43d4b9146b3b73f26875902546f`
的 `DatabaseManager.reserveNextId`、`AccountCreationService` 以及角色 UID 分配策略。
本地仍使用读取计数器后异步保存的方式；即使方法有 Java `synchronized`，
下一次读取也可能早于排队保存。创建账号还会以普通保存方式替换同一 `_id` 的文档。

隔离 Mongo 的首轮 10 项检查中，9 项断言失败、1 项通过，错误与跳过均为零。
实际复现了重复编号、成功返回时账号未落库、同名多次成功以及旧账号被覆盖。
随后又用控制台的两种密码模式复现了“创建成功时初始权限尚未保存”，2 项断言均失败。

## 已接入

- 编号在 Mongo 中通过条件递增确认保存，使用多数确认与日志写入，不再排队回写计数器。
- 保留已有 `counters` 集合、按类命名的计数器，以及 10,000 的历史起点。
  分离运行时账号编号仍使用游戏数据库中的旧计数器，账号写入选择的账号数据库。
- 支持旧 int32 和 int64 计数；低于起点的合法旧值只向前推进，不回退较高编号。
  损坏的计数类型、负数及 int32 编号耗尽会报错，不截断、回绕或重置。
- 新账号只执行确认插入；同名竞争由唯一索引裁决，只有一个创建者返回账号。
  旧编号已占用时最多尝试 64 个新编号，始终保留旧账号完整内容。
- 新建入口先确认用户名唯一索引。指定正数玩家 UID 时，另确认仅覆盖正数的
  `reservedPlayerId` 唯一索引；普通账号的缺省 0 不参与唯一约束。
  已有玩家或控制台 UID 不接受新预留。
- 创建操作固定当时选择的账号与游戏 Datastore，切换运行模式或连接不会中途改变目标。
- 普通创建和旧密码创建 API 都走确认插入。GM／控制台 `account create` 先准备原有密码哈希和 `*` 权限，
  与账号一起插入后才报告成功，不再依赖后续异步保存补齐初始信息。
- 保留中文、点号和邮箱式用户名；没有照搬参考库禁止 `.`／`@` 的新用户名限制。
  空白新用户名不创建账号；已有用户名继续按原规则读取。

写入确认丢失会返回失败。若编号递增已落库，重试会使用后续编号，允许留下空号；
若账号插入已落库，同名重试不会另建或替换原账号。

  旧账号保留、数据库切换、保存前失败／真实写入后确认丢失、耗尽和无效计数、
  控制台初始密码与权限，以及原有角色创建和旧 UID 探测。

## 仍需核对

本项不代表整份 Account 已有玩家存档同等的版本隔离；普通密码、权限和会话后续更新仍需单独审阅。
角色 UID 的持久预留、未建角色的账号预留与自动分配协调，以及跨服务首次创建角色的完整裁决仍待接入。
账号文档与游戏数据库计数器之间没有增加跨库事务；插入失败允许消耗编号，禁止重用不明结果。

若旧数据含重复的正数预留 UID，或现有索引规格冲突，新指定 UID 的创建会报错；
本入口不会删除索引、修改旧账号或自动清理冲突数据。
计数器远远落后且连续占用超过 64 个编号时，本次创建明确失败，不覆盖旧账号；应先审阅计数器与已有数据。
原有登录策略、协议、资源和奖励数值未因此改变；当前客户端画面和此前游戏报错未实机复验。
