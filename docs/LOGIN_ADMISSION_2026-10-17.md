# 登录阶段与本地密码重置的并发保护

## 问题与范围

此前令牌校验和进入角色之间没有共同的准入记录。
密码重置已经完成，正在准备登录的旧连接仍可能继续建档、进入角色；
刷新会话账号还可能丢失最初客户端提交的令牌依据。

本批接入内置的四条路径：`GetPlayerTokenReq`、`PlayerLoginReq`、
`SetPlayerBornDataReq` 和延迟的默认角色创建。
本地账号来源的登录阶段与密码重置使用同一进程内的写入屏障，
同一来源、同一账号的登录阶段按顺序执行。

## 实现

- `AccountLoginAdmission` 保存客户端最初提交的令牌、账号来源、游戏数据库和连接归属。
  账号缓存刷新不会替换这份凭据；后续阶段重新查询当前账号，并核对原令牌和上下文。
- 已完成的密码重置、账号删除、有效封禁、来源切换或玩家／会话归属改变会拒绝后续阶段。
  同一账号的新握手替换先前登记的连接；不同账号和不同数据库中的同 ID 账号分别处理。
- 本地重置等待已接收的登录阶段及其写入退出屏障，确认凭据更新后，
  在维护范围内标记待登录和在线连接失效，再离开屏障请求关闭传输。
  `AccountCommand` 不再重复请求退出。
- 会话失效后不能重新设置为活动状态；路由入口拒绝包括 Ping 在内的后续消息，
  普通出包也停止。传输关闭请求防止重复执行，登录阶段内的关闭延后到退出屏障后执行。
- 在账号查询尚未返回时关闭连接，也不能继续执行准备回调。
  失败和关闭路径清理准入登记，后续有效连接仍可登录。

`GAME_ONLY` 同样保存原令牌并逐阶段重新查询远端账号。
另一进程中的密码重置尚未参与本地屏障，因此本批不提供跨进程的原子撤销保证。

## 复现与验证

- 初始旧实现的四项检查均以断言失败复现；独立的“查询期间关闭连接”检查
  先复现准备回调仍执行一次，再修复并通过。
- 新增 33 项检查覆盖真实令牌处理器的准备事件、UID 建档与响应，
  实际登录／角色创建入口、延迟创建回调、原令牌保持、并发重置、替换连接、
  账号和来源隔离、取消及登记清理、失效路由和出包。
- 最终专项三套、80 项通过；相关回归 25 套、491 项通过，失败、错误与跳过均为零。
- 使用独立 Mongo 数据库和可控传输。完整令牌处理器的正向用例通过测试玩家跳过资源场景读档，
  保留实际 UID／账号关联写入和响应构造；登录和创建入口用明确的探针终止业务。
  这些用例没有执行完整资源场景登录，也没有使用真实账号认证、重置、建档或删除。
- 两次夹具编译错误和一次缺失导入的尝试均保留，未计入测试通过记录。
  失败对照、最终报告和构建指纹保存在本地忽略目录 `debug/aster-mid-20261011/batch356`。
- 2,705 份 Java 主代码与测试文件匹配构建副本（允许换行差异），应用类匹配编译输出。
  相对上一构建，改变的类仅属于本批十个生产源码，新增加的八个类均属于准入实现。
  默认资源、开发资源、资源子模块及九个参考库的固定版本保持不变。

## 仍需适配

分离服务的主动失效通知与确认、多游戏服定向 RPC、异步回复上下文、连接代次与完整重连，
以及真实多进程的故障时序仍需接入。已在执行的普通游戏／后台敏感操作并未全部纳入本批屏障。
自定义代码直接调用 `Player.onLogin()` 也不自动获得上述内置入口的保护。

本批测试与本地服务检查不能证明此前报告的游戏错误已解决；客户端仍需单独验收。
