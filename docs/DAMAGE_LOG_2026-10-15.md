# 战斗伤害统计

参考 LunaGC_7.1.0 固定提交 `8be69a16c1410fc4233c4872996581317c876ffe` 的 DamageLog。
使用本地扣血结算入口，实现当前世界的按玩家／角色统计，不从客户端原始伤害直接累加。

## 使用

GM 的命令目录可直接选择 `dps`，选择顶部 UID 后执行；控制台也可输入：

```text
dps @10001
dps @10001 reset
```

查询输出角色伤害、承伤、命中次数、最大单次伤害、活跃时间及 DPS。
权限为 `player.dps`；操作其他玩家使用 `player.dps.others`。
统计覆盖目标玩家所在世界，包括该世界的其他联机玩家，重置也作用于整个世界。

GM HTTP 入口：`GET /gm/api/combat?uid=10001`、`POST /gm/api/combat/reset?uid=10001`。
沿用 GM 令牌与本地地址限制，必须指定在线玩家，不按 IP 或唯一在线玩家猜测目标。
返回使用 `no-store`；没有增加公开查询或免鉴权清空入口。
GM 路径的 404 保留真实状态和正文，避免被旧 SDK 的空成功兜底覆盖；其他路径继续使用原兜底。

## 结算与归属

插件取消和调整伤害、无敌及锁血判断完成后，才记录实际接受的扣血量。
致命伤害只记录目标剩余生命，不将溢出伤害累加到输出。
角色支付生命的能力不作为战斗承伤；角色承伤与输出分别统计。

攻击者必须仍为当前场景登记的实体，其他世界或已移除实体不能继续产生统计。
客户端召唤物在正常登记时记住原角色；切换前台角色后仍可归属到队伍中的原角色。
角色离开原队伍／世界或实体编号被其他物体复用时，不沿用旧归属；所有者链有循环和长度检查。
未知攻击者不自动归属到当前角色，也不虚增一行未知角色输出。

相邻有效输出间隔小于 5 秒时累计活跃时间，长时间停战不算入分母。
首击使用 1 秒下限；这是本项目统计口径，不表示官服客户端的伤害面板。
保留最近 40 次输出，角色行最多 256、召唤物归属最多 4,096 条，避免无限增长。
统计驻留于世界内存，世界销毁或服务器重启后重置；不写入玩家数据库。

## 验证

初始 22 项用例对照旧实现全部失败；退场角色归属与缺失显示文本分别保留修复前失败证据。
测试覆盖真实扣血、锁血、溢出、插件取消与调整、召唤物归属和编号替换、并发、历史上限、DPS 计时、
重置及快照隔离；独立 HTTP 检查查询和清空鉴权、目标检查与缓存控制。

证据在忽略目录 `debug/aster-mid-20261011/batch220/`。
首轮完整单元 **6,599 项／367 套件**通过；启动检查先暴露 GM 404 被覆盖。
修复该 HTTP 路径后重新运行 **36 项／2 套件**及启动／HTTP **2 项／1 套件**，全部通过。
去重合并报告为 6,601 项，不把专项重跑计算成第二次完整回归；最终变更限于 HTTP 兜底及其专项测试。
9,947 处输入一致，13 个已有运行类及 5 个新增运行类均与 JAR 字节一致，没有删除或非预期变化。
JAR SHA-256：`3f88f46bb3f749b426dff032e76362de47d69809776d9ce3f103e72ddda7dd74`。
