## 开启与优先级

在 `config.json` 的 `server.game.gameOptions.dungeonRewards` 中配置：

```json
{
  "referenceDropTables": false,
  "talentMaterialMultiplier": 1,
  "weaponMaterialMultiplier": 1,
  "relicEnhancementBonus": false
}
```

将 `referenceDropTables` 设为 `true` 后，执行无参数 `reload` 或重启。
匹配的增强条目会优先于自身根表和普通 `DungeonDrop.json`；未匹配的秘境继续走原有奖励路径。
它是可选增强：包含数量和稀有度分布变化，部分低难度也可能获得五星圣遗物。
默认关闭、旧配置缺省或整项为 `null` 时，原有数量和优先级保持不变。

此开关不自动启用材料三倍或祝圣材料追加。
如同时设置材料倍率或追加开关，先按增强目录完成普通／浓缩抽取，再应用
[独立奖励策略](DUNGEON_REWARD_POLICY_2026-10-17.md)。

## 文件与重载

- 增强目录优先读取运行数据目录的 `DungeonDropReference.json`，不存在时使用 JAR 内置版本。
  路径遵循 `folderStructure.data`，默认用户覆盖位置为 `data/DungeonDropReference.json`。
  用户文件替代整份内置增强目录；未包含的秘境 ID 回退普通路径。
- 普通 `DungeonDrop.json` 与增强目录分别持有快照、来源和加载状态。
  覆盖普通文件不会替代已开启的增强条目；要调整增强条目，请覆盖增强文件或关闭增强开关。
- `reload reference-drops` 强制重载增强目录；开关关闭时也可使用，加载成功不会自行启用增强。
- `reload dungeon-drops` 只重载普通目录。无参数 `reload` 重读服务器配置、普通目录，
  并在增强开关开启时重载增强目录。
- 开关开启的进程启动时加载增强目录；运行中首次启用也可延迟加载。
  下一次领取前检查来源／文件变化，沿用已验证的并发读取、完整快照替换和读取重试。
- 解析、结构或权重错误保留上一份完整快照；首次读取失败拒绝本次领取。

领取固定使用本次已选中的条目；重载不改变已经选定的候选分组。
自动文件读取不会启动额外轮询线程。内存 Reader 快照不关联磁盘来源，显式文件重载后恢复自动检测。

- 所有物品须在当前资源中有对应定义。

- 圣遗物须属于本秘境预览声明的套装；增强目录可改变其稀有度分布。
- 虚拟奖励仅允许本批使用的冒险阅历、好感经验和摩拉。

候选与当前资源不符时，本次领取拒绝，不扣树脂或浓缩树脂，修正后可重试。
不通过切换其他奖励来掩盖已选增强条目的错误。完整奖励仍通过原有整批容量检查和领取占用保护。
