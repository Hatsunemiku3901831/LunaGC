# 随行小道具与独立装备槽位

## 接入范围

采用 AstaPS 固定提交 `7cc148d1f752a43d4b9146b3b73f26875902546f` 中
`WidgetPetHelper` 的随行能力组方案，并按本项目当前资源、能力生命周期和协议重新实现。

- 快捷使用与随行槽位分别保存，装备宠物不覆盖快捷道具。旧记录中放在快捷槽的纯随行道具，在登录槽位同步或场景准备时迁移。
- 装备核对实际小道具类型、当前背包实例、玩家归属、数量及资源允许的槽位；错误操作、未知标签和未拥有物品返回错误。
- 卸下清空对应槽位，并返回实际操作和标签。查询及登录全量通知使用同一份槽位信息。
- 随行能力在进入场景信息前准备，场景初始化后同步能力组通知；切换、卸下、队伍实体更换和最后一个物品移除会更新能力状态。
- 动态能力 ID 与能力表索引保持对应；切换保留其他能力的 ID，重新装备复用该能力的保留槽位。旧客户端消息不能重建已卸下的宠物能力。
- 仅清理由此功能建立的实例及其效果；已有的同名其他功能实例保持其归属，替换后的外来实例也不被删除。
- 新的玩家字段 `widgetPetId` 保存随行槽位，运行时管理器同时使用 Morphia `@Transient` 和 Java `transient`。
  保存提交在自身的场景和管理器锁释放后执行；外部仍持有场景／背包锁时交给既有能力线程池提交，避免数据库队列回压时在这些锁内写玩家。

快速使用的原实现只扣物品、不产生效果，并会对空槽位抛出空指针异常。
当前对尚未实现实际效果的快速使用返回错误，保留可重复使用及消耗类物品；随行显示通过装备与能力组流程完成。
这不代表已经补齐所有快速小道具的效果、冷却、便携锚点或探测器玩法。

## 资源与兼容

当前 `ConfigWidgetNew.json` 有 **131** 条配置，其中 **26** 条包含 FlyAttach。
本轮接入的 **20** 条随行能力组都有当前 `ConfigAbility_Scene_Toys.json` 的实际能力定义。
能力组加载使用资源中的 `targetAbilities`，而不是仅依赖旧格式 `abilities`。

当前导出有 11 个对应能力组；缺失导出的 9 个采用参考库的明确别名。
别名保存在随 JAR 打包的 `widget-ability-groups.json`；实际资源导出优先，未知组不会按字符串猜测。
资源重载更新目录；无效配置不会发布部分目录。
另 6 条 FlyAttach 配置没有本轮配对的随行能力组，未把它们当作已完成的宠物玩法。

斯露莎和寻宝仙灵在此范围内完成装备与能力组登记；附加操控、任务互动和寻宝玩法还需分别核对。

## 当前客户端协议

只读工具使用固定 SHA-256 校验的当前 executable、global-metadata 和 startup-metadata。

- 装备请求 opcode **3319**、类型 **14384**：op 字段 2、material 字段 12，补回标签列表字段 **4**。
  `0x15262ac17` 使用 packed tag `0x22`。标签枚举 **72424** 的常量为 QuickUse=0、AttachAvatar=1。
- 随行能力组通知 opcode **5968**、类型 **59707**：`0x149bacd00` 读取字段 **2** 的 boolean 与字段 **3** 的 material ID。
  新增相应 proto 与发送包，保留已有包号。

证据：`debug/aster-mid-20261011/batch226/widget-native-proof.json`、相关反汇编及 `widget-resource-map.json`。
当前原生反汇编核对使用已有的固定哈希 Capstone 工具；radare2 的后续连接已在此前核对中中断。
