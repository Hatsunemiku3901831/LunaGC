# 制作、学习与领奖流程的真实保存夹具

## 本轮发现

在物品版本保护接入后，继续检查合成、烹饪、家具制作、配方学习、手册、选择礼包及还圣奥迹。
11 个套件、461 项检查的首次运行有 98 项失败。部分旧夹具仅模拟 `datastore.save` 成功，
没有为新的条件写入提供真实 mapper；部分确认失败注入仍挂在已经不再经过的旧方法上。
另外，匿名测试角色会把外层测试对象带入 BSON，不能作为真实玩家存档夹具。

这 98 项是测试适配失败，不能当作 98 个产品缺陷。原始结果与后续每轮结果均保留在
本地忽略目录 `debug/aster-mid-20261011/batch344/`。

## 调整

- 使用随机命名的隔离 Mongo 数据库，玩家经过版本保存保护，物品经过正式条件写入。
  家具相关夹具的家园保存也写入实际集合；移除对保存成功的空实现。
- 同步经济确认继续支持指定阶段失败，普通后台保存不消耗同步故障编号。
  普通删除已经先行完成时，也观察后续同步保存对删除记录的确认读取，
  避免故障位置随异步队列调度漂移。
- 测试中的自定义库存、回调、角色管理器和计数器不再进入玩家文档；
  其他玩家使用独立、无外层捕获的夹具，并保持内存与 BSON 的 UID 一致。
- 家具完成边界检查会直接读取数据库中的产物和家园队列，
  要求产物已保存、队列已清空、领取记录已清除。

原有的扣费数量、失败阶段、防重入、并发领取、库存容量、预留实例 ID 及重复领取断言继续保留。
真实数据库保存并不代表角色窗口、动画或完整玩法已经通过客户端验收。

最终按两组互不重叠的套件运行：9 组 258 项与 9 组 403 项，合计 18 组 661 项通过，
失败、错误、跳过均为 0。覆盖修改夹具的 11 个套件、既有商城／远征／锻造流程及 29 项物品保存保护。
已核对 2,675 个 Java 源文件与构建目录一致；生产源文件及当前运行 JAR 的哈希保持原值。
