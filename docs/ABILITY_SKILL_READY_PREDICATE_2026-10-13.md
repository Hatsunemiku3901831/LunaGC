# 7.1 技能全部次数恢复条件

## 来源与问题

沿固定 AstaPS `7cc148d1f752a43d4b9146b3b73f26875902546f` 胡桃与久岐忍六命补偿实现继续核对本地资源。
当前角色能力资源共有 114 个 `BAEGOCNMDPJ` 条件，此前全部按未知条件放行。
本批使用当前 7.1 客户端的元数据签名、评估函数及次数记录核对执行语义。

## 原生证据

| 类型或地址 | 核对结果 |
| --- | --- |
| `BAEGOCNMDPJ`（65063） | `+0x20` 为包装的技能 ID，`+0x18` 为包装的技能槽位数组 |
| `IMHPJAGBBNN.ECDMEADHGDE`，`0x14a732d70` | 检查指定技能 ID，再遍历槽位；槽位减一查实例；任一实例次数未满即返回 false |
| `BJKDIFKLEBG.ADOFKHMCCML`，`0x14b56aba0` | 取技能实例的当前次数并与最大次数比较；当前次数小于最大次数表示尚未完全恢复 |
| `0x1517a7f70`、`0x1517a8820` | 次数记录 getter 读取 `+0x60` 当前次数和 `+0x74` 最大次数 |
| `0x14eedca20` | 普通释放消耗 `+0x60` 次数，加入独立恢复时长队列 |
| `0x14b563a20` | 普通槽位保留数组索引和空洞；能量技能写入索引 4，攻击模式技能写入索引 5 |

因此该条件要求全部次数恢复，不能以“仍有一次可用”替代。
不存在的技能实例不会构成未恢复条件；没有选择技能时，在有效角色组件上满足空集合条件。
这里的 `skillSlot` 是技能槽位，区别于共享冷却开始动作的时长槽位。

r2 连接仍关闭，使用现有只读元数据提取器与 Capstone，没有修改客户端。
三个客户端文件 SHA-256 与[绝对血量条件分析](ABILITY_HP_VALUE_PREDICATE_2026-10-13.md)所列配置完全一致。
元数据、反汇编与校验脚本位于 `debug/reference-audit-20261013/`。

## 实现与边界

注册专用条件处理，复用玩家会话中的普通恢复队列和共享组时钟。
普通技能读取角色自身次数，共享技能读取玩家的共享组；任何待恢复条目都会使条件不成立。
查询不消费次数，也不发送通知。共享组查询区分无效时钟／无效配置和正常已恢复状态。
规范数字与槽位读取接受 uint32，非法输入拒绝通过；默认六个槽位保留空洞、能量与攻击模式位置。
施法者与指定目标分别读取，保持已有目标解析。

动态技能槽位的优先级覆盖、`UnlockSkill` 注册、HPDown 自动检测、濒死保护及完整六命生命周期还需继续接入。
本批没有宣称完整六命或全部角色技能已完成，也没有替代游戏内验收。
