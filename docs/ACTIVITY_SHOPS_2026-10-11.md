# 历史活动商店排期与购买校验

本批修复服务端排期、分页开放和限购，完整游戏内兑换流程仍需继续接入与验证。

## 已接入

- 使用 `ActivityHistory.json` 中明确的原排期与活动对应关系，定位 GM 当前复刻排期。
  不用排期编号除法推断活动；没有历史对应关系时只接受完全相同的已有排期。
- 加载 `ActivityShopSheetExcelConfigData.json`。第一天使用活动开始时间，随后按国服
  每日 04:00 开放；`ActivityShopSheetInfo` 返回 Unix 秒，结束时间使用活动总截止时间。
  玩法已关闭、兑换期仍有效时保留商店。
- 活动总览、单个商店、批量商店和直接购买使用相同开放判定。关闭、过期、未开始、
  缺少个人进度、进度属于其他玩家或旧排期时不能访问。未归的熄星沿用资源要求的冒险等阶。
- 提前预览的分页可以显示商品与未来开始时间，直接购买仍受分页条件约束。
  未实现的章节／任务条件不放行购买；无效或缺失的分页配置不开放。
- 区分资源的 `secondarySheetId` 与 `subTabId`，避免 JSON 中后出现的零值覆盖活动分页。
  本地未归的熄星 25 项商品保留原来的货币 109／110、价格与 10／15 项分页归属。
- 限购记录保存活动排期。第一次绑定旧限购保留次数，暂停、恢复和修改截止时间不重置；
  真正重新复刻时清空本期次数，保留总购买次数。普通商城限购维持原方式。
- 购买成功的响应使用本次已接受的商品，即使发货期间商店被关闭也能正确答复，后续请求拒绝。

## 参考和边界

行为对照固定版本的 [PlayerShopComp](https://github.com/Havesten/hk4e-sources/blob/d12e0ae8dbe6012aefca71128d4c13e48113b68d/data/jenkins/jenkins_hk4e/workspace/hk4e_3.4_dev/gameserver/src/player/shop/player_shop_comp.cpp)
和同版本 `ActivityShopExcelConfig`：预览与购买分别检查，分页按开放日计算开始时间，
兑换使用排期总结束时间。新代码根据本项目资源与 GM 复刻模型编写。
资料的 Git blob 与 SHA-256 核对记录位于 `debug/aster-mid-20261011/batch73/sources.json`。

后续已接入货币 109 的服务端扣费、发货和活动账本，见[活动代币兑换](ASTER_SHOP_2026-10-11.md)。
尚未将未归的熄星商店标为完整还原：第三章代币扣费、原生余额槽的 109／110 语义、
当前客户端商品分页字段和完整游戏内兑换验证仍需补齐。当前资源中的炼金章节等条件
也需要对应玩法进度；不会把预览状态作为购买资格。未知商店编号仍需从当前客户端核实。

## 验证

新增检查使用本地原始商店与分页资源，涵盖新排期查找、秒时间、04:00 边界、提前预览、
玩家资格、过期与关闭、错误配置、商品价格、限购重载和真实购买处理器的扣费／发货／限购。
真实购买处理器还覆盖发货过程中关闭商店的响应。最终回归与候选包摘要见适配记录第七十三批。
这些检查验证服务端行为，不等同于完整 7.1 客户端游玩验证。
