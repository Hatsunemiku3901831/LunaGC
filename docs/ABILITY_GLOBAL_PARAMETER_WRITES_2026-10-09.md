# 全局值写入与技能参数传递

本批扫描当前 `AvatarAbilities`；节点数量用于定位影响范围，不能代替技能完成度。

## 行为

- 五类动作均检查资源条件。未解锁天赋不再执行原本应被阻止的写入或复制。
- 固定写入和累加使用严格表达式计算；无效算术、非有限输入、空白键、
  无效上下限和倒置范围不会破坏原值。未启用范围限制时不应用默认零上下限。
- 累加继续使用实体全局值表的原子更新。计算用较宽数值范围，先按已启用的边界截取，
  最后检查能否作为有限 float 保存；无界溢出拒绝写入。
- 合法零值可创建键，完全相同的重复写入不再重复刷新或发送全局值通知。
  实际变化在原子更新结束后刷新依赖，避免在 map 更新回调中递归修改同一键。
- 跨实体复制检查来源和目的实体生命周期；拒绝非有限来源，保留来源数据。
- 全局值转技能参数复用第四十六批的参数写入路径，刷新跨实体附着的状态，
  支持指定接收目标已有的技能实例。找不到技能不会写回来源实例。
- 普通参数转换只是读取来源全局值，不再改写同值或发送多余的全局值通知。
  `isFromOwner` 保留机关主人来源，主人已离开时不改参数。
- 没有公式且整个动作链可识别的参数转换可以由服务端周期执行，继续遵守完整链验证。
  显式公式转换不接管；原有 `DummyThrowSpeed` 原生兼容路径保留，其他公式尚未逐项还原。
- 资源中的 `randomInRange` 现在参与链验证。丽莎的随机计数不会被服务端周期当作固定值执行；
  原生随机取值链仍待核对，不宣称其完整随机分布已实现。

服务器周期中的全局值通知仍沿用已有抑制规则。本批没有重写所有 Lua／客户端全局值入口，
也没有宣称并发通知顺序、所有动态表达式快照或全部未知谓词已解决。
