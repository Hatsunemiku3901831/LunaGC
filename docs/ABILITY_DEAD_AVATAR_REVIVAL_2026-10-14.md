# 死亡角色复活与队伍作用范围

> 2026-10-15 后续进度：七七技能控制和 Rerir 布尔条件已接入，43／43 个资源动作通过本地预检。
> 见[七七复活技能控制](QIQI_REVIVAL_CONTROL_2026-10-15.md)和[实体可用状态](ABILITY_ENTITY_AVAILABILITY_2026-10-15.md)。下文保留本批验证时的范围及待办快照。

## 来源和问题

核对 AstaPS `7cc148d1f752a43d4b9146b3b73f26875902546f` 的
`ActionReviveAvatar`、`PartyReviveHelper` 和本地资源后，接入缺少的 `ReviveDeadAvatar`。
资源中有 27 个该动作，另有 16 个已有的 `ReviveAvatar`。
参考库的全队复活思路可用于补齐入口，但其中按角色名称判断冷却、缺少参数时使用固定半血等行为未直接采用。

旧处理器没有检查明确目标是否属于当前玩家、当前队伍和当前场景，
移除的实体也能收到晚到复活。已选择的回调目标还会再次扩散到全队。
同时，标准回血比例与混淆别名同时存在时，结果依赖 JSON 成员顺序。

## 已实现

- 同一个处理器注册 `ReviveAvatar` 和 `ReviveDeadAvatar`。
- `ReviveDeadAvatar` 未指定目标时处理所属玩家当前队伍；显式目标继续按配置选择。
- `AllPlayerAvatars`、`CurTeamAvatars` 支持当前队伍，已选择的角色不再重复扩散。
- 目标必须是当前玩家的有效队伍实体，并与能力所属实体处于同一场景。
- 隐藏但仍在队伍中的有效实体可复活；失效、替换、转场或不在队伍中的实体不可复活。
- 保存原始 `range` 配置，当前使用有限正数作为三维距离范围，包含边界。
- 按资源计算固定回血量、施法者最大生命／攻击比例，以及目标当前／最大生命比例。
- 参数缺失、表达式无法求值、非法数值或未知条件不产生复活，不填充固定半血。
- 标准 `amountByTargetMaxHPRatio` 优先于两个导出别名，不修改调用方 JSON 树。
- 复用现有 `EntityAvatar.revive` 的死亡标记清理及生命／血量通知，存活成员不受影响。
- 受控回调树和周期控制器可执行已支持的复活，未知目标和条件在预检阶段阻止部分应用。

队伍组目标不作为单一谓词或标量复制目标使用。
全局值监听链的允许动作未扩大到复活；这类动作只在自身已支持的回调路径执行。
