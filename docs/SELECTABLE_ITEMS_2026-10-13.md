# 自选礼包奖励解析、消费与发放

对照固定 AstaPS `7cc148d1f752a43d4b9146b3b73f26875902546f` 与本项目公共道具选择类，
修复共同存在的奖励 ID 误用、数组边界和批量装备数量问题，采用分阶段经济记录确认库存使用。

## 当前资源与行为

资源有 14 种数量选择礼包、1 种物品选择礼包和 13 种奖励选择礼包，共 **28 种**。
13 种奖励选择礼包关联 96 个奖励定义，原实现把奖励 ID 当物品 ID 查询。
现按 `RewardExcelConfigData` 解析奖励内容、合并同 ID 数量并按实际使用次数缩放。
明确的附加货币数量纳入计划；未知附加字段、溢出或不支持的奖励在消费前拒绝。

- 所有候选边界和数量均检查；空参数、缺少数量分隔符等损坏配置不抛出加载异常。
- 先核对完整奖励、堆叠与容量，包括消耗最后一个礼包释放的格子，再保存所选奖励和来源身份。
- 确认实际礼包扣减和数据库写入后，逐项确认材料／家具入包、货币增量与独立武器身份。
- 批量武器逐件生成。服装和千星外观使用已有商城解锁定义，确认实际拥有后保存。
- 已有外观、未知奖励、错位配置、数量溢出或无法容纳时保留礼包。
- 保存预约、支付和全部发放三个阶段，成功清除记录；部分发奖或写入异常保留记录，阻止重试。
- 原选择动作的无来源直接调用不发奖，正式使用通过持有礼包的库存入口执行。

`pendingItemUse` 保存操作 ID、来源物品 ID／ObjectId／当前 GUID、支付前数量、使用次数、
选择序号、动作类型、完整产物和已确认发放身份。奖励计划采用独立 Morphia 产品结构。
旧玩家没有该字段时照常使用道具；未清除记录会拦截新的道具使用。

## 实际边界

本批验证服务端单个选择序号的库存流程与实际资源；原生分组选择列表的业务含义和游戏界面仍待核对。
后续[道具使用协议修复](USE_ITEM_PROTOCOL_2026-10-13.md)已补齐标量选择回包关联和异常响应。
目标限制型自选道具不跳过目标检查。
当前资源选择奖励的经验等额外类型仍需单独接入，未知奖励不会静默丢弃。
消费、发放与玩家记录仍跨文档；中断可能留下部分状态，自动退款／补发尚未实现。
数据库持续拒绝保存时，内存记录不能保证跨进程保留。本批没有重启日常服务。
