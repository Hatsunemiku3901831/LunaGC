# 食物故障记录的库存核对与结算

`itemuse` 后续新增了[学习书的 resume／cancel](LEARNING_BOOK_PERSISTENCE_2026-10-17.md)；本页的 refund-cost／settle 仍只处理食物记录。

食物执行发生未确认异常后，`pendingItemUse` 会阻止继续使用消耗品，避免重复执行回血或复活。
新增 `itemuse` 管理命令，用实际存档核对并处理这条记录的库存成本。
它不重新执行食物，也不推断、撤销或补发角色效果。

## 用法

控制台／GM 使用 `@UID` 指定在线目标；游戏内可使用本人。
权限为 `server.itemuse`，操作其他玩家另需 `server.itemuse.others`。

| 命令 | 效果 |
| --- | --- |
| `itemuse @10001 status` | 只读显示操作 ID、阶段、源物品持久 ID、成本前值与当前存档数量 |
| `itemuse @10001 refund-cost <operationId>` | 对尚未执行效果或已经决定退款的记录，仅退回库存成本 |
| `itemuse @10001 settle <operationId>` | 对已完成或效果不确定的记录，明确接受当前消耗与效果并结束记录 |

先查看 `status`，按显示的阶段选择动作。操作 ID 必须完全一致；处理后的同一 ID 不能重放。
自选／随机礼包和没有完整成本快照的旧记录不能通过此入口清除。
内存与存档不同、物品被替换、余额不等于快照或资源不满足退款条件时保留记录。

## 阶段与决定

| 阶段 | 可执行动作 |
| --- | --- |
| 1 预留 | `refund-cost`；未扣除则只结束预留，已确认成本删除则退回原成本 |
| 2 付款已确认、动作尚未开始 | `refund-cost` |
| 3 食物已完成 | `settle`，仅清除已经确认完成的记录 |
| 4 效果可能已部分生效 | 只允许 `settle`，保留消耗与当前效果；不能自动退款 |
| 5 已决定退款、库存退款未确认 | `refund-cost`，按成本前后快照补齐库存退款 |
| 6 库存退款已确认 | `refund-cost`，只清除记录，不再给一份物品 |
| 7 已接受消耗、记录待清除 | 只允许 `settle`，不能切换为退款 |

`refund-cost` **只处理库存**。饱食度、惩罚、冷却、生命值、复活和持续 buff 保持当前状态。
现有记录没有完整的角色属性前后快照，不能据此猜测这些状态是否已经恢复。
`settle` 是管理者接受当前结果的明确决定，不会重放动作、postUse 回调、取得物品或消耗任务事件。

## 存档与重登

- 等待已有写入排空，投影读取 `pendingItemUse`，不解码另一份完整 Player，不触发其生命周期保存。
- 比较内存／存档的相同记录、唯一物品堆叠、归属、数量和 Mongo ObjectId；运行时 GUID 不作为持久身份。
- 全堆叠已经删除时，退款用原 ObjectId 重建，分配当前会话的新 GUID；剩余堆叠则沿用其身份。
- 退款先确认资源、堆叠上限及背包空位，再保存退款决定、成本和完成阶段，最后清除记录。
- 退款或清除中断后，重登核对前后快照再继续；已确认的退款不会再次发放。
- 明确接受消耗的决定也先持久化，清除失败不能使它切换为退款。
- 完成后发送当前完整背包快照，不使用旧会话 GUID 发送删除通知。

本入口没有跨集合事务。异步显示通知失败不会重新打开已经完成的经济操作；
数量或身份不符时不通过修改余额强行凑齐快照。

错误成本身份、背包容量、内存／存档差异、只读审计、权限及实际命令分发。
