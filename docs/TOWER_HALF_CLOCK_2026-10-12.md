# 深渊上下半场计时与切队调用

核对 AstaPS `7cc148d1f752a43d4b9146b3b73f26875902546f` 的 WorldChallenge、ScriptLib 和 TowerManager。
同时读取资源中 33401 场景的 233401001／003／004 组：上半场把成功事件 param2 写入 TPL_TIME，下半场直接作为剩余秒数使用。

## 行为

- 计时深渊挑战的成功事件提供剩余秒数；普通挑战继续提供已用秒数。
- 下半场直接使用剩余预算，不再从上一场总时长中重复相减。
- 服务端记录合法上半场完成时的预算，绑定场景对象、管理器、楼层、当前间和两支所属队伍。
- 下半场启动使用匹配的预算，支持大于 600 秒的配置；切队等待时间不扣除。
- 成功启动下半场后消费预算；新选队、进新间、成功重试或副本结束清除预算。不匹配上下文沿用合法 Lua 配置。
- 时间耗尽不能启动无限时下半场；未知配置、未知组或没有玩家时提前返回失败，不替换旧挑战或消费预算。
- 按挑战类型处理真正的时长参数：TIME_FLY 使用第五参数，守护挑战的组编号保持原值。
- 补上 Lua 单参数切队入口和可查询结果的 Java 切队入口，保留旧 void API。
- 切队失败返回非零，不停止当前怪物潮；成功后再卸载原怪物潮。

本批没有依赖参考实现中小于 60 秒、差值大于 60 秒或达到 600 秒的猜测规则。
异步成功事件与副本结算顺序、客户端半间动画和完整原生客户端流程继续适配；没有将控制测试描述为完整深渊验证。
