# 炼金合成扣料与产物确认

本批参考固定版本 AstaPS `7cc148d1f752a43d4b9146b3b73f26875902546f` 中
`RewardGrantJournal` 的分阶段记录与禁止盲目重放原则，接入本项目现有 Player／Morphia 保存流程。
参考库的通用 API 未直接移植；本功能覆盖正式炼金合成入口。

## 行为

- 扣料前保存操作 ID、配方、次数、计划产物、有效成本与支付前余额。
- 检查成本定义和实际库存；树脂消耗关闭时，从有效成本与响应中排除树脂。
- 逐项确认实际扣减，并同步保存材料堆叠或零数量删除，再确认支付阶段。
- 材料与货币检查实际增量；武器、圣遗物检查独立 GUID、所有权和逐件增量。
- 仅在全部产物确认后推进调查手册，保存完成阶段，再清除待核对记录。
- 同一玩家存在未清除记录时拒绝新合成，防止扣料、发奖或保存故障后的重复操作。
  更换管理器以及 Mongo 重载后的记录也保持此限制；其他玩家可以正常合成。
- 未知虚拟产物、树脂关闭时的树脂产物，以及皮肤／外观解锁物品在扣料前拒绝。
  货币检查支付后的有效余额，树脂与传说钥匙遵守属性上限。

`pendingCombine` 保存三个阶段：1 已预约、2 已支付、3 产物与进度已确认。
产物记录携带物品 ID、数量与确认的 GUID；货币 GUID 为 0。
旧玩家没有该字段时继续正常合成。异常返回错误并保留记录，不自动退款或重发。

## 实际边界

这些写入仍跨多个文档，未构成原子事务。断电或持久化失败可能留下部分消耗、部分产物，
甚至已完成但尚未清除的记录；阶段和快照供核对使用，不能据此推测应该退款或补发。
若数据库持续拒绝所有保存，内存记录无法保证跨进程保留。
自动核对恢复、六个转换模板、幸运角色与额外产物来源继续适配。
本批没有重启日常服务，原生游戏结果窗口仍待实机验证。
