# 场景组计时与熄星增援

## 本次修复

`CreateGroupTimerEvent` 使用场景的一次性计时任务，以组 ID 与来源字符串独立管理。
原实现使用重复任务，回调结束又按同一来源取消；Lua 在回调内排下一轮时，
新任务会被一起取消。本次让回调完成仅清理其自身对象，允许安全地排下一轮。

- 延迟以场景的一秒时钟计数，小数向上取整，零延迟在下一次场景时钟执行。
- 同组不同来源、不同组同名来源分别管理；相同来源重新创建替换原任务。
- 组刷新、卸载、对象替换、场景销毁和玩法轮次替换使旧计时器失效。
- 队列中的回调在进入 Lua 前再次校验，在场景锁内执行；过期触发器不参与执行。
- 已进入 Lua 的回调保留其轮次占用，内部停止并排下一轮也不能在返回前替换战斗。
- 保留烘炉的挂载代次、原始轮次和活动中判定。
- Lua 的无效组 ID、来源、延迟在载入组或替换任务前返回 `-1`。

## 原始活动脚本

继续使用固定来源 [Ahanlei123/2.8_live_data 的 AsterBig.lua](https://github.com/Ahanlei123/2.8_live_data/blob/f25e3155e38f9dc8f647493bf23a935147caf59e/lua/common/AsterBig.lua)。
原始计时组 `133001426` 定义五轮时间：**60、180、300、420、540 秒**。

公共脚本原本在最后一轮招怪前返回错误。本次先执行当前波次，最后一轮完成后正常返回，
其余波次再排下一次计时。无效／已完成指针正常退出并保留可复用触发器；
倒计时和已停止的战斗通过现有零进度操作校验，不能产生增援或消耗波次。
133 项来源清单保留原始 Git blob、上游哈希和此前适配，更新了公共脚本哈希与本次适配记录。

## 增援提醒消息

接入原脚本在招怪前调用的 `ShowTemplateReminder(context, 110, {0,0})`，向场景广播。
语义参照固定原服务端 [ScriptLib::ShowTemplateReminder](https://github.com/Havesten/hk4e-sources/blob/d12e0ae8dbe6012aefca71128d4c13e48113b68d/data/jenkins/jenkins_hk4e/workspace/hk4e_3.4_dev/gameserver/src/script/script_lib.cpp#L11153)，
其参数为有符号整数列表。源文件 Git blob 为 `9a6e7ccb005f997da3dcf043fa9920ca681316f2`，
SHA-256 为 `d7d810e3e5f4c8b98fe758b6621416badf8fc71a09093ee0c1bfe968f8f6e387`。

网络字段直接核对提供的客户端：消息类型 `37088`，包号 **28686**，读取函数
`0x1519dce80`。静态编解码初始化与元数据泛型共同区分两个列表：

| 字段 | 标签 | 类型 |
| --- | --- | --- |
| 玩家参数列表 `param_uid_list` | 1 | `repeated uint32` |
| 提醒 ID `template_reminder_id` | 4 | `uint32` |
| 文本参数列表 `param_list` | 12 | `repeated int32` |

有符号列表的编解码槽为 `0x144b8`，初始化使用标签 `0x62`；无符号列表的槽为
`0x144b0`，使用标签 `0x0a`。读取函数的对应分支与两种列表一致。
另外两个布尔标签 3、10 的语义尚未核实，本次不发送；按玩家分配及撤销提醒尚未实现。

原始提醒 110 仍存在于当前资源 `TemplateReminderExcelConfigData.json`，图标为
`UI_Tips_Item_Monster`。Lua 接口验证稠密参数数组和完整有符号 int32 范围，
空列表有效，无效／失效组及销毁场景不发送消息。
