# 修饰器战斗属性

第三十五批接入固定 LunaGC 7.1 的
[ActorProperty 映射](https://github.com/capyb2222/LunaGC_7.1.0/blob/c3f203a5234fefe32c8d4dbfe9e84a665c8f9cc8/src/main/java/emu/grasscutter/game/props/ActorProperty.java)。
37 个名称与战斗属性的对应关系保持原样，包含此前已接入的生命值比例；
本地补入解析、可移除层、参数更新和统一通知。来源清单见
[外部实现适配记录](UPSTREAM_INTEGRATION_2026-10-08.md)。

## 已接入的属性

| 范围 | 资源字段与处理 |
| --- | --- |
| 攻击 | `Actor_AttackRatio`、`Actor_AttackDelta`、`Actor_AttackExtraDelta`；更新百分比、固定值及当前攻击 |
| 防御 | `Actor_DefenceRatio`、`Actor_DefenceDelta`；更新百分比、固定值及当前防御 |
| 生命值 | `Actor_MaxHPRatio`；沿用生命值比例层、血量比例和生命之契保护 |
| 精通 | `Actor_ElemMasteryDelta`、`Actor_ElemMasteryExtraDelta` |
| 暴击与充能 | 暴击率、暴击伤害、抗暴击及元素充能效率增量 |
| 治疗与伤害 | 治疗加成、受治疗加成、总伤害增加／减少、物理及七种元素伤害增加／减少 |
| 其他 | 技能冷却减少、护盾成本减少、弱点伤害、防御忽略比例与固定值 |

数值、命名参数和后缀表达式使用已有 `DynamicFloat` 解析器。
其他名称也进入属性字典，当前资源中的未映射表达式能保留和往返，但不会被猜测成另一战斗属性。
原有可写的 `Actor_MaxHPRatio`／`Actor_HpThresholdRatio` 字段保留，兼容现有调用。
未知对象形状仍受原有动态数值解析器限制，本批没有通用不透明 JSON 保存能力。

## 计算与移除

属性层归属承载实体，与 [生命值层](ABILITY_HP_MODIFIERS_2026-10-08.md) 使用同一控制器集合。
客户端实例、服务端多层、确认去重、替换、迟到移除和初始 `ApplyModifier` 使用同一登记路径。
技能参数更新、整表重建、天赋刷新以及 [实体全局值](ABILITY_GLOBAL_VALUES_2026-10-09.md) 更新后重算该层。
首次哈希全局值更新也能从已附着且已映射的属性表达式查找名称；歧义仍拒绝。

计算分两步：

1. 普通属性基于撤去本层后的战斗属性、承载实体全局值及所属技能常量计算。
   技能常量优先；当前攻击／防御加上基础属性对应的比例项与固定项，怪物保留原有复合倍率。
2. 更新 `FIGHT_PROP_NONEXTRA_*` 中间值，再计算 `ExtraDelta`。
   额外精通或攻击不会把自己的上一轮加成当作新基数反复扩大。

每个已改变属性保存原基值及本轮最终值。当前值仍等于本层最后写入值时，移除直接恢复原基值，
避免巨大有限 float 加成与小基值相减时丢失精度；外部数值变更则保留其新增部分。
角色／怪物完整重算后清空旧账，再应用一次。已覆盖额外外部攻击增量的移除场景，
并不据此宣称任意并发属性写入或完整跨属性依赖图已经验证。

无穷、溢出或导致负当前攻击／防御的组退回有效基值或普通阶段结果，不清掉其他有效属性组。
客户端 NaN／无穷参数仍被原有入口拒绝；有效的零参数可以撤去加成。
一次刷新先完成生命值和其他属性，再合并发送实体更新；有效队伍角色同时通知拥有者。
角色静默重算仍不提前发送通知。

这些公式及 `NONEXTRA` 上下文是依据资源和本地复合属性模型作出的适配选择。
真实 7.1 客户端的公式、界面同步与客户端／服务端重复应用所有权仍待实机验证。
任意跨属性循环依赖、移动／动画／物理效果及完整元素反应加成没有由这一层统一解决。

## 验证

新增 **60 项测试**：37 种映射参数化用例，以及 23 项叠层、实例替换、参数更新、
统一通知、角色／怪物重算、无生命值实体、额外属性中间值、无效组恢复、
巨大有限属性移除、外部增量保留和真实资源片段用例。

最初 52 项中 50 项复现失败、2 项已有保护通过；新增六项用旧实现复现六项失败。
巨大有限生命值与攻击恢复再以两项失败复现。一次中间测试错误地预期无穷客户端参数清除有效值，
修正为拒绝无穷、另用有效零值撤去后重跑。
最终相关 **423 项／23 套件**、全量 **1403 项／167 套件**通过，失败、错误、跳过均为零，
`gradle test jar` 成功。

四个固定夹具位于 `src/test/resources/ability/`：

- `actor-property-mapping.json`：参考映射的 37 个名称。
- `actor-stat-modifiers.json`：25 处资源的完整单个修饰器子树和所属技能常量表。
- `actor-stat-sources.json`：原路径、技能、修饰器名称及源文件 SHA-256。
- `actor-stat-cases.json`：显式注入参数及独立算术计算的期望属性。

25 处包含爱诺、阿贝多、艾尔海森、埃洛伊、阿蕾奇诺、白术、芭芭拉、北斗、班尼特、
夏沃蕾、千织、重云、哥伦比娅、塔利雅、迪奥娜、优菈、珐露珊、菲林斯、莫娜、雷泽等资源。
测试直接登记控制器，检查该属性层及移除；注入参数用于避免资源常量为零掩盖缺失实现。
这些是属性子树测试，不计作上述角色的技能、天赋、命座触发链或实机验收。

## 剩余范围

未映射清单包括耐力、移速／动画、重力、各类元素反应、额外暴击等。
资源中的 `Actor_DefenseIgnoreRatio` 与上游 `Actor_DefenceIgnoreRatio` 拼写不同，前者三处保留待核对。
`Actor_HpThresholdRatio` 也不属于这 37 种映射，沿用既有消费入口，未作为本层普通战斗属性计算。
队伍／场景／世界虚拟实体的战斗属性持久承载仍需单独适配。
通用 `duration`／`thinkInterval`、完整结束动作、刷新耐久及自动生命周期清理继续待实现。
其他技能、TPS、历史活动、商城 SDK、千星复杂资产与发布／执行／任务／奖励，
以及其他参考项目适用改进继续保留在总目标中。
