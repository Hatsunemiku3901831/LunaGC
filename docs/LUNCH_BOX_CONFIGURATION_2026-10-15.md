# 便捷营养袋的食物配置与保存

## 已完成

- 使用当前资源中物品 **220008（叁零式·便携营养袋）** 的食物规则，保留恢复槽和复活槽各自的选择。
- 设置前验证营养袋、食物数量、实际背包 GUID 和玩家所有权；错误槽位、错配食物和坏消息返回错误及原有选择。
- 请求按槽位更新；物品 0 只清空指定槽，不影响另一槽。设置不会消耗食物或营养袋。
- 选择写入 Player 的 `lunchBoxFood`，通过 `AllWidgetDataNotify` 在后续同步／登录时恢复。
- 食物耗尽后保留选择，补货后不用重设。运行时 WidgetManager 不写入数据库。
- 食物范围同时读取资源的明确物品表和食物效果分类，覆盖未写入旧名单的新食物。
  `foodEffect` 优先于当前导出 `PANBBKJOBOL`，后者优先于旧导出 `KNOIOAPAFIH`。

参考 AstaPS 固定提交 `7cc148d1f752a43d4b9146b3b73f26875902546f` 的设置处理器只回显请求；
其 QuickUse 通用路径明确注明“扣物品但没有效果”。本次增加实际保存与校验，未采用该扣除路径。

## 当前客户端依据

经 `tools/extract_client_type_names.py` 固定 SHA-256 校验的客户端：

| 内容 | 核对结果 |
| --- | --- |
| 营养袋槽位枚举 | 类型 75091：None=0、Hp=1、Revive=2；运行类 66665 在 `+0x48` 使用该枚举 |
| 设置请求 | 命令 23773，类型 27373，写入 lunch_box_data 字段 4（`0x147359093` 写 tag `0x22`） |
| 设置响应 | 命令 29400，类型 14979；`0x148d52490` 读取数据字段 6、retcode 字段 14 |
| 食物映射 | 类型 30270 的 codec 在 `0x14b3d7059` 使用 tag `0x4a`，即 map 字段 9 |
| 登录通知 | 命令 599，类型 83680；`0x148ca1884` 读取 tag `0x62` 到 lunch_box_data，即字段 12 |

radare2 打开文件后，反汇编及关闭调用仍返回 Transport closed；使用现有 SHA 校验的只读 Capstone 工具完成上述配对。
额外的食用调用追踪遇到 Python 解释器异常，未将该次追踪记为有效证据。
