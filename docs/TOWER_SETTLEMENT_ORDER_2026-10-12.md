# 深渊成功事件与结算顺序

核对 AstaPS 固定提交 `7cc148d1f752a43d4b9146b3b73f26875902546f` 的 WorldChallenge。
参考实现等待成功事件 Future；本项目的 Lua 队列回调也会取得场景锁，同步等待可能堵住事件线程。
实际 33401 下半场组 233401004 的成功函数将状态组 233401001 的 stage 改为 2。
此前服务端可能在这个修改前判断通关，结算监听器看到 stage=1 后退出，无法补发结算。

## 实现

- 深渊成功事件处理结束后，再投递通关条件与挑战结束触发器。
- 深渊成功结算事件处理结束后，再更新玩家完成记录、调用结算监听器并发送最终结算。
- 两段延续使用既有事件线程池，队列任务无需等待另一个队列任务；延续在 Lua 上下文清除后执行。
- 延续验证玩家、世界登记、场景、管理器、挑战对象、挑战启动序号、加载组、楼层、当前间与两队身份。
- Java 最终修改同时取得玩家传送锁与场景锁；重试／清理会失效已排队的延续。
- 挑战完成只接受一次；移除 DungeonChallenge 的额外通关投递，成功结算重复调用不会重复改记录。
- 成功挑战的星级使用实际完成用时；排队和 Lua 等待不会继续扣时，进行中的挑战继续实时计时。

原有 Future 接口保留。新增事件延续仍遵循现有 Lua 错误处理与返回值规则，不代表任意脚本错误都已修复。
本批覆盖成功深渊结算；失败与退出通知的同步等待路径，以及完整原生客户端流程仍需继续检查。
