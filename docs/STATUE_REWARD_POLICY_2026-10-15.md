# 神像奖励倍率与分配

参考 AstaPS 固定提交 `7cc148d1f752a43d4b9146b3b73f26875902546f` 的
`StatueOfferRewardHelper`，接入可选参考倍率和按地区／物品自定义倍率。

## 配置

默认使用资源原始奖励。要启用参考增强，在现有配置的 `server.game.gameOptions` 中加入：

```json
{
  "statueRewards": {
    "referenceMultipliers": true,
    "evenlyDistribute": true,
    "cityItemMultipliers": {}
  }
}
```

`referenceMultipliers` 启用下表预设；`cityItemMultipliers` 可独立使用，也可覆盖预设。
例如 `{"1":{"201":1,"102":2}}` 表示 1 号地区保留每级原石原数量，阅历改为两倍。
倍率须为正整数，1 表示保留对应物品的原始等级分布。
`evenlyDistribute=false` 时，只将各等级原有物品数量乘以倍率，不重新分配到其他等级。

配置重新加载后，新供奉读取当前设置。一次供奉使用同一有效策略；
已经产生的待核对供奉保留其奖励快照，不因之后调整配置而变更或自动重发。

这是参考项目的增强规则，原石总量会明显增加。例如 1 号地区 2–10 级合计从 90 增至 4,950，
均分后每次升级 550；5 号地区每次升级 1,800。是否启用由上述配置控制。
神瞳成本和体力增长仍来自实际资源，管理性调级也不会触发这套奖励。

## 分配与数据边界

- 使用实际升级行，按等级排序；同等级旧 StatuePromote 优先，缺少旧行时使用 CityLevelup。
  不固定城市数或 20 级上限。
- 开启均分时，先求该地区的增强物品总量，再除以实际升级行数；整数余数依次分给较早等级。
  例如 6 号地区 15 个相遇之缘分为前 6 次各 2 个、后 3 次各 1 个，总量保持一致。
- 100533、旅行者命座材料 912–918，以及当前神像钥匙
  107008／107018／107025／107027／107031／107037 保留原等级和数量，自定义倍率也不改变它们。
  其他未指定增强的物品保留原分布。
- 使用当前资源中的真实奖励，包括 8 号地区的相遇之缘、916 和 107037。
  缺失奖励定义时拒绝结算；不生成参考库早期缺失资源时使用的占位奖励。
- 每次供奉重新建立所需分配，不使用首次构建后永久保留的全局缓存。资源更新可供新供奉读取。
- 倍率、逐级数量和跨级总量均检查溢出；增强奖励通过既有物品／堆叠／背包预检后才扣除神瞳。
  奖励阅历沿用直接发放链路，不再次乘以全局击杀／探索经验倍率。
