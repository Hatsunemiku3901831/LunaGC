# 圣遗物重塑的异常恢复

在已配对的当前重塑协议和真实结算基础上，补齐支付不确定、取消预留和结果选择中断的管理恢复。
使用现有 `transmuter` 命令，玩家须在线：

```text
transmuter @10002 status
transmuter @10002 resume <operationId>
transmuter @10002 cancel <operationId>
```

权限继续为 `server.transmuter`／`server.transmuter.others`。
`status` 给出每笔重塑的操作 ID、物品持久 ID、阶段、成本、进度前后值，
以及材料持久 ID、扣除前数量、内存和存档现存数量。查询不扣尘、不改词条或周期。

## 预留与阶段

新预留在第一次保存前冻结独立 UUID、材料物品 ID、材料 ObjectId 和扣除前数量。
重塑计划、原词条、新词条及进度仍沿用先前生成并保存的候选；恢复不重新随机。
重复请求继续使用同一笔操作。持久 ID 用于存档关联，临时 GUID 在当前背包中重新绑定。

| 保存阶段 | resume | cancel |
| --- | --- | --- |
| RESERVED | 核对实际扣尘，仅支付尚未支付的成本，再同步 READY 候选 | 材料与进度均未改变时可取消 |
| READY | 重发完整候选快照，供玩家继续选择 | 拒绝；已扣尘不退款 |
| ADOPTING | 继续已保存的采用决定 | 拒绝更换决定 |
| KEEPING | 继续已保存的保留决定 | 拒绝更换决定 |

READY 不会由管理恢复自动采用或放弃。已有多个 READY 候选时，各自保留结果，
重发较早候选不要求材料余额仍等于它最初付款后的余额，也不回退全局进度。
取消一笔未付款预留后仍同步其他候选，释放被取消物品的占用。

## 核对与中断

- 内存经济状态必须与存档一致，候选的键与物品持久 ID 必须相同。
  同一操作 ID 若对应多笔记录会停止，不代选另一笔或另一种操作。
- 同时核对背包与存档的物品归属、数量、等级、主／副属性、装备／锁定和指定属性信息。
  恢复付费或结果选择前验证原计划的词条及属性库；词条、主属性或等级不符时不覆盖原物品。
- RESERVED 材料数只能等于扣除前或扣除后快照。材料已用完且原持久 ID 已不存在时，
  只在预期扣后数量确实为零时承认付款。不会对新补入的另一堆材料再收费。
- 付款已完成而进度尚未保存时只补记一次进度；若进度已经保存，也不再次累加。
  未付款却出现付款后进度时拒绝继续。
- 保存 READY、确认材料或取消清除的过程中再次中断，记录仍保留。
  重登后按实际存档阶段继续；清除已提交但回执失败时，重登会解除占用，旧操作 ID 不能再执行。
- 未扣费取消只要求付款与原物品快照匹配。待放弃结果缺失／损坏、资源暂时缺失不会迫使重建它。
  取消不改变原词条、不退款；材料数量或原物品快照不匹配时停止核对。

所有动作共用玩家背包锁。并发 resume 可以先完成付款再重发同一 READY 候选，
只保留一笔成本与一次进度。成功处理的 UID、操作 ID、动作和阶段写入日志。

## 旧存档

旧候选没有 UUID 时，查询显示明确的 `legacy:<物品ObjectId>` 标识。
已确认付款的 READY 可重发，ADOPTING／KEEPING 可继续原决定，均不再次检查或消耗旧材料。
旧 RESERVED 没有完整付款快照时保留记录并拒绝猜测付款、退款或无条件清除。

## 无副作用的经济状态读取

回归发现：完整解码 Player 会执行 `Player.onLoad -> PlayerCodex.setPlayer -> fixReliquaries -> save`，
给读出的独立玩家副本排队保存；它可能在经济记录清除后把旧记录写回。
此前萃取取消检查已实际出现这种写回，另有计数器测试确认一次读取额外产生一次玩家写入。

萃取、制作和重塑恢复现在共用 `ArtifactRecoveryStore`：只投影读取 `artifactTransmuterData`，
将其基础类型、列表和映射解码为独立记录，不构建 Player 或执行读档迁移。
检查覆盖零额外玩家写入，以及 uint32 上限进度／时间、整数小数进度单位和制作次数的完整往返。
通用玩家读档的图鉴迁移保存路径列为单独待办。
