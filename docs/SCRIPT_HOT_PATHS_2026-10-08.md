# 区域检测与 Lua 技能调用适配

## 来源与差异

参考 [AstaPS d99a441](https://github.com/MeChen618/AstaPS/commit/d99a4411245462ea944200df403efe94d7d5364e)
中的 `RegionMembershipTick` 和缺失 Lua 函数警告限流。
当前项目已有世界集合快照、生命值回调和控制器上下文修复，本轮补齐区域检测及技能调用路径。

区域旧实现对每个已在区域内的 ID 调用 `List.contains`，单个区域内的离开检查为平方级。
改为整型哈希集合查询，另保留有序 ID 快照用于产生事件。
每个区域仍读取实时场景实体；进入回调产生的实体可以被后续区域看到。
先添加成员、发送进入事件，再实时检查移动／消失、清理成员并发送原先计算出的离开事件。
事件参数、实体类型 19 的过滤及所有区域形状维持原语义。

## Lua 调用修复

- 缺失或非函数绑定直接返回失败，最多每分钟采样一条警告并附带累计抑制数量。
  限流器只保存初始化标记、时间戳与抑制计数，不缓存玩家、函数名或 Lua 环境；真正的脚本异常仍保留堆栈。
- 每次读取当前绑定，之后定义或替换函数可以生效，先前的缺失结果不会被缓存。
- 所有调用恢复外层的场景、组和实体线程上下文，包括嵌套调用和异常。
  SpecificGroup 使用配置选定的组，OwnerFromGroup 使用技能所属实体的组。
- Gadget／OwnerGadget 原先只返回成功，没有执行函数。
  现在交由真实控制器执行，并共用现有控制器串行化及原素烘炉活动生命周期取消检查。
- 空组、空函数名、缺失或非法指定组参数、无效调用类型和超出 0–3 的参数数目返回失败。
  技能谓词不满足时跳过调用，避免产生 Lua 副作用。

额外核对真实资源发现，带数字参数的 Lua 函数依然以 `context` 为第一个参数。
例如 `Scripts/Common/V3_4/Activity_SeaLamp_BoatRaceV3.lua:466` 定义
`SLC_PlayerGetCoin(context,param1)`；旧代码在 paramNum=1 时仅传一个数字，替代了 context。
本地改为始终传 context，再传 0–3 个数字，并保留小数，避免坐标参数被强制转成整数。

context 是每次调用独立的 userdata，保留 ScriptLib 的 Java 接收对象，因此实际 Lua
仍可调用 `ScriptLib.GetContextGroupId(context)`；同时提供 `uid`、`group_id`、
`source_entity_id` 和 `target_entity_id`。这些值不放入共享全局变量。

两个玩家的并发 UID／组隔离、活动取消、谓词、错误和动态修改绑定。

## 第二十四批：告警窗口的并发修正

后续全量测试发现，时间戳 CAS 与抑制计数清零分别执行，会把新窗口内的并发计数包含在上一条警告返回值中。
将窗口切换与计数采集合并为同一同步操作，缺失函数检测后的日志输出仍在锁外，正常 Lua 函数调用不进入限流器。
初始化使用独立标记，Long.MIN_VALUE 作为真实单调时钟值处理，保持时间差的回绕语义。

保留原先 20 线程／20000 次调用的精确计数断言，新增最小时钟值测试，先在旧实现复现后修复。
四项限流测试及全量 1176 项／151 个套件通过，失败、错误、跳过均为零。
初次全量失败和最小时钟值失败的 XML、最终源码及 JAR 在系统临时目录
`C:\Users\InvokerBot\AppData\Local\Temp\lunagc-miliastra-types-20261008\`。
该验证证明并发窗口计数，未据此声称整体服务器性能提高。
