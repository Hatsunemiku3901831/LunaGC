# 客户端事件 Mixin 回调接入

## 来源与实际缺口

对照 AstaPS 固定提交 `7cc148d1f752a43d4b9146b3b73f26875902546f` 的 `HutaoC6Helper` 和 `ShinobuC6Helper`。
参考实现为缺少事件执行的角色加入专用伤害钩子与定时状态。本地已有资源、能力、修饰器和冷却框架，需要接入实际回调并继续核对完整机制。

当前胡桃与久岐忍六命资源共有 3 项修饰器 `DoActionByEventMixin`，`onEvent` 为 `HPDown`，普通字段 `type` 为 `Both`，动作包含触发能力。
本地枚举已存在、客户端 local ID 分发也已存在，但未注册对应处理器，因此这些已选择回调不执行。

## 本批实现

注册事件 Mixin 到既有有序回调执行器。客户端 local ID 选择的动作链沿用目标解析、已支持条件、队列优先级、触发能力和场景生命周期规则。
保留资源的 `onEvent` 和执行类型元数据；`$type` 继续用于 Mixin 分类，普通 `type` 字段不会覆盖分类。
没有新增协议标签或根据消息名称猜测新的包号。

本批接通客户端选择的事件回调。HPDown 自动检测、原生混淆条件、完整六命冷却／濒死保护及角色实机验收仍需继续接入。
当前未知条件的既有评估行为没有作为六命正确性的证明，也没有据此宣称两个角色的六命已经完整修复。
