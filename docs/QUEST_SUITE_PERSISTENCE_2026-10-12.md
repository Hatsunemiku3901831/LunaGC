# 任务套组切换与存档：2026-10-12

## 来源与复现

参考 AstaPS 的[任务套组持久化](https://github.com/MeChen618/AstaPS/commit/07eb59172b3a59e9da983558b4187c3a0be6062e)。
原本地每次正数套组指令都追加一条记录，刷新失败也追加，重置到 0 则不清除旧记录；
已执行变化没有在该入口保存。重新登录可能看到过时、重复或缺失的波次覆盖。

本地验证还发现两个实际缺口：

- Mongo 冷读取时，空列表可能被省略或保存为 `null`。重新接受套组变化需要可写列表。
- `ban_refresh` 的延后刷新比较旧活动套组与待刷新目标，重复请求同一新目标仍一直等待。

上述两个问题均由追加测试先复现，再修复。
固定上游补丁及失败记录保存在 `debug/aster-mid-20261011/batch101/`。

## 保存与切换规则

- 每个任务章节的覆盖列表，对相同场景／组只保留最近成功应用的套组。
- 成功重置到 0 移除该覆盖，保留其他场景、其他组及其他章节的记录。
- 刷新失败、套组不存在或仍处于延后阶段时，不保存新套组，也不通知套组 0 已应用。
- 重复套组不追加记录；应用真实变化后立即保存。历史重复记录在下一次成功指令时合并。
- 旧空列表在访问时转为可写空集合，随后成功变化可正常保存；不主动批量迁移数据库。
- 延后刷新仍等待再次请求同一目标。目标改变时重新等待该目标，已应用后清除待刷新状态。

覆盖以原章节为保存边界，未为不同章节互相覆盖时另设全局优先级。
任务指令的可见性固定、场景脚本初始化前的等待机制和完整游戏剧情仍待继续适配。
