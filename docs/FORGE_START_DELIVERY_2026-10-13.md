# 锻造启动校验与扣费确认

本批核对固定 AstaPS `7cc148d1f752a43d4b9146b3b73f26875902546f` 的锻造实现与本项目。
参考库仍使用相同的直接乘法、扣材料后追加队列路径，不能直接作为已修复版本合并。
本项目依据实际资源表和故障测试补齐启动校验与确认保存。

## 校验与实际费用

- 数量必须为正，且不超过资源 `queueNum`。检查配方存在、角色等级、资源世界等级列表、
  默认配方或已解锁图纸，以及可选协助角色确实归玩家所有。
- 加载 `effectiveWorldLevels`。没有该字段的旧资源保留原有行为；实际配方 12001 限制世界等级 3–9。
- 检查加工耗时、锻造点、摩拉、产物和材料配置；先计算数量与最终时间，溢出时拒绝扣费。
- 合并重复材料后检查库存，接受资源表中的零数量占位行。
- 同时确认材料栈、摩拉、树脂和锻造点的实际变化，扣空的材料栈同步确认删除。
- 保留 `resinUsage` 配置：关闭时跳过树脂费用，材料和摩拉仍按资源扣除。

实际资源共 61 条，数量限制为 1／5／10／20／40，耗时为 3／5／6／10／30／180 秒。
流程测试直接加载普通铁矿配方 11001 和含树脂配方 12001；并未把两条配方测试等同于全部 61 条的游戏验证。

## 队列保存

同一玩家的管理器和背包锁覆盖启动过程。队列新增持久化 `startState`，
0 表示可用、1 表示启动扣费或保存结果待核对。

1. 保存待确认队列并同步确认玩家文档。
2. 实际扣除费用，确认材料保存／删除。
3. 扣除锻造点并同步确认包含费用状态的玩家文档。
4. 清除待确认状态，保存成功后发送正常队列通知及启动成功回包。

失败队列保留待核对状态。它不产出可领取数量；同一玩家不能继续启动锻造，
也不能通过领取或取消该队列重复处理不确定费用。最终清理保存失败时恢复内存待核对状态。
旧 Mongo 队列没有新字段时默认为 0；待核对字段在重新载入后仍阻止再次扣费。

当前不是跨文档事务，也没有自动退款、补扣或恢复。
首个预约保存失败时无法证明预约已经落盘，重启后仍须核对实际数据。
旧零耗时队列避免除零，未来开始时间不产生负的完成数量，损坏的超大时间不回绕为正常结束时间。
