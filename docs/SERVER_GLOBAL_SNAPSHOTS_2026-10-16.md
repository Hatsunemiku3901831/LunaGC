# 服务端全局变量的进场快照

## 已接入

之前的进场包只手工填入燃素、魔导角色数量和月兆等级，
其他运行时 SGV 没有随角色、武器、队伍或世界发送。
联机的 `SyncTeamEntityNotify` 则只有燃素。

新增 `AbilityGlobalValueSnapshot`，从实体当前全局变量表读取 `SGV_` 变量，
写入 `AbilitySyncStateInfo.sgv_dynamic_value_map`。目前接入：

- `PlayerEnterSceneInfoNotify` 的角色、普通武器、队伍及 MPLevel 世界实体。
- `SceneTeamUpdateNotify` 的角色与普通武器能力块。
- 角色的 `EntityAuthorityInfo` 和普通武器的 `SceneWeaponInfo`。
- 联机 `SyncTeamEntityNotify` 中每个队伍所属玩家的状态。

自己的队伍进场与其他玩家的队伍同步共用 `buildTeamAbilityInfo`，
读取各自玩家的燃素、队伍构成和当前 SGV。
由包构造器明确计算的燃素等值优先于运行表中的同名／同哈希旧值，
同一哈希只发送一项，已有条目的未知字段继续保留。

读取保持零、负数及其他有限浮点值，跳过非有限值和零哈希。
哈希冲突使用完整变量名称集合检查，在过滤无效数值之前确定歧义；
因此另一个冲突项为 NaN 时，也不会把剩下的一项误当作唯一名称。
快照不写回变量、不触发回调或通知。

运行表只从当前实体读取：检查生命周期、场景、实体编号和注册表身份，
以及当前队伍／世界的归属。后台队伍成员可以在普通实体注册前发送 SGV；
角色／武器所属玩家已经换世界时，旧场景对象不会继续导出变量。
这些快照保留现有初始化标志，普通进场路径仍为 `is_inited=false`。

## 当前客户端路径

固定 7.1 客户端的九个原生函数已核对，输入哈希及汇编检查记录位于
`debug/aster-mid-20261011/batch291/global-native-verification.json`。

- 类型 79891 的 `0x14ea38b00` 为 `0x19030` 编解码器设置 tag `0x32`，
  `0x14ea38600` 将该字段读入对象 `0x18`；写入函数 `0x14ea38fa0` 使用同一个编解码器。
- `0x14c557010` 在组件存在且未要求跳过 SGV 的分支中，先把 `0x18` 的列表交给
  `0x14c557650`，随后才判断 `0x40` 的完整初始化标志。
- `0x14c557650` 解析变量键并将 `0x20` 的浮点数交给 AbilityComponent 更新函数。
  类型 22494 的写入函数 `0x1535834f0` 使用字段 1／3 保存键／数值。
- TeamEntityInfo（类型 62480）、TeamEnterSceneInfo（75806）、MPLevelEntityInfo（35036）
  的能力块编号分别为 2／10／5，与当前三条发送路径一致。

radare2 打开成功，但反汇编接口返回 Transport closed，随后使用同一固定输入进行只读 Capstone 检查。
