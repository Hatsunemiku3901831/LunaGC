# 资源逐条加载与兼容性：2026-10-08

## 来源和本地缺口

参考 [AstaPS 5bf70f9b 的资源修复](https://github.com/MeChen618/AstaPS/commit/5bf70f9b058f8cb1d4e889acaa42b6a7647f748d)。
它说明了活动、深渊初始化和空机关配置导致加载中断的问题。
本地已经处理部分空列表，仍缺少深渊空排期、监听器空参数、逐条隔离和多文件继续加载。

本批补齐共用加载路径：

- JSON 先解析整个容器，再逐行转换类型、执行 `onLoad` 和写入表。
  单行字段类型错误、空行、初始化或取 ID 异常只拒绝该行，后续有效行继续加载。
- JSON 语法损坏或顶层形状错误仍报告文件失败，并且不会安装该文件的部分行。
  同一资源类型的其余文件继续尝试；文件失败不留下“已加载”的缓存标记，允许重试。
- TSV／TSJ 解析返回的空行以及后续初始化异常使用同样的逐行安装保护。
  原有 TSV 字段解析器保持现状，不据此宣称所有字段格式错误都已经严格拒绝。
- 保留合法 ID 0、重复 ID 最后有效行覆盖、初始化后计算的组合 ID，以及原有加载优先级。
  失败的替换不会覆盖主表中已有的有效对象。
- ID 聚合警告依据本文件成功行和不同 ID 的数量，重载不再根据全局表增长量误报。
- 每文件汇总拒绝数和前五个样本，位置与原因分别截断到 200 字符。
  TSV／TSJ 解码器原有的日志行为没有在本批重写。
- 角色／怪物单配置不会把 `null` 写进缓存。机关和场景能力的配置映射逐项隔离，
  `null` 文件或条目保留已有有效配置，Gson 支持的键值数组 `[[key,value],...]` 和空数组 `[]` 保持兼容。
- 空深渊排期规范为列表，活动忽略空监听器 ID，监听器缺少参数时规范为空列表。
  缺少整个触发器仍属于无效数据，不会伪造玩法。
- 按文件名读取的入口统一使用 `FileUtils.getExcelPath`，支持配置资源目录、Server 覆盖和三种表格式。

## 验证边界

本批没有部署到日常服务。全量资源表 ID 覆盖也不能替代角色技能、历史活动、千星奇域或商城界面的实机验收。
逐行隔离保证主表写入顺序，不提供对任意 `onLoad` 副作用的事务回滚。
资源重载也没有增加删除旧 ID 或自动监测文件更新的行为。
JSON 容器解析使用额外内存；未据此声称整体加载速度或内存用量改善。
