`a8e6e3932515bb5730ae4469bfd76a4c3516433f`、

当前实际资源包含 697 条开关、1,053 项命名条件；其中 1 项使用 `cond_type`，
其余使用 `condType`。两种字段均可读取，类型 getter 继续返回原枚举。
资源中的空槽位和 `OPEN_STATE_COND_NONE` 被移除；未知的命名条件保留，参与判断时返回未满足。
未知条件与已满足的等级条件并列，也不能被丢弃后误开功能。

| 条件或场景 | 自动解锁策略 |
| --- | --- |
| 等级、子任务、章节完成 | 读取当前玩家状态，全部满足后开启 |
| 供奉、城市声望及未知类型 | 尚无完整实现时保持条件未满足 |
| 非默认开关没有有效前置条件 | 等待任务执行或其他明确开启入口 |
| 客户端控制的开关 | 等待合法客户端请求；仍检查全部前置条件 |
| 资源明确默认开启的服务端开关、派蒙入口 | 登录快照可使用当前资源的默认值 |
| 玩家已有记录 | 快照优先使用该记录，包括明确的 0 |

默认值在发送快照时读取，解决玩家管理器先于资源初始化而缓存空列表的问题。
同一开关的资源重新加载会替换旧条目，避免旧默认值残留。
原 `DEFAULT_OPEN_STATES` 常量保留为废弃的动态只读视图；正常消息路径直接检查当前条目。
黑名单 48、忽略项 1404 继续限制自动开启；玩家既有记录和明确开启入口不被自动回滚。
关闭树脂消耗时，登录快照中的开关 45 仍为 0。

## 可选全功能解锁

在 `config.json` 的 `server.game.gameOptions` 中配置：

```json
{
  "unlockAllOpenStatesOnLogin": true
}
```

默认值为 `false`，旧配置缺少字段也不会启用。设为 `true` 后，登录时开启资源目录中
除黑名单和忽略项外的开关，包括客户端控制的开关；完整状态先更新，再发送一次登录快照。
关闭此选项不会撤销玩家此前已经获得的状态。
该选项调整入口权限，对应任务、商城、活动等玩法仍需各自实现。

此选项与 `questing.enabled` 独立。停用任务时仍保留本地既有的蒙德起始区域、
传送点 7 和导航开关 47；不因停用任务就批量开启所有功能。
正常模式取消原 7.0 地区开关的无条件默认开启，使用资源中的任务前置。

神像章节资源尚未加载或保存章节因资源不一致而暂缓加载时，
登录过程可继续发送功能快照，不访问空章节，也不创建新的重复任务进度。
