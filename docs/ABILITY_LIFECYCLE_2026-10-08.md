# 首次入场与异步技能生命周期

本批延续 [世界进入与恢复](WORLD_ENTRY_2026-10-08.md)，补齐初次发布世界和排队技能的边界。
参考库版本和后续范围见 [外部实现适配记录](UPSTREAM_INTEGRATION_2026-10-08.md)。

## 来源与本地适配

AstaPS 的 `ActionTriggerAbility` 复用已有技能并执行 `onAbilityStart`，
提交 `a0c4d2f8f87dae706a42a95e72e413c191dfabcb` 又改为使用列表快照，避免联机遍历并发修改。
固定版本仍读取 `player.getWorld().getHost().getAbilityManager()`；本地改用技能记录的管理器，
并按名称和施法者身份复用，保留访客归属。

AstaPS 和 HunkyMeow 的世界构造器也会提前注册尚无成员的世界。
本地沿用上一批的原子成员登记，进一步把首次注册移到入场预检之后。
参考思路需要结合当前服务的退役与迁移规则适配。

## 世界发布

构造器完成初始化后，世界暂不加入服务器 tick 集合。
首次入场通过场景和 TPS 预检，在成员登记临界区内注册世界。
预检失败的世界不发布；构造与首次入场之间的 tick 不会把它退役。
尘歌壶初始化也不会提前暴露给 tick。

已发布世界仍使用原来的关闭、在途迁移计数、访客恢复和空世界退役规则。
显式退役后的旧引用不能接收新玩家。
现有 tick 测试通过显式注册构造其测试场景，继续验证集合锁与退役判断。

## 排队技能

场景实体记录生命周期版本，移除后版本失效；重新加入同一对象进入下一版本。
异步动作、异步 Mixin 和治疗回调在提交与执行时检查施法者场景、实体版本、ID 和登记实例。
治疗序列还在每步之前检查，保留原有治疗标签和动作顺序。

允许实体首次登记前的初始化动作。未显示的队伍实体被移除时同样使旧任务失效。
同 ID 的新对象不会被旧引用移除，TPS 武器清理也会更新生命周期。
技能实例列表使用并发快照，已有按索引读取的客户端技能列表语义保留。

这些检查用于阻止过期的排队工作开始执行。已经执行中的任意处理器，其脚本、网络或数据库副作用
没有通用事务回滚。世界和队伍实体的场景是动态绑定的，本批保留其初始化语义；
完整生命周期仍需单独适配。

## 触发技能

- 使用原技能记录的管理器，不再通过当前世界房主寻找施法者。
- 同一目标、同一施法者和同一名称复用同一实例，不反复堆叠。
- 首次触发按顺序执行 `onAdded` 再执行 `onAbilityStart`；再次触发只执行开始动作。
- 并发触发只创建一个实例，每次触发都执行开始动作。
- 缺少资源、参数不完整或目标已失效时返回失败，不安装新实例。

初始化回调在实例列表锁外执行。初始化期间的新触发先登记开始动作，
初始化完成后再执行，不阻塞另一个调用线程。
每个开始动作保留提交者的治疗标签与服务端执行标志，执行后恢复工作线程上下文。

真实 7.1 丝柯克资源用例提取拾取技能中的 `TriggerAbility` 和拾取处理器，
验证重复触发回能、技能计时冻结值，以及已有冷却状态不会被初始化重置。
该用例控制回能参数为 8，用于验证资源动作执行；完整天赋、拾取对象、视觉效果及客户端操作仍待验收。
