# 深境螺旋历史配置与管理工具

本轮在现有深渊状态机上增加历史目录、GM 控制、自定义难度、出生配置和脚本修复。**尚不能声称第 8–12 层已与官服完全一致**：7.1 原生协议、地脉／渊月祝福、完整 Boss 行为与客户端实战仍有待恢复和验证。资料不足的期数不提供伪造的“精确配置”。

## 打开和使用

双击根目录 `Open-Abyss.cmd`，或在现有 `Open-GM.cmd` 后台选择“深境螺旋”。沿用现有 GM 认证与仅本机访问设置。

1. 选择年份，点击“详情 / 编辑”查看本期第 8–12 层。取消“仅显示脚本齐全的期数”可查看跳过原因。
2. “一键启用原配置”保存这期并把自定义倍率复位到 1、等级偏移复位到 0。每期的真实来源日期显示在目录中；游戏运行窗口仍采用本服常驻开放配置，不把历史结束日期当作当前关服时间。
3. 自定义生命、攻击、防御倍率或等级偏移，点击“应用自定义配置”。倍率是相对于资源难度的额外倍率，不是最终血量。
4. 输入在线 UID，读取角色，选择两支不重复的队伍和第 8–12 层，点击“选队并入场”。在客户端操作工作台开始战斗。可通过后台重试本间、进入下一间和退出。
5. 完成本层后先退出，再选择下一层。GM 入场是管理入口，不以原生界面的前层解锁状态作为限制；它仍校验角色归属、双队、排期成员和场景交接。

“导出配置”保存可再次导入的 JSON。“导入配置”先填入表单，点击应用才写入服务器。后台显示的基础生命按当前资源的基础值、等级成长和楼层系数计算，未计词缀、祝福或动态能力，不能当作历史官服血量的认证。

这里的“排期记录”按来源表计数，包括来源中的特殊排期 ID，不能当作经过独立核定的官服周期总数。2026 数据截至来源的 10 月 16 日排期；未公布的未来期数不补造。

可用的 26 期覆盖 75 个不同场景。每层三间的关卡、怪物等级、星级条件，以及每个出生点的 monsterId、configId、位置、朝向、姿态、词缀和 AI 配置均保留。套件列表明确标作 **suite**；真正波次／怪潮触发由原始脚本执行，不能把每个 suite 简化成一波。

64 条资料不全记录保留日期、楼层、等级、星条件、客户端预览和缺失文件清单，禁止一键启用。未将客户端预览列表拼成“真实波次”，也未把一套怪物配置复制到不同年份。

## 自定义配置

本机生效文件是 `local/data/TowerPresets.json`，由 GM 原子写入，不提交 Git。字段 `schemaVersion=1`，`revision` 用于阻止旧浏览器窗口覆盖较新设置。JAR 内目录是证据，不直接覆盖资源 Lua。

```json
{
  "schemaVersion": 1,
  "profile": {
    "scheduleId": 62,
    "hp": 1.5,
    "attack": 1,
    "defense": 1,
    "levelOffset": 0,
    "monsters": [
      {
        "groupId": 233746004,
        "configId": 4001,
        "monsterId": 0,
        "level": 100,
        "hp": 1,
        "attack": 1,
        "defense": 1
      }
    ]
  }
}
```

这是**导入格式**；服务器持久文件另有 `revision`。每个倍率必须是 0.05–20 的有限数字；等级偏移为 -90–100 的整数，实际等级钳制到 1–200，并检查成长曲线存在。出生点覆盖中 `monsterId=0`、`level=0` 表示沿用配置，组与 configId 必须属于本期第 8–12 层，不可重复。

生命计算为“基础生命 × 等级成长 × 本层系数 × 全局自定义倍率 × 出生点自定义倍率”，之后仍受现有 Ability 机制影响。第 8–11 层的本层系数为 2，第 12 层为 2.5。攻击、防御的自定义倍率不改变抗性、攻击动作、盾机制或怪物技能时序。

替换怪物保留原位置、数量、波次、pose 和出生点身份。机制型 Boss 的脚本可能依赖特定种类，不能认为任意替换都兼容。AI 默认采用当前客户端对应怪物的行为和已实现能力；没有用“AI 强度倍率”冒充官方 AI。

应用前核对资源表／脚本指纹、三间结构、场景区块和组依赖、怪物与等级曲线。资源改变后应重新导出、测试、重建并重启；不能只修改目录中的状态字符串绕过检查。

```powershell
python tools\export_tower_catalog.py
python -m unittest discover -s tools/tests -p test_tower_catalog.py
```

## 行为和数据边界

- 选队时冻结难度与楼层列表；进入每间前把楼层、基础等级和难度装入 DungeonManager。首波、后续波次、上下半和重试均使用相同配置，后台修改不会改变正在打的本层。
- 怪物构造前先设置组、configId、pose、AI 和 Lua 元数据；初始化能力与发包统一使用场景词缀与基础词缀的去重副本，避免漏用场景词缀或修改共享列表。
- 补齐 `DelAllSubEntityByOriginOwnerConfigId`；保留召唤物的原始组／出生点身份，可在主人移除后清理嵌套召唤物。清理不计击杀、不增加怪潮进度。
- 属性重算保留当前生命比例，不反复累乘倍率；未配置深渊的普通场景维持原数值。
- 星记录增量通知从完整实际记录构建，与全量通知一致。零星通关保存键；缺少星条件参数按不满足处理，避免结算异常；空挑战结果不抛异常。
- 选择历史期数不会清除存档、重置已领标记或重新发奖。默认已补满的前八层仍可进入战斗，但不变回未通关存档。
- 尚未补齐全部原生协议、选卡／月度效果、星奖励经济闭环和周期独立存档。本轮不声明已经完成这些功能，具体待办见原接手文档。
