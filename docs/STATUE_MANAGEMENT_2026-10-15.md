# 神像管理命令

参考 AstaPS 固定提交 `7cc148d1f752a43d4b9146b3b73f26875902546f` 的 `StatueCommand`，
使用本项目的命令框架、城市资源表、供奉写入和传送点管理接口接入。

## 用法

命令名 `statue`，别名 `sots`。控制台和 GM 可使用 `@UID` 选择在线目标；
游戏内省略目标时使用本人。沿用 `player.teleport` 与 `player.teleport.others` 权限。

| 命令 | 效果 |
| --- | --- |
| `statue @10001 city` | 查询目标当前场景的神像城市、等级与部分供奉量 |
| `statue @10001 city 7` | 查询指定城市；有未确认供奉时显示操作 ID 和阶段 |
| `statue @10001 level 7 6` | 将 7 号城市设为 6 级，部分供奉量清零 |
| `statue @10001 reset 7` | 将 7 号城市重置为 1 级 |
| `statue @10001 reset` | 沿用参考命令的默认值，重置 8 号城市 |
| `statue @10001 status [pointId]` | 查询指定神像入口；省略 ID 时寻找当前场景最近神像 |
| `statue @10001 lock [pointId]` | 锁定并隐藏神像入口，保留永久探索记录 |
| `statue @10001 unlock [pointId]` | 解锁或解除临时锁定，并立即同步入口状态 |

神像入口根据实际点位的 `maxSpringVolume` 判断，同时接受当前原始字段 `PHBHHNDGFCF`。
本次扫描实际 scene3 点位发现 62 个非零泉水容量的神像入口，未沿用参考库的固定 gadget 白名单。
不存在的点位、普通传送／跳转点及其他场景的点位不能通过此命令锁定或解锁。

## 进度、奖励和写入

管理性调级只修改城市等级和部分供奉量，不扣神瞳、不补发供奉奖励，也不重新计算体力或触发供奉事件。
按实际资源校验城市和目标等级，不使用固定 1–8／1–10 上限；大数值不能通过复合资源键碰撞绕过校验。
保存确认后发送城市响应及该场景的完整城市快照，并记录管理修改日志。
保存抛错时恢复内存中的原记录；这不构成跨集合事务，也不证明未知保存结果已经回滚。

调级和重置与普通供奉共用库存监视锁。存在 `pendingOffer` 时拒绝覆盖，反馈保留操作 ID，
供奉记录的完整核对与补偿恢复仍是后续工作。

入口锁定和解锁复用 `PlayerProgressManager`：首次发现仍领取既有解锁奖励，
锁定后再解锁不会重复领取。锁定不会删除探索记录；解锁仍执行已有任务、脚本及见闻刷新。
