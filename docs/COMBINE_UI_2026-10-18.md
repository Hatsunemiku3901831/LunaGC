# 合成页面初始化通知

用户反馈：原料和摩拉足够时，“合成”无法点击，随后页面右上角关闭按钮也无响应。
本地角色冒险等阶为 10，截图中的污秽的面具配方为 11003，要求等阶 5、破损的面具 3 个和摩拉 25。
排查时材料数量为 13，角色没有待核对的合成／还圣奥迹记录。

## 已修正的问题

登录日志明确记录 `PacketCombineDataNotify has no 7.1 CmdId, so it is not being sent`。
原代码仍使用包号 `-145`，因此整条配方初始化通知被跳过；其列表字段 9 也与当前客户端不符。

- `CombineDataNotify` 使用包号 **28314**。
- `combine_id_list` 使用字段 **13**，支持 packed／unpacked uint32。
- 保留现有的默认配方、图纸解锁、角色等级、材料扣除、产物发放和保存确认规则。

## 客户端依据

只读分析的客户端 SHA-256 为
`7f89938da606c1281659607d464702cddb9a09a7d4320a196630f60a811ec38e`。

| 内容 | 原生位置 |
| --- | --- |
| 通知类型 | 82833，`FLNFDFNMION` |
| 包号返回函数 | `0x152681b20`，返回 `0x6e9a`（28314） |
| 读取函数 | `0x152681a50`，接受 `0x68`／`0x6a`，对应字段 13 |
| 配方列表 | 原生对象偏移 `0x18` |
| 接收函数 | `0x14b14cf10`，清空并重建合成模块的已解锁配方集合 |

原始分析和诊断记录放在忽略的 `debug/combine-ui-20261018/` 下，未使用 Computer Use。

## 验证

先新增两项独立协议测试，两项均在修改前失败：包号实际为 -145，序列化列表实际使用字段 9。
修正后，合成协议、手册和保存凭证三套件 **86 项通过**。

另发现合成手册测试仍使用旧的无确认数据库替身；原始生产代码下，同一用例也失败，
而使用隔离存储的合成凭证用例通过。已将手册测试接入现有的角色保存保护及物品写入测试工具，
保留原有材料、奖励、并发和失败断言，不放宽生产保存规则。

最终合成与锻造 **11 套件、304 项测试通过**，失败、错误和跳过均为 0。
核对了 5,516 个 Java／proto 输入与构建目录一致（允许换行差异）、编译类与 JAR 一致，资源未变更。

构建 SHA-256：`b21a9e7a3f4535afb717406d0c448a7f3e25e522034c318adc7f68d2426984c6`。

本次在旧运行版本中复点时没有收到合成请求，材料未扣除。
以上证据确认了登录通知的协议缺陷；合成按钮和关闭按钮是否同时恢复，需要部署后再次进入客户端验证。
