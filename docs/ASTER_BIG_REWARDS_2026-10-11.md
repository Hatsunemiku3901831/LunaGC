# 大型陨星奖励机关

## 接入范围

恢复原始 `LF_Battle_Win` 使用的 `CreateScenePlayGeneralRewardGadget`。
只有原始大型陨星玩法 2 的有效胜利轮次，才能创建主控组 `133001413`、
配置 `413124`、机关 `70330041` 的奖励点。重复调用返回成功并保留同一个机关与领取代次。
失败、倒计时、运行中、已失效组和错误配置不能生成奖励。

修正 `MpPlayGroupData` 的奖励机关字段映射：当前资源使用
`generalRewardConfigId`，此前解析后的 `rewardConfigId` 为 0。
Lua 接口在 Java 转换前验证字段类型、整数范围与正数条件，字符串和小数不会被静默转换。

## 原始奖励规则

行为以固定原服务端的
[BaseScenePlayBattle::createGeneralRewardGadget](https://github.com/Havesten/hk4e-sources/blob/d12e0ae8dbe6012aefca71128d4c13e48113b68d/data/jenkins/jenkins_hk4e/workspace/hk4e_3.4_dev/gameserver/src/player/scene_play/base_scene_play_battle.cpp)
为依据。Git blob 为 `588bb1e562ddc40050663a9bc58e51263f9a9a7a`，
SHA-256 为 `4d14c17937b3e6ffe7e242d309c317145d39f9a467359e7fc8bb71e630d8b3b9`。
Lua 参数解析参照同一提交的
[ScriptLib::CreateScenePlayGeneralRewardGadget](https://github.com/Havesten/hk4e-sources/blob/d12e0ae8dbe6012aefca71128d4c13e48113b68d/data/jenkins/jenkins_hk4e/workspace/hk4e_3.4_dev/gameserver/src/script/script_lib.cpp)。
旧服务端的协议标签不作为当前客户端字段依据。

- 奖励点生成时枚举当前世界成员，固定领取资格；不局限于战斗成员或当前场景玩家。
- 每名玩家使用自己的世界等级，生成时固定掉落 ID 与数量。之后改变世界等级不会改变这次奖励。
- 每次个人领取消耗 **40 点原粹树脂**；预览不扣费，不接受浓缩树脂。
- 原始普通场景玩法奖励点的 `dead_time` 和 `destroy_cd` 都为 0；没有中型陨星奖励点的首次领取后倒计时。
- 所有玩家领取后清理机关。原轮次失效、活动关闭或开启下一轮时清理旧机关和预览凭证。

## 保存与防重

房主活动文档保存共享机关的领取代次、固定奖励、剩余玩家与未确认领取。
个人活动文档保存未确认领取、已领取代次、货币 110 与领取次数。
两份文档按 UID 顺序加锁，同一个房主领取只使用一份文档。

1. 确认当前排期、第三章开放时间、冒险等级、机关身份、加载状态、世界／场景成员和五米交互距离。
2. 正式领取必须使用当前机关的预览凭证；确认剩余资格、原资源一致性和整数余额上限。
3. 同步确认房主与个人的领取保留记录，再消耗树脂。
4. 同步保存树脂；通过实际库存入口发放冒险阅历、好感经验，确认玩家和角色保存。
5. 保存个人领取凭证，再确认房主剩余资格变化。

树脂不足且取消记录保存成功时可重试。树脂／发奖异常，以及已写入但未收到确认的保存，
保留相应领取记录，阻止重复发放。个人确认成功但房主确认失败时保留个人已领取凭证。
机关清理后，房主文档中的未确认领取仍会阻止下一轮覆盖，错误日志包含玩家 UID 和领取代次。
这些异常需要核对持久化状态，当前不会自动重发或自动解除。
