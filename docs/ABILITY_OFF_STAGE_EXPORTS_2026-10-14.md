# 公共能力的 doOffStage 导出兼容

## 问题与资源范围

第二百零七批结构审阅发现 Avatar_Common 两个能力的动作含 doOffStage 数组，
布尔字段解析失败。实际启动加载按文件读取列表，任一条失败会使该文件的其他公共能力也无法载入。

这个键有 262,055 个布尔值、99 个空数组、40 个数值和 2 个字符串。
数值、字符串还出现在其他类型的 Mixin／选择器结构中，不能一概改成布尔值或猜测新字段名。
原始形状与路径记录在 `debug/aster-mid-20261011/batch208/offstage-inventory.json`。

## 修复

- 动作的布尔值保持原有语义；当前导出的空数组兼容为本地已有的缺省 false。
- 保留非布尔原始 JSON，空数组、显式 null 及未知形状可往返；Java 明确设置 true 时写回布尔值。
- 未确认的非空数组、对象、数值与字符串保持不可执行，不把它们转成离场执行许可。
- 同步、异步及回调动作路径检查原始形状；完整子动作树预检避免先运行一部分再遇到未知控制配置。
- 标准化在资源树副本上进行，解码不再修改调用方传入的 JSON。
- 显式 null 的保留只影响这个成员，其他字段继续使用原有的空值输出规则。

本批核对了客户端动作配置基类的字段与构造代码；导出键与混淆布尔字段的完整对应仍需继续核对。
没有按未知字段或数组内容编造客户端包号、动作参数或权限。
