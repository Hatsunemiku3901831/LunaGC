# 家园批量开始制作协议

## 原生依据

当前固定指纹客户端的家园管理器 `0x14fac9ee0` 从 `List<类型 80016>` 创建请求类型 85662。
请求包号 getter `0x15089ca40` 返回 **871**；其静态 codec `0x15089c840` 使用 wire key `0x62`，即 repeated message 标签 **12**。
列表元素为类型 23201。

元素写入器 `0x1481dcd70` 将 `CBEPHONEGMP` 写为 uint32 标签 **7**，将 `IJLHELGGCBA` 写为 uint32 标签 **12**。
两字段名与已确认单条开始请求类型 48691 的配方和角色字段一致，尽管内存字段顺序不同。
批量发送函数使用结构的第一项作为配方、第三项作为角色。
界面 `0x1486e5c40` 按数量把选择展开为多项，每项的中间值为 1；协议元素中没有额外数量字段。

制作界面调用 `0x1486e6170` 将新增任务数和已用槽位相加，检查剩余容量，再尾跳到批量发送函数。
响应类型 63299 的 getter `0x14793e720` 返回 **9832**；解析器 `0x14793ea20` 确认错误码标签 **4**、槽位标签 **15**。
接收函数 `0x14fad60d0` 更新队列后发家具刷新阶段 6。
该界面阶段分支 `0x1486ec683` 推进批量选择列表，并刷新队列和制作视图。

这补充了此前竞争响应的业务依据：9832 接入批量开始路径，单条开始响应继续使用候选 21056。
业务归属依据静态发送与界面消费路径，尚未通过实际游戏请求与响应往返验证。
协议使用服务端语义名称，原始类型名仍为混淆名称；没有据此宣称恢复了客户端原始 protobuf 名称。
