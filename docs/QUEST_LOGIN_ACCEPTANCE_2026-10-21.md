# 任务初始化白屏与反复重连

点击开始游戏后，客户端在进入世界阶段白屏，短暂转圈并提示重新连接服务器。服务端的 `PlayerLoginReq → Player.onLogin → QuestManager.onLogin → enableQuests → addQuest` 对缺失的子任务调用 `start()`，登录响应无法发送；下一次连接重复同一异常。HTTP 健康和游戏端口正常不能发现这类单次登录失败。

## 原因

本次资源审计发现，任务 Excel 中有 66 个子任务未出现在对应 `BinOutput/Quest` 章节的子任务列表。`GameMainQuest` 按章节列表构造子任务，自动接取却按 Excel 条件检索；两者未校验一致性。

批量完成章节的存档让其中 8 个遗漏子任务满足了前置条件：`2202205`、`30318`、`42710`、`42711`、`48006`、`7113908`、`7165415`、`7201303`。例如 `30317` 已完成后，系统尝试启动 Excel 中的 `30318`，但章节 `303` 没有这个子任务。原实现也没有排除已完成章节的自动接取。

此前的建档验证覆盖了冷读数量、已有子任务的完成状态和持久化，但未执行任务登录恢复，因此没有覆盖这条路径。

## 修复边界

- `QuestData.hasMatchingChapter()` 核对章节身份和子任务成员关系；资源加载完成后汇总报告不一致定义，保留定义供已有存档解释。
- 自动接取跳过无对应章节子任务的定义，并跳过已完成主任务。
- 显式任务启动同样验证资源；已有章节缺少请求的子任务时返回不可启动，每个会话的每个子任务只报告一次，后续恢复匹配数据后仍可重试。
- 保留已有主任务、完成状态、时间戳和进度；不补造任务定义、不清空存档，也不把遗漏子任务自动标为完成。有效子任务的显式 GM 启动继续保留。

不一致的资源仍需由匹配版本的完整章节数据修复；跳过不可启动任务只能保护登录与其他有效任务，不能让缺失剧情自动可玩。

## 回归验证

`QuestAcceptanceGuardTest` 使用独立 Mongo 实例，覆盖实际资源中的上述 8 个子任务、已完成章节的冷读后任务登录恢复、缺失章节、Excel 单边子任务、存档缺少子任务后的保留与重试，以及正常自动接取和显式启动。修复前 6 项测试中 5 项失败，包含与实机相同的 `quest.start()` 空指针。

修复后，针对性 69 项回归全部通过；扩展到任务相关回归共 21 个套件、373 项测试，0 失败、0 错误、0 跳过。

本机使用 `task.cmd serve` 正常停止旧服务、重建并启动便携服务。HTTP 8088 与 UDP 22101 均属于新 Java 进程，健康正常、死锁数为 0；启动记录的 JAR SHA-256 与文件一致，三个变化类的 JAR 字节与本次编译产物一致。启动日志识别出上述 66 个资源不一致的子任务，无启动异常。这些检查不替代客户端进入世界的确认。

本机测试资料保存在忽略目录 `local/white-screen-fix/`，诊断资料在 `local/white-screen-audit/`；不提交玩家资料、连接凭据或运行日志。
