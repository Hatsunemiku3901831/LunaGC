# 动态技能槽位与就绪条件

## 来源与缺口

沿 AstaPS 临时技能／冷却适配继续核对当前资源与 7.1 客户端。
资源共有 **426 个 SwitchSkillIDMixin 节点／139 个文件**，服务端此前没有解析此类型；技能就绪条件只查询默认技能库槽位。
最初按含 priority 的节点筛选漏掉 12 个默认配置；回归库存已改为扫描全部同类型节点。

本批读取有效根能力与修饰器中的切换配置，让 BAEGOCNMDPJ 查询当前选中技能的恢复队列。
输入标志、按钮行为、完整模式激活和其他技能注册仍属于后续工作。

## 原生核对

| 来源 | 核对内容 |
| --- | --- |
| 0x14b561e60 | 默认六元素槽位数组；比较当前技能实例的槽位及优先级，较小优先级不替换已选结果 |
| 0x14b5611a0 | 保存槽位索引与优先级，分别写入实例 +0xd0 与 +0x78 |
| 0x147b9ea00 | 从配置读取包装的索引并传给注册函数 |
| 0x15302ada0 | 配置默认优先级为 4 |
| 元数据 NCNELJMLNJP（62919） | 从默认值表读取实际优先级常量 |

优先级数值为 Base=0、AvatarCommon=4、AvatarSpecial=5、AvatarCustomSkillBase=10、AvatarCustomSkillCommon=14、Playmode=101、Quest=102、PlaymodeExtra1～4=1001～1004。
这些是稀疏数值，不能使用 Java 枚举序号替代。

r2 连接仍返回 Transport closed；使用现有只读提取器及 Capstone，核对三个客户端文件的固定 SHA-256。
源码、反汇编、元数据默认值与校验脚本保存在 debug/aster-mid-20261011/batch199/，未修改客户端。

## 服务端行为

- SwitchSkillIDMixin 的 skillIndex 从零开始，就绪条件中的 skillSlot 从一开始；保留普通槽位空洞、第五槽位能量技能、第六槽位攻击模式技能。
- 按有效来源及资源优先级解析覆盖，来源移除后恢复剩余配置。同优先级采用服务端来源创建顺序确定结果；客户端完整同级竞争行为仍需实机核对。
- 修饰器客户端重复确认沿用原实例／来源顺序，避免确认消息制造新的覆盖来源。
- 显式 skillIndex 优先于整理资源时补入的默认兼容字段 actorIceSubHurtDelta。字段缺失不自动指定第一槽位。
- 未知技能、非当前角色拥有的技能、无效索引、未知优先级、失效上下文及未支持的条件不产生覆盖。
- 所选技能继续使用现有普通或共享恢复队列；查询不消费次数、不写存档、不发送通知。

本批只实现槽位解析与就绪查询。额外输入标志、载具切换、AvatarChangeSkillMixin 的技能注册、UnlockSkill、完整技能模式及游戏内验收仍需继续适配。
