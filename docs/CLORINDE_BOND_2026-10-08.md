# 克洛琳德生命之契与治疗转换适配

## 来源与范围

参考 [AstaPS 的克洛琳德实现](https://github.com/MeChen618/AstaPS/blob/932078b21b557b980c196dcc74a27cfdabaf130f/src/main/java/emu/grasscutter/game/ability/ClorindeBoLUtil.java)，
核对当前资源与本机 7.1 客户端。外部治疗转换、突进自身治疗及突破被动的设计，
也与 [HoYoWiki 的技能说明](https://wiki.hoyolab.com/pc/genshin/entry/5653?lang=en-us) 对照。
本轮接入生命之契核心结算；完整角色动作与命座玩法仍需后续验收。

资源来自本机 `LunaGC-Resources`：

- `BinOutput/Ability/Temp/AvatarAbilities/ConfigAbility_Avatar_Clorinde.json`
- `BinOutput/Talent/AvatarTalents/ConfigTalent_Clorinde.json`
- `ExcelBinOutput/ProudSkillExcelConfigData.json`

该来源提供了治疗转换、子弹加契和自身治疗的参考。实际实现采用已安装修饰器及其资源条件，
倍率来自技能／固有天赋参数；不使用额外的技能名称模糊匹配或全局计时器来猜测技能状态。

## 本机客户端证据

客户端只读核对使用 `r2mcp-basic` 技能；本轮没有可用的 r2 MCP 接口，使用本机 r2 CLI。
对应 `YuanShen.exe` SHA-256：

```text
7f89938da606c1281659607d464702cddb9a09a7d4320a196630f60a811ec38e
```

地址仅适用于该二进制。类型与成员表来自既有提取结果；本轮重新验证了二进制哈希，
并检查实际执行函数，而非只依据类型名或克隆方法推断语义。

| 资源类型 | 执行函数 | 确认的行为 |
| --- | --- | --- |
| `LPKOBOLMDBI` | `0x14a864090` | 读取战斗属性 `0x7d4`（2004，当前生命之契），与动态阈值比较 |
| `GKGBIPDLMMG` | `0x14a750df0` | 任一子条件成立即失败；只有所有子条件均不成立才成功，即 NOR |
| `ONJEHDDFFCH` | `0x14a7345d0` | 在治疗事件中检查标签数组是否包含本次治疗标签 |

比较函数 `0x149c71440` 的跳转表位于 `0x149c71868`，枚举 0–4 依次为
`Greater`、`GreaterOrEqual`、`Equal`、`Lesser`、`LesserOrEqual`。
省略 `logic` 时是严格 `Greater`。

当前枪击资源省略了 `logic`，在比较成功的反分支执行加契。
因此本轮保留客户端与资源的精确行为：契值恰好等于最大生命时仍会执行这次加契；
超过最大生命后才停止。该精确边界与技能说明中常用的“小于 100%”表述不同，
有独立回归测试，仍需实机对齐，不能据文字说明擅自改成 `GreaterOrEqual`。

本机证据保留在 `debug/clorinde-20261008/` 的 `runtime-evaluation.jsonl`、
`debt-comparison.json`、`comparison-enum.json` 与 `native-types.json`。
探索时保存的克隆函数和空的间接类型搜索结果不是运行行为的证明。

## 实现

1. `SwitchHealToHPDebtsMixin` 保存并执行资源中的条件，检查被治疗实体当前安装的修饰器。
   读取该修饰器所属技能的倍率，不读取外部治疗者同名参数。
2. 克洛琳德普通外部治疗按 80% 增加生命之契；解锁对应固有天赋后按 100% 增加。
   保留 200% 最大生命上限与死亡保护；转换不会恢复 HP。
3. `Clorinde_ElementalArt_Heal` 被资源条件排除，正常进入先偿契、再恢复 HP 的结算。
   实际资源中两档治疗系数为当前生命之契的 1.04 与 1.10。
4. 新建技能实例时应用角色已解锁的固有天赋参数。
   枪击倍率为 0.35 最大生命；爆发加契取实际技能等级参数，一级 0.66、十级 1.20。
5. 删除 E／Q 技能开始、闪避标志清零和任意攻击命中的额外加／扣契分支。
   枪击、爆发和治疗分别由实际资源动作结算。
6. 修饰器移除即结束转换。命名登记为当前状态的来源，旧客户端实例 ID 晚到不会重新激活已替换的状态。
   单独调用 Mixin 不再把角色永久标记为禁止治疗。
7. `HealHP` 与芙宁娜现有团队扩散路径共用转换结算；保留外部调用者显式设置限制的兼容接口。
   阿蕾奇诺的真实资源限制同样支持自身爆发标签与移除后的恢复。
8. 异步 `onHeal` 回调按顺序执行，携带不可变的治疗标签。
   嵌套条件能读取本次事件；异常与嵌套调用后恢复原上下文，下一次无标签治疗不会复用上次标签。

转换与普通治疗均使用被治疗实体的锁；命名修饰器快照在既有登记锁下取得。
没有新增跨玩家的静态角色状态表、额外线程池或技能过期计时器。

## 验证

修正测试夹具后，32 项核心用例在第六批实现上复现 **24 项断言失败**。
最初夹具缺少技能等级表、固有天赋集合与技能实例，及一次切回旧源码时残留新辅助类的
编译失败，均独立保留为调试记录，不计作项目缺陷证据。

本轮新增 36 项测试：克洛琳德 23 项、条件判断 9 项、治疗上下文 3 项、
阿蕾奇诺真实修饰器生命周期 1 项。另修正前一批两项保留旧行为的断言。
覆盖当前真实资源、实际注册处理器、客户端修饰器添加／移除消息、被治疗者倍率隔离、
旧实例延迟移除，以及 100 次并发外部治疗。

**全量 726 项测试全部通过，0 项跳过、0 项失败、0 项错误；`gradle test jar` 构建成功。**
使用 Java 17／Gradle 8.5、真实资源只读挂载和独立临时 Mongo，包含两项既有 Morphia 保存读回测试。
Spotless 仅格式化本轮四个较小的生产文件，没有对大型现有文件做全面格式改写。
