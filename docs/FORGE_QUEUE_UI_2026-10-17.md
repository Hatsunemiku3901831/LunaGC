# 锻造界面队列 0/0 与启动回包

## 原因

游戏截图中的锻造队列为 `0/0`。当前客户端打开锻造页时发送空请求 `26968`；
旧服务端将 `ForgeGetQueueDataReq` 保留为负数占位，处理器因此没有注册。
运行日志中也记录了这条未处理请求。

登录时的 `ForgeDataNotify` 更新配方和队列缓存；锻造页通过独立查询回包读取队列上限。
未收到查询回包时，页面上限保持 0，开始按钮在发送锻造请求之前就被队列容量检查拦截。

另有一处相连的适配缺口：`ForgeStartRsp` 使用负数占位包号，正式会话会丢弃它，
其错误码字段也仍为旧标签。成功后的队列通知不能替代失败回包与启动完成通知。

## 修复

| 消息 | 7.1 包号 | 字段 |
| --- | --- | --- |
| ForgeGetQueueDataReq | 26968 | 空消息 |
| ForgeGetQueueDataRsp | 6800 | 队列上限 7、队列映射 5、错误码 14，沿用已核对定义 |
| ForgeStartReq | 21223 | 配方 2、数量 6、协助角色 8，沿用已有定义 |
| ForgeStartRsp | 7643 | 错误码 8 |

恢复查询处理器的注册，并修正启动回包包号与错误码标签。
继续使用已有队列上限规则：冒险等阶不足 5 时为 1，5–9 为 2，10–14 为 3，15 起为 4。
查询返回已付费队列及当前进度，不产生扣费或保存。

## 客户端依据

只读核对用户提供的客户端，YuanShen.exe SHA-256：
`7f89938da606c1281659607d464702cddb9a09a7d4320a196630f60a811ec38e`。

- 打开页面调用 `0x14b161720`，类型信息单元 `0x1457b76a8` 对应类型 34384；
  其包号返回函数 `0x147f99ac0` 返回 26968。
- 队列回包解析器 `0x14b21f7a0` 读取上限标签 7；页面接收函数 `0x147f34860`
  将上限写到页面 `+0x2d4`，开始按钮在 `0x147f41805` 使用它检查容量。
- 启动回包类型 33210 的包号返回函数 `0x14ae1a450` 返回 7643；
  解析器 `0x14ae1a2f0` 将标签 8 读取到唯一的 int32 字段 `+0x18`。
  接收函数 `0x14b165b10` 在成功时发布锻造事件 `0x247`，页面事件表进入刷新函数。

原始反汇编、元数据引用与哈希校验位于 `debug/forge-ui-20261017/`。
