# 密码重置、令牌撤销与重置后的登录

## 来源与复现

参考 AstaPS 固定提交 `7cc148d1f752a43d4b9146b3b73f26875902546f`
的 `AccountPasswordResetService` 和账号命令：先排空已接收写入，
同步修改密码并撤销两类令牌，确认后再请求在线会话退出。

本地旧命令会先踢人、异步保存密码并立即报告完成，原有令牌未清除。
默认密码和宽松 session／combo 路径还会允许旧凭据重新登录。
9 项重置复现中 7 项断言失败，28 项认证检查中 21 项断言失败，错误与跳过均为零。

## 命令与保存

仍使用 `account resetpass <username> <password>`，仍要求
`EXPERIMENTAL_RealPassword=true`，并保持原有控制台／GM HTTP 入口限制。
命令将密码转换为 BCrypt，再调用确认保存服务；失败会传回调用方，不报告重置完成。

1. 固定调用时的账号 Datastore，暂停新的正式写入准入，等待已接收写入完成，默认最多 30 秒。
2. 保留原账号 ID 和副本版本检查；过时、已删除、未建档或来自其他 Datastore 的对象会拒绝。
3. 将新密码、删除 `token` 与 `sessionKey`、`passwordRequired=true` 及新保存版本
   放进同一份 Mongo 条件替换中，不通过无条件字段更新绕过账号版本保护。
4. 写入得到确认后才发布本次凭据到内存，再请求该账号在线会话退出并报告完成。

没有同进程游戏服务器时仍可执行离线重置。
写入失败不会先踢人；等待超时会释放维护准入，保留原凭据。
本进程的正式数据库写入线程不能在自身写入中等待排空，以免等待自己的完成。
该维护屏障是全局操作，持有期间会短暂拒绝其他账号的新正式写入。

## 重置后的认证

`passwordRequired` 是账号字段，由成功重置写入；旧档缺少该字段时按 `false` 读取。
未执行重置的账号保留原有本地便利登录策略，没有批量改变已有账号。

执行重置的账号：

- 默认密码入口校验新密码，不能通过修改全局密码模式重新启用任意密码登录。
  标记为加密的密码会解密后验证；解密失败、空请求或错误密码不签发令牌。
- 国服密码入口继续检查密码；当前没有真实短信校验的手机号入口不再绕过密码。
- 注册令牌、国服 stoken 恢复及 combo 入口只接受当前非空 session key，
  不能把旧值或缺失值重新写回并接纳。
- 游戏令牌与内部 Dispatch 校验在登录令牌被清除后返回失败，不再因空值抛空指针。
- 正确的新密码可以生成新的 session key，交换 combo token，再通过游戏令牌校验。

实验密码入口也补齐了缺失密码的拒绝，以及新账号初始密码与创建的确认插入，
避免先使用尚未创建成功的对象或在创建后另行异步写入密码。

## 结果不明与恢复

密码重置复用账号保存凭证，保留本次确切文档和条件。
发生写入前失败、实际提交后确认丢失或原替换晚到时：

- 识别本次写入已提交，才将新密码和清空的令牌发布到原内存副本。
- 用元数据更新使尚未提交的原替换失效时，不将其当作密码已经重置。
- 其他副本已更新或重置时，旧尝试拒绝覆盖，不采纳其他副本的版本。
- 普通保存会先核对不明的重置；已提交的重置不能被该对象的旧凭据写回。
- 三种令牌生成都会先核对不明写入，再分配新令牌，避免确认重置时把刚生成的令牌清空。

命令收到错误时不代表数据库一定未修改。例如写入成功但确认丢失，
数据库可能已经要求新密码；应核对状态或重新读取后重试，不能按错误消息假定旧密码仍有效。
这类错误没有触发“已确认重置后踢人”的完成动作。
