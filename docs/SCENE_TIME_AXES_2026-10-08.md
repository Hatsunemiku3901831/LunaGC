## 已实现

`InitTimeAxis` 保留 Java 整数数组和小数数组入口，Lua 使用原始表入口，检查连续索引和数值类型。
Lua 参数在转换为 Java 数组前读取，避免 LuaJ 用首项选择数组重载、截断后续小数。
时间点是从启动开始计算的绝对秒数，
所有时间点按原顺序触发；`param1` 从 1 开始，`source` 和 Lua 使用的 `source_name` 一起填写。
循环的周期取最后一个时间点，下一周期重新从序号 1 开始。
零秒和相同时间点保留全部事件；空数组、负数、降序、非有限数和零周期循环返回失败，保留已有合法时间轴。

登记键由组 ID 和名称组成。Lua 的 `EndTimeAxis` 只停止当前组；
兼容没有组参数的 Java 停止入口。替换时取消旧实例，旧实例完成清理不能移除新实例。
一次执行完毕移除登记；组卸载和场景销毁取消剩余时间轴，销毁后拒绝重新初始化。

全进程共用两个守护定时线程，构造时间轴不会创建专属线程；取消时立即移除定时队列中的任务。
定时线程只投递事件，实际 Lua 继续使用场景脚本执行器及已有原素烘炉生命周期校验。
每个时间轴等待当前回调完成后再安排下一个时间点，保留绝对计时与事件顺序，慢回调不会不断堆积本时间轴的事件。

停止会取消等待中的任务，并在 Lua 执行前核对登记实例。已经开始执行的 Lua 回调允许完成，
停止不会强制中断脚本。组卸载与正在执行的回调之间的完整隔离、全部场景传送锁顺序和缓存生命周期仍需继续适配。
