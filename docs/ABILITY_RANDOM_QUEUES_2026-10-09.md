# 条件随机队列

当前角色资源有 4 处 `RandomAction`：恰斯卡 3 处、流浪者 1 处，抽选次数均为 1。
固定参考库 AstaPS、LunaGC 7.1、HunkyMeow 没有对应处理器。
本批结合资源字段、客户端配置类型及
[固定 MIT 版本 gcsim 的流浪者实现](https://github.com/genshinsim/gcsim/blob/caf738dc807a646e2eee7e7b572f225dd6deb510/internal/characters/wanderer/asc.go)
接入现有的单组抽选路径。

## 依据与边界

- 客户端配置类型 `BHENLPCGNDF`（48228）持有队列和整数次数，
  组类型 `GFDIFMMPJMF`（67174）持有动作及条件数组。
  当前可读资源和混淆字段相互对应；类型与序列化代码只能证明配置形状，不能证明完整抽样算法。
- gcsim 固定 MIT 提交 `caf738dc807a646e2eee7e7b572f225dd6deb510` 的流浪者 C4
  从尚未取得的元素效果中均匀抽取一种，选中后从候选集合移除。
  本批据此实现“先过滤条件，再从合格组均匀选一组”。这不是对客户端通用算法的完整证明。
- [同一固定版本的恰斯卡实现](https://github.com/genshinsim/gcsim/blob/caf738dc807a646e2eee7e7b572f225dd6deb510/internal/characters/chasca/aimed.go)
  还涉及跨弹丸池与池重置，队伍重复元素也会影响池。
  本批没有从局部队列推断完整恰斯卡弹丸排序、重复元素权重或重置时机。
- gcsim 当前版本已改为 AGPL，本批参考的是上述固定 MIT 版本；未直接复制 Go 实现。
  固定参考源码与许可证保存在忽略的证据目录。

## 接入行为

- 保存队列、组条件和有序子动作，支持 `GJKEHHFNGLP`、`AHHFBGACEJF`、
  `EBOIAJJCFAG`、`FMBINFHJBGG` 别名；明文字段在两种 JSON 顺序下都优先。
- 次数按整数读取，拒绝把小数、字符串、布尔、数组或溢出值截断为 1。
  缺失次数默认零，零次、空队列与没有合格组均没有副作用。
  多次抽选语义尚未证明，次数大于 1 的父动作不执行且不由服务端接管。
- 父条件先检查，组条件根据实际调用目标筛选；选中组逐个执行子动作。
  子动作分别检查自身条件、目标和生命周期，参数写入可供后续治疗读取。
- 组子动作纳入本地 ID 登记。完整可识别的所有组经过验证后，
  单组随机树可参与周期、状态回调和已接管树的重复回调抑制。
  即使某组不满足条件，未知的条件或子动作仍阻止整棵树接管。
- 原生回调和嵌套重复沿用已有执行额度与深度限制。
  没有扩大盲场景推测链的动作权限或顶层初始化范围。

原生未知谓词沿用现有回退行为；严格服务端树拒绝未知谓词。
真实客户端的调用载荷、子动作 wire ID 顺序和双方抽选一致性仍待验证。
当前自动化测试证明内部登记与服务端归属，没有替代这些客户端证据。
本批也没有完成丽莎 `randomInRange`、完整元素球／子弹／特效链或全部角色玩法。
