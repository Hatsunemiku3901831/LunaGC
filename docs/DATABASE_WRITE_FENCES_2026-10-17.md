# 单次操作与派生写入的完成等待

## 用途与失败对照

跨服撤销登录时，需要等待相关登录阶段和它已经派生的写入结束。
直接等待整个数据库空闲，会把无关写入也算进去；如果等待者本身正在处理另一项数据库操作，
还可能等待自己。它不能直接用于远端密码重置的逐服确认。

本批先建立 `DatabaseWriteFence`。最初用现有全局 `awaitIdle` 包装该接口，
两项契约检查分别以“无关写入导致等待超时”和“等待者被当作自己的待完成工作”失败。
随后改为按操作传播计数，保留该失败包装器与原测试作为对照。

## 实现

- 一个 Fence 运行一次操作，返回原结果或抛出原异常。
  `await` 等待该操作及其已经接收的派生写入结束；超时不会取消写入。
- `DatabaseWriteBarrier` 的接收凭证携带当前 Fence 集合。
  数据库队列的工作线程和队满时的调用者执行都继承它，嵌套的直接写入、子任务和孙任务仍属于原操作。
  退出时恢复线程上下文，后续无关任务不加入旧 Fence。
- 同一对象、同一目标库的快照合并时，后来的 Fence 加入已有任务。
  实际写入执行时还会把这些 Fence 传给它的子任务，防止合并调用过早完成。
- 快照任务开始后解除合并登记；完成时核对登记对象的身份，
  避免旧任务结束删除同一对象后来建立的新登记。
  取消、拒绝和异常路径均释放已接收的引用，释放及完成回调在登记锁外执行。
- `isDrained` 和 `whenDrained` 供生命周期登记清理使用。
  回调在完成线程执行，其后新发起的工作不属于已经完成的阶段。
  操作不能在自己的 Fence 中等待自己，可以等待其他已完成阶段。

全局维护仍负责冻结外部接收和排空所有已接收写入；Fence 提供指定操作的等待范围。
“已经结束”包括失败和取消，不代表数据已经成功持久化；业务仍需检查自己的保存凭据和结果。

## 验证

- 新增 15 项检查：无关写入隔离、调用者执行、嵌套 Fence、子／孙任务、
  合并快照及其派生工作、独立调用者、旧任务结束、强制取消、拒绝、失败、回调、上下文和中断。
- 队列与屏障专项四套、35 项通过；扩大回归覆盖此前账号和经济事务的相关集合，
  79 套、2,434 项通过，失败、错误和跳过均为零。
- 2,711 份 Java 主代码和测试文件匹配构建副本（允许换行差异），应用类匹配编译输出。
  类改动仅属于本批三个生产源码，新增三个类文件，默认资源保持原值。
  资源子模块、外部开发资源和九个参考库保持原固定提交且工作区干净。
- 第一次扩展编译因新内部类与既有统计记录同名而失败，没有执行测试；改名后继续验证。
