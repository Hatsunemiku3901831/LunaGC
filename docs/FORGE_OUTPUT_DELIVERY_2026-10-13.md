# 锻造实际领取与确认保存

本批在已确认的锻造结果协议之上，修复实际领取未检查入包结果、背包满时清队列、
多个武器只生成一件、领取重入以及失败后重复发放的问题。
固定 AstaPS 的对应路径仍采用直接发放和清队列；本项目依据实际库存与故障测试补齐确认流程。

## 领取

- 检查队列和资源、完成次数、产物数量、背包容量及时间／数量范围。
  未完成、无配方、无产物、损坏队列均返回明确错误。
- 普通材料按实际数量检查库存增量；每件武器创建独立实例，检查入包对象和 GUID。
  同步确认实际保存的物品，回包数量表示此次新增量，不把已有材料栈总量当作产物数量。
- 部分领取保留未完成单位并准确推进开始时间；完全领取移除队列并更新队列 ID 通知。
- 背包满时保留原来的完成产物，之后可以再次领取。

## 插件与重入

在调用 `PlayerForgeItemEvent` 之前为队列设置内存预约，阻止插件重入领取、取消或启动。
保留插件调整产物的能力；重新检查全部输出再发放。
事件实现 `Cancellable`，使既有取消分支能正常生效。
取消、空产物、产物不合法或容量不足时释放尚未保存的预约，返回失败并保留可领取队列。

插件输出必须是新的物品对象：不能带已有 GUID、数据库 ID 或所有者，也不能多次复用同一对象。
这避免把旧数据库物品重新写成新产物。多武器按独立对象逐件调用事件。
未知操作和损坏请求也返回类型正确的失败回包。

## 确认状态

队列新增持久化 `outputState` 与预约数量：0 可用、1 预约、2 已发放待最终确认。

1. 同步保存领取预约。
2. 实际发放全部产物，核对库存增量和物品身份，并逐件同步确认保存。
3. 扣除队列内已领取单位，推进任务进度并同步确认玩家保存。
4. 移除或开放剩余队列，确认保存后返回成功。

确认失败或部分发放后，队列保留待核对状态，阻止重发、取消和新的锻造启动。
最终清理保存失败也恢复内存待核对状态；完全完成的队列必要时重新放回原位置。
旧 Mongo 队列缺少字段时默认为可用；待核对状态重新载入后继续阻止重复领取。
跨文档写入尚未实现事务或自动恢复，需要人工核对不确定发放；本批没有自动补发或清除预约。

## 冒险手册与纪行

通过现有 BattlePassSystem 桥接，成功发放后按加工单位数触发 `TRIGGER_DO_FORGE`。
按实际已发放武器的星级与件数触发 `TRIGGER_FORGE_WEAPON`，保留手册资源过滤。
材料数量不等于加工单位数，取消或尚未完成发放不会推进进度。

真实资源验证使用配方 13001、武器 11406 及手册目标 60016／60058：
两次领取四星武器可分别完成普通锻造与两件四星锻造目标。
这证明上述资源与服务端事件路径，全部配方及游戏界面仍需进一步验证。
