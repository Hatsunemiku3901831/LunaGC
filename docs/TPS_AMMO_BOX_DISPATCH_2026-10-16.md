## 分配规则

1. 计算总份数，先转为 float 再截断，范围为 1–100。
2. 从能力来源实体读取各组权重，按配置顺序每次给正权重组分配一份，
   扣一份权重；轮流继续，直到总份数用完或指定权重耗尽。
3. 有剩余额度时，读取自适应权重，取其与剩余额度的较小值。
4. 按接收角色的装备顺序，仅选择 `wearSlotType == 1` 的主武器，
   为每件武器找到首个类型匹配且非空的组，再轮流分配自适应份数。

两把同类型主武器保留两次组出现；手雷槽不参与自适应选择。
指定的空组和满池仍消耗本次份数，满池份数不会重新转给其他弹药池。
原生主武器筛选依据 `GDLKDBPFDDF`（`0x14f9e4200`），
武器类型依据 `OGCDKJDMJHA`（`0x14f9e4080`）。
本地内部动作按组数组顺序编号，并继续后续根动作的编号；当前客户端实发编号仍需实机核对。

## 服务端约束与去重

- 接收者必须是能力所属玩家当前登记、存活并已装备 TPS 武器的角色。
  每次写入前复核来源实体和已安装能力；来源权重与接收者全局值分开读取。
- 当前组支持明确池、无额外倍率的 `TPSSupplyAmmo`，以及空组。
  不认识的动作、选择器、组类型、条件或异常配置拒绝整个父动作。
- 先校验完整选中计划。未选择的 1004 叶子不会阻止有效组；
  选中的池或数量无效时，整次发放不写入、不保存、不发通知。
- 通过预检查后，先在当前效果实例中记录本次领取，再冻结并确认保存完整发放计划。
  同一叶子的多次计划出现保留多次补给，重复 ADD、REMOVED、父动作或叶子确认不能重复领取。
- 移除发奖只由实际移除入口驱动，提前发来的父动作确认不发奖。
  另一次冷却清理遍历不执行弹药箱；未选分支的客户端叶子确认也被拦截。
- 存档抛错后，本次已开始的实例不重放。完整计划、阶段与总量现会持久化，
  支持[按操作 ID 核对、恢复和取消](TPS_SUPPLY_RECOVERY_2026-10-16.md)。
  箱子跨重生周期的领取身份及多服务进程并发所有权仍需接入。

原有弹药池容量和增量通知继续使用[补给条件](TPS_SUPPLY_CONDITIONS_2026-10-15.md)
及[补给动作](TPS_AMMUNITION_SUPPLY_2026-10-15.md)的实现。
未新增 1004 池，也未据此确认容量配件、补给倍率、伤害或弹道。
