## 场景与角色

当前资源的 7 个场景指定旅行者 10000134／10000135，最多一名角色：
51334、51336、51341、51342、51343、51344、51345。
进入时依据玩家旅行者性别，从有效试用资源中选择最低 ID，使用资源的等级与装备模板。
自定义配置先核对实际角色 ID、等级及装备参数；缺失或无效资源会在移除原场景前拒绝进入。

TPS 队伍独立于永久队伍、多人队伍、临时副本队伍与任务试用队伍。
专用旅行者只在本次场景中借用，不能通过编辑队伍替换为永久角色。
退出时清理 TPS 武器和占位武器实体，删除客户端借用角色，并恢复原队伍和选中位置。
再次移除旧场景中的同一玩家对象不会破坏新场景队伍。

同一角色的永久版和任务试用版共存时，场景按当前队伍解析角色实例。
任务试用角色在 TPS 内获得或撤销时，不会替换正在使用的 TPS 角色。
多人场景按玩家分别选择性别和配装，不共用一个副本试用角色。

登录发生在创建场景队伍之后，`AvatarDataNotify` 会包含借用角色、临时 GUID 和正确的选中 GUID。
在线进入则先完成装备和属性初始化，再发送角色增加与队伍通知，避免先发送未知角色的技能或属性更新。

## 配装与保存

首次进入且没有有效旧配装时，发放一件初始武器 224001。
已有配装会移除空值、重复、未持有武器及槽位超额部分，沿用两把枪和一个投掷武器的限制。
武器仍遵循库存唯一性和容量检查；无法发放时记录警告，并保留首次初始化状态供重试。

新增 `tpsLoadoutInitialized`，区分尚未初始化与主动卸下全部武器。
主动空配装在重进和 Mongo 保存读回后仍保持为空，不会再次强制装备初始武器。
队伍仅保存进入前的选中位置 `tpsPreviousIndex`，支持在该模式中断线重连后退出恢复。
角色对象、场景引用和场景队伍不写入 Mongo；离开时清除位置备份。

默认试用配置按试用 ID 回退。
存在其他自定义条目不会使未覆盖角色失去默认参数、技能模板或初始武器。

## 普通副本的试用角色保护

副本分别记录每个玩家由该副本新增的试用 ID 和角色 GUID。
退出只移除匹配的借用实例，保留进入前已有的任务试用角色。
同一试用 ID 后来被新的任务实例替换时，旧副本退出也不会删除它。
一个玩家退出不会清除其他玩家的撤销记录；重复退出可以安全处理。

补齐资源中四个 TPS 副本类型的解码，并处理空类型与空活动玩法类型。
只有上述 7 个明确指定专用旅行者的场景会切换 TPS 队伍，
没有据副本名称将其余 TPS 防御或佣兵场景强制套用同一队伍。
