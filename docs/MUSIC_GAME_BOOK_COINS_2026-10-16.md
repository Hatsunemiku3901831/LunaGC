# 千音币与共享扣费检查

## 本批范围

接入资源中的千音币：物品 `207`，类型 `ITEM_VIRTUAL`，对应玩家属性
`PROP_PLAYER_MUSIC_GAME_BOOK_COIN = 10058`。

- 发放写入玩家余额并发送属性通知，不创建普通背包物品。
- 余额随现有玩家确认保存入口持久化，可从 Mongo 冷读恢复。
- 单笔扣费及数组、Iterable 两种批量扣费都读取该余额。
- 公共物品数量查询正确读取虚拟余额，同时覆盖既有原石、摩拉、创世结晶与洞天宝钱。
- 千音币加减使用整数边界检查；负数单笔费用被拒绝，零费用保持可用。

批量扣费在扣除前只遍历输入一次，先合并同物品费用，再检查全部余额。
这修复了重复费用各自通过检查后才发现不足、单次 Iterable 第二遍漏扣、
负数费用以及乘法／合计溢出问题。资源中的零数量占位项继续被忽略。
该检查不提供多文档事务，也不保证扣费途中持久化或插件异常后的完整回滚。

余额函数 `0x14b504fd0` 中，`0x14b5059e8` 的相对跳转表以物品 ID 减 `171` 索引：
物品 `207` 的第 `36` 项落至 `0x14b5055bf`，随后在 `0x14b5055e6` 载入 `10058`，
并调用玩家属性读取函数 `0x149573820`。后面的减 `179` 跳转表属于另一个回退路径。

这是本地静态核对，未运行客户端；radare2 连接中断后使用重新校验输入的只读解码和反汇编。
