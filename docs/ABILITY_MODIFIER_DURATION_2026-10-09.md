# 服务端临时状态的持续时间与结束动作

对照固定 AstaPS 和 LunaGC 7.1 的状态登记、属性撤销及回调路径，补齐资源 `duration` 和 `onRemoved`。
参考库同样缺少通用到期处理；本实现复用已有实体 tick、属性层和生命周期检查。

## 当前行为

- 服务端创建而尚未获得客户端确认的状态按资源持续时间到期，撤销该实例的属性和周期治疗。
- 客户端确认后，持续时间与移除继续由现有客户端链管理；服务端请求的结束动作不在确认时重复执行。
- 周期动作创建的子状态保留初始化／结束动作归属；多实例逐个确认，未确认实例继续保留属性和到期计时。
- 这些子状态的客户端移除在注销后执行结束动作，同一实例只执行一次；普通客户端状态保留原有重新应用行为。
- 多实例分别结束；旧客户端实例不阻止新的服务端实例到期，旧计时器不会删除替换后的状态。
- 结束动作在属性撤销后按资源顺序执行，检查目标与条件，支持创建后续状态。
- 全队结束动作分发到各队伍实体，同一个实体重复出现时只执行一次。
- 显式移除也执行服务端实例的结束动作，包括持续时间为零的状态。
- 动态持续时间晚到时保留原始登记时间；首次有效时长确定后固定该实例的截止时间。
- 周期治疗先处理截止时刻允许的最后一次治疗，再执行到期移除和结束动作。
- 实体生命周期失效时取消计时和旧结束动作；没有计时的实体快速返回。

## 继续适配的范围

已支持的混合周期动作及子状态交接见 [周期治疗](ABILITY_PERIODIC_HEALING_2026-10-09.md)，
本页上方的 1478 项为第三十九批验证；后续状态链的全量与最终相关回归记录在该文档。
带上限的刷新型多实例已支持计时器代次替换，旧截止时间和并发中的旧计时器均不能删除新代次，
具体模式与客户端交接边界见 [堆叠与刷新](ABILITY_MODIFIER_STACKING_2026-10-09.md)。
客户端持续时间／耐久度变更、扩展堆叠／刷新规则、隐式 Default 计时、扩展结束字段和未知目标仍待接入。
结束动作复用已有处理器，尚未实现的动作类型及需要客户端载荷的行为仍需适配。
本批没有验收游戏内完整施法、视觉效果、任务／奖励或客户端移除时序。
日常服务尚未切换，本批没有提交或推送；商城 SDK、其他技能、历史活动和千星奇域继续推进。
