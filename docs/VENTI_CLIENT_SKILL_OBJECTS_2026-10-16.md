# 温迪客户端技能对象与旧副本清理

参考 AstaPS 固定提交 `7cc148d1f752a43d4b9146b3b73f26875902546f` 的
`VentiSkillObjHelper`、创建入口及清理调用，核对本地仍会为温迪的角色根节点
创建另一份服务端 `EntityGadget`，客户端创建通知也没有清理对应旧副本。

当前 `GadgetExcelConfigData` 中四个对象为：

| 编号 | 资源名称 | 类型 |
| --- | --- | --- |
| 41022001 | Hurricane_Arrow | Bullet |
| 41022002 | Venti_WindBlade | Field |
| 41022003 | Venti_WindBlade_Land | Field |
| 41022014 | Venti_WindField | AirflowField |

当前 `Avatar_Venti_WindBlade` 与 `Avatar_Venti_Hurricane` 的创建动作指向这些对象。

## 实现

- 将温迪四类对象与伊涅芙七类对象的角色／编号对应关系放入 `ClientSkillObjects`。
  已确认由客户端创建的角色根节点不再生成额外的服务端副本。
- 客户端对象登记后，清理该发送者实例的同类服务端旧副本；其他角色和怪物的服务端创建路径保留。
- 共用逐对象归属检查、嵌套所有者、循环／深度保护与移除前的对象身份检查。
  同 UID 的另一玩家实例不因此取得对象归属。
- 伊涅芙继续单独管理中继与辅助物的成组生命周期。
  温迪的各个客户端效果保持独立，不互相排斥或被当成旧副本移除。
- 单个和批量服务端对象移除后，重新核对移除回调是否复用了编号。
  批量移除在所有回调结束后确定消失列表，避免后一个回调创建的替代对象被旧消失包隐藏。

角色自身的天赋条件、技能时序与创建位置仍由原有资源／动作路径处理，
没有因为对象编号命中而授予新天赋或主动开启客户端效果。
