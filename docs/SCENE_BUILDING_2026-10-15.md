# 大世界持久建造

## 使用

目标玩家必须是当前大世界的房主。命令权限为 `server.build`，指定其他玩家需要 `server.build.others`。
GM 的命令目录自动显示 `build`；也可在控制台使用目标 UID。

```text
build @10001 <gadgetId>
build @10001 <gadgetId> 1 2 3 0 45 0
build @10001 <gadgetId> temporary
build @10001 list
build @10001 remove <buildingId>
```

省略坐标时使用玩家当前位置和朝向。指定坐标支持已有的相对坐标语法。
默认保存，temporary 为当前场景的临时物体。成功后返回唯一建筑 ID，用于查询和删除。
删除立即在场景生效，不会关闭玩家连接。位置和朝向不会随机偏移。

## 来源与保存

参考 HunkyMeow `029f0a63d1b9eb786825110fc4fd14debf83e70a` 的 BuildCommand、SceneBuild 与 SceneBuildStorage。
公开实现的编号、临时模式和删除流程在本地重新实现，沿用本项目场景实体与权限机制。

保存到游戏数据库的 `scene_buildings` 集合，按房主 UID、场景 ID 读取。
建筑使用独立唯一 ID；临时实体 ID 不写入存档。
数据库确认成功后加入场景，存储失败不报告建造成功；已经写入但确认丢失的记录可在下次恢复时加载。
目录在场景生命周期内保持同一数据库目标，账号删除同时清理该玩家的建造记录。

进入大世界完成加载时恢复房主的物体。重复进入不重复生成。
场景达到实体上限时保留未生成的目录项，后续有空间时可以继续恢复或直接删除这些记录。
保存等待期间被其他物体填满时，也会保留新记录并提示等待恢复，不突破场景上限。
只删除当前管理的实体实例，不会误删复用了实体 ID 的其他物体。

允许现有资源中的普通 Gadget，载具使用已有载具系统，不通过此命令创建。
副本、尘歌壶及非房主玩家不使用本目录。该功能是 GM 放置，不提供客户端自由建造编辑器。

## 验证边界

单元检查覆盖保存和临时模式、唯一 ID、并发创建、坐标副本、存储失败、重复恢复、场景上限、
父世界所有权及即时删除。实际隔离 MongoDB 验证保存、冷加载、坐标、房主和场景筛选及删除隔离。
旧实现缺少管理入口，初始 16 项对照全部失败；确认丢失的恢复边界另有先失败后修复的证据。
保存期间场景变满的用例先观察到错误生成第二个物体，修复后只保留存档，腾出空间再恢复。

构建证据在忽略目录 `debug/aster-mid-20261011/batch219/`。
最终建造专项 26 项（25 项单元及 1 项真实 MongoDB）；相关 2,074 项／79 套件与启动／HTTP 2 项均通过。
9,942 处输入与编译环境一致，三个已有运行类变化、六个新增运行类，无删除或非预期变化。
编译类和 JAR 中字节一致，JAR SHA-256：`025f2bcd44d3c38708287f17e79071bbc4550207a5a474e33a53ac8592670547`。
没有向日常玩家数据库写入测试建筑，当前客户端的模型、碰撞与交互表现仍需游戏内验收。
