# 动物图鉴统计响应与客户端越界

## 实机错误定位

本机 7.1 客户端进入场景后弹出 `Specified argument was out of the range of valid values`。
调用栈包含 `DMABGCDJFPE.KPHHGEABHJM`、`DMABGCDJFPE.OOGMCAKFPLO`，
异常返回位置为 RVA `0xf66e44e`。当时新服务健康，服务端没有对应 Java 异常。

对当前客户端的只读检查确认：

- 类型 20894 `AOMOHMONLOJ` 的包号方法 `0x147f18f20` 返回 `20558`，
  对应 `QueryCodexMonsterBeKilledNumRsp`。
- 解析方法 `0x147f19240` 读取 ID 字段 14、两组统计字段 10／15，以及返回码字段 2。
- 处理方法 `0x14f66e070` 用同一个下标读取三组列表。
  字段 10 的列表不足时进入 `0x14f66e421` 异常分支，抛出后的返回位置与实机栈吻合。
- 字段 10 写入管理器偏移 `0x60` 的字典，字段 15 写入 `0x68` 的字典。
  图鉴 UI 方法 `0x1489c3dc0` 的 countType 分支将击杀／钓鱼通道交给前者、捕获通道交给后者；
  输入字段的类型也已核对为包含 NONE／KILL／FISH／CAPTURE 的图鉴计数枚举。

旧响应只添加图鉴 ID，填充两项计数的代码被注释，协议定义仍使用 50000／50001 占位编号。
只要响应包含已经解锁的图鉴，客户端就会访问缺失的统计位置。
参考 AstaPS 固定提交 `7cc148d1f752a43d4b9146b3b73f26875902546f` 中也存在相同缺口。

## 修复

| 字段 | 当前编号 | 类型 |
| --- | --- | --- |
| `codex_id_list` | 14 | repeated uint32 |
| `be_killed_num_list` | 10 | repeated uint32 |
| `be_captured_num_list` | 15 | repeated uint32 |
| `retcode` | 2 | int32 |

每个返回 ID 同时添加两项统计，包括明确的零值，保持三组数组长度与顺序一致。
请求中的重复 ID 保留对应位置；未解锁 ID 沿用现有过滤规则。
资源标为 CAPTURE 的记录进入捕获数组，其他现有记录进入原计数通道。
旧空值或负数在响应中按零处理，避免编码成巨大的无符号次数。

现有存档每条动物图鉴保存一个计数，另一通道以零返回；
历史上未记录的独立统计仍需另外适配。本次查询只读取进度。
