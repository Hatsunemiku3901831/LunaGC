# 角色死亡动画请求与编号：2026-10-12

## 参考与缺陷

参考 AstaPS 的[角色 GUID 对应修复](https://github.com/MeChen618/AstaPS/commit/504c6bb72448366a83322d8ffe50b284c3ec0d69)
及[编号测试](https://github.com/MeChen618/AstaPS/commit/79e5cfa1d5481ffffdc55bc639c7b3e817f80a86)。
上游在请求入口将当前角色的持久 GUID 转为场景实体编号；
本地原处理直接比较实体编号，带角色 GUID 的请求不能进入换人或全队死亡分支。

本地在队伍处理入口接受两种当前角色编号，保留既有请求解码、响应包号及响应内容。
这样也覆盖直接调用队伍入口的路径，既有实体编号请求继续工作。

## 接入行为

- 仅处理当前队伍、当前场景中已死亡的角色；角色 GUID 按完整 64 位比较。
- 零值、无关角色编号、其他队员、存活／已复活角色和旧场景角色不触发换人。
- 空队伍直接结束，避免调用会补建默认角色的 getter。
- 使用同一队伍快照选择活着的替补，进入现有场景登记流程。
- 全队死亡继续发布原死亡类型及击杀者；溺水沿用原不自动换人的流程。
- 正常换人后再次收到旧角色请求不会改变新角色。

响应仍使用原场景实体编号和技能值 0，未根据字段名猜测新的响应语义。
队伍快照用于本次处理；它不表示已经证明与所有并发切队、传送和复活操作的完整时序。
同一角色再次死亡后的旧 GUID 请求，单靠这两个编号也不能确定它属于哪一轮动画。
