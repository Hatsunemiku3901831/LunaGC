# 圣言自明机的异常萃取与制作恢复

此前移植参考系统时，为支付、发奖和保存确认中断保留了持久操作记录，
并禁止普通请求自动重复扣费。本次补上明确操作 ID 的查询、继续和取消入口。
不从参考库的调试包号、候选自动放弃或发奖猜测分支恢复经济操作。

## 使用

玩家须在线。可在 GM 命令页选择顶部目标 UID，也可在控制台明确填写：

```text
transmuter @10002 status
transmuter @10002 resume <operationId>
transmuter @10002 cancel <operationId>
```

权限为 `server.transmuter`，操作他人还需 `server.transmuter.others`。
命令已注册到现有命令目录，中英文说明随语言资源打包。

- `status` 只读显示当前排期、进度单位、萃取／制作次数、操作 ID、阶段、计划奖励，
  以及每笔材料的持久 ID、支付前数量、消耗数量和内存／存档现存数量。
  另外列出重塑候选及其阶段；不会打开道具、重置周期、扣费或发奖。
- `resume` 继续这一笔已预留操作。已扣除的材料不再扣；部分材料已扣除时，
  仅扣除其他仍等于原数量的材料。已经落库的奖励不再发放，完成后保存进度／次数并清除记录。
- `cancel` 只取消未扣费、未发奖的预留，不退款，不撤销已结算进度。
  取消不需要重建产物，因此背包满、产物资源缺失、旧记录没有强化约束，
  或待支付圣遗物后来被锁定，都不会单独阻止取消原封未动的预留。

修改操作必须携带当前完整操作 ID；缺少、过期或另一笔 ID 都不会选择任意待办来代替。
成功操作记录 UID、操作 ID 和动作到日志。数据库或状态检查失败时保留未确认记录并反馈原因。

## 核对和重试

1. 共用玩家背包锁，等待既有数据库写入完成；内存和已保存的操作、周期、进度／次数须一致。
2. 每笔成本按 Mongo ObjectId 定位，并同时检查内存和存档的归属、物品 ID、数量。
   数量只能等于支付前或支付后快照；已标记确认支付的阶段要求全部材料处于支付后状态。
3. 萃取奖励同样检查发放前／后数量、唯一堆叠、容量和堆叠上限。
   继续扣料将释放的材料槽可用于存放待发放的奖励。
4. 定向制作按预留 ObjectId 寻找真实产物，核对主／副属性和指定属性信息。
   缺少产物时使用原存档的 ID、词条和强化约束重建，最终结果不重新随机。
   新记录在支付前冻结强化约束；旧记录缺少该字段且产物未落库时，拒绝猜测其值。
5. 先确认材料，再确认奖励，最后保存原操作的进度／套装次数和完成阶段。
   最后的记录清除若确认失败，内存保留该记录；重新登录后按实际存档阶段继续核对。

恢复过程本身可以中断。每次重试都重新核对实际存档，不因上一次收到错误就假定没有扣费或发奖。
采用原操作的周期快照；其周期已经过期时，之后正常打开道具仍按原有逻辑更新周期。
没有修改周期设置，也不把旧周期操作改记为本周期的新一次制作。

该工具不提供强制清记录、无条件补偿、自动退款或覆盖已改变产物的选项。
如果材料／奖励在故障后发生过其他消费、发放或人工修改，应先结合操作日志核对；
仅凭当前数量不能重建所有外部操作历史。无法匹配快照时命令会停止。
重塑 RESERVED 阶段的支付核对与专用恢复仍在后续范围内，`status` 对它只作列举。

## 验证

最初 12 项用例失败，其中命令用例先因夹具没有初始化插件管理器失败；
补齐夹具后命令用例独立复现缺少入口，其他 11 项复现缺少核对 API。
实现后首轮 12 项通过。

随后三项检查先复现取消被产物重建条件误拦截；修复后 21 项通过。
另复现精确扣料腾位的检查失败。锁定材料的取消用例最初因夹具圣遗物未达资源最低等级，
未建立预留记录；将夹具设为实际允许的 +4 后，单独复现锁定条件误拦截，再补修复。
这些夹具故障未计作功能复现。
