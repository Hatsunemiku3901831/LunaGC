## 资源与装备

正式资源加载器新增三张表；物品表同时读取 TPS 武器。
当前本地资源提供 8 件武器、12 个配件、5 个弹药储备池。
武器按物品 ID 唯一持有，数量固定为 1；重复发放不会再次产生获得通知或获得历史。
TPS 背包容量沿用参考实现的 20 件，每个角色可穿戴两把枪和一个投掷武器。

角色穿戴与玩家 TPS 配装保存物品 ID，配件保存在对应武器上。
重登后由库存重建 GUID，场景实体与 GUID 不写入 Mongo。
缺少这些字段的旧文档可继续使用；库存中的重复武器会记录警告并跳过。

穿戴前验证整组 GUID、持有者、配置、重复项和槽位限制。
转移时同时处理永久角色与试用角色；卸下、删除或离开场景会清理旧武器实体。
配件必须属于实际持有的武器，重复、未知及其他武器的配件不会写入协议或词条。
客户端能力消息不能直接授予配件。

附加能力通过词条的 openConfig 加入角色，武器能力实例与下发编号保持一致。
只在当前角色初始化完成后下发武器能力；武器自身的初始化回复不会再次触发下发。
专用旅行者 134／135 使用 AetherShadow／LumineShadow 基础配置，
旧能力缓存缺少这两项时直接读取对应资源；空缓存会重新生成。
攻击模式技能和空天赋列表也补上读取兼容。

## 弹药保存与验证边界

弹药储备按资源配置 ID 保存，多个武器槽位可以共用同一储备。
省略值使用资源容量，明确的零会保留；负数及超过容量的旧值在读取时限制范围。
服务端补给和扣除均限制上下界，并使用 long 计算避免 int 加减溢出。

客户端扣除只接受当前角色或其当前武器的消息，要求处于玩家当前场景。
只允许已穿戴武器对应储备的非正变化量；整批校验通过后一次保存。
未知储备、无关实体、超额扣除和客户端自行增加弹药均不会改变存量。
拾取与补给须继续接入服务端事件，未直接信任客户端的 PICKED／SUPPLY 数值。

场景武器的 currentAmmunition、首次弹药通知和补给初始化目前沿用参考实现的储备表示。
弹匣、换弹与增量／绝对值通知的完整含义仍需实机消息核对。
本批不导入参考实现的强制无限弹药开关或固定按怪物生命百分比扣血逻辑。

当前资源中，雷枪 224002 声明槽位 201 和 202，储备表仅映射 201。
202 的含义尚未确认；代码不会将它借用为冰枪的储备池。
覆盖测试明确记录这项资源缺口，没有据此宣称所有槽位都已实现。

配件的最新字段 LDACNDBDKBA、IJFENBIJGLJ、AAAENHAPNLB 已补解析，
包括实际冰枪弹匣的解锁标志和射速参数。
资源中的负参数引用（例如 `-%1`）、全部词条参数应用与解锁条件仍待完整接入。

## 开发命令

目标玩家须在线，使用常规目标 UID 语法和命令权限：

```text
tps @10001 give
tps @10001 give 224001
tps @10001 wear 224001 224002 224004
tps @10001 wear
tps @10001 accessory
tps @10001 accessory 224506
tps @10001 refill
```

`give` 无 ID 时发放资源内全部武器；`wear` 无 ID 时卸下所有 TPS 武器。
`accessory` 是 GM 免费解锁操作，要求持有对应武器。
权限为 `server.tps`／`server.tps.others`。GM 物品目录新增 TPS 武器筛选。
这些命令用于开发验证，尚不构成完整游戏入口。
