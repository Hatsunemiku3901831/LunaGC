# 游戏服发起密码重置与结果确认

## 已复现的缺口

分离模式中，游戏服此前把密码重置作为普通账号替换发送：账号服写入后返回，
其他游戏服没有收到撤销通知。游戏服控制台的 `account resetpass` 还只查询本机账号集合，
无法找到仅存于账号服的用户名。两项独立进程失败对照均已执行。

## 当前流程

1. `account resetpass` 通过当前账号来源查询用户名；游戏服只接纳绑定远端来源的账号副本，
   本机用于编解码的 Mongo 集合不能充当远端账号来源。
2. 保存保护器使用专用 `reset` 操作发送账号原版本、完整替换文档和新的保存标记。
   账号服严格检查 ID、连续修订、新标记、密码登录策略及两类旧令牌的撤销。
3. 账号服在有上限的工作执行器中获取维护屏障，确认条件替换并撤销本机登录，释放屏障后，
   请求当次已认证游戏服逐个确认。全部确认完成才返回重置成功。
   取得维护屏障后再次检查原连接，尚未提交的旧连接请求不能在重连后继续提交。
4. 游戏服等待账号服时不占用本机全局维护屏障。它仍可处理撤销通知，
   排空已进入的登录阶段和派生写入，并处理关闭连接产生的本机写入。
5. 正常账号 RPC 默认等待 5 秒；重置与结果确认默认等待 65 秒，覆盖账号服最多 30 秒的维护等待、
   30 秒的逐服确认及传输时间。显式绑定的超时用于该副本的所有操作。
   账号服最多四个工作线程、64 个等待任务，接包线程不等待这些业务。

## 回复丢失及重试

同一个仍在内存中的绑定副本会保留未确定的重置尝试。
读取到相同保存标记后，还必须通过 `confirm-reset` 获取明确业务确认；
该操作核对确切的密码散列、密码登录策略、已撤销的令牌和原保存标记，再执行逐服确认。
仅仅看到 Mongo 中的保存标记不能将未完成的撤销解释为成功。

- 确认不重写密码，也不增加账号修订号。成功确认后才发布该副本中的新密码策略并清空旧令牌。
- 原文档尚未提交时，保存保护器以条件更新退役旧尝试；后来才执行的原条件替换不能覆盖后续状态。
- 当前行已前进、内容不符、缺少确认或原连接被替换时，旧尝试保持未确认或冲突状态，不能发布旧结果。
- 超时不等于账号服已取消业务，密码也可能已经写入。新一轮控制台重置是新操作，
  不等于恢复先前副本；进程重启后的业务记录恢复和持久幂等键仍需继续接入。

分离服务两端需要更新到支持该协议的版本；旧端缺少撤销确认时，请求会报告未完成。

## 验证范围

本批新增十五个独立进程用例和一项本机编解码库拒绝检查。
进程用例覆盖游戏服发起及控制台入口、逐服撤销、本机登录排空、关闭时写入、
已提交回复丢失、缺少确认后重试、四类账号内容不一致、行版本前进、迟到条件替换、
旧连接确认、过期副本、两个游戏服竞争及提交前断线。

测试使用实际 WebSocket 和独立 Mongo，KCP 隧道及场景为替身。
控制请求开始／回复时机的用例在测试执行器中调用同一生产处理函数，
普通入口用例调用默认生产处理器；没有用模拟处理器替代条件替换或撤销业务。

失败对照、最终回归和构建指纹保存在本地忽略目录 `debug/aster-mid-20261011/batch361`。
中间一次扩展运行的并发检查只等待账号写入，过早释放了游戏服阶段，
现已改为同时观察游戏服的失效标记；该次结果保留，不计为通过。

最终相关回归 22 套、484 项通过，失败、错误与跳过均为零，其中独立进程用例合计 25 项。
2,714 份 Java 主代码和测试文件匹配构建副本（允许换行差异）；应用类匹配编译输出，
类变动仅属于本批五份生产源码，没有类增加或删除，默认资源不变。
资源子模块、外部开发资源和九个参考库保持原固定提交且工作区干净。

## 后续范围

本批基于当次连接开放、已认证的游戏服集合，未提供网络分区下的成员租约、持久重置操作记录，
分布式账号删除／同 ID 重建、普通游戏或后台敏感操作的完整并发裁决和完整重连接管。
自定义认证或插件自行持有账号对象、阻塞接包线程的入口也需要单独核对。
本批没有启动原生游戏，此前用户反馈的客户端窗口错误仍未实机确认。
