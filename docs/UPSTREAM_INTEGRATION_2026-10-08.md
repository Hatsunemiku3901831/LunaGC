- `AvatarSkillData` 同时读取 `specialEnergyCostMax/Start`、旧明文字段及旧混淆字段。
- 重算角色属性时，特殊能量容量、起放阈值来自技能资源，当前值限制在容量范围内。
- 四种新资源名称映射到处理器：`ReviveSpecialEnergy`、`AddNyxValue`、`SetNyxValue`、`ChangeNyxValueMixin`。

### 后续接入：数据库写入可靠性

设计依据为 AstaPS `c4ae75e6c04f7f7333bea8763926ade8fda6d70a` 的四类有界队列，
以及 `bb2640a` 的重复保存合并；HunkyMeow 同样分开账号、物品和场景保存。

- 默认总计六个工作线程，四类队列容量分别为 1024、256、2048、1024。
- 队列满时提交者执行；关闭后的提交明确拒绝，异步读取的 future 也会结束，避免永久等待。
- 排队的同一对象与同一 Datastore 按身份合并；不同对象或不同 Datastore 即使相等也各自保存。
  开始写入前只清除该目标的合并标记，写入期间的新变化仍可排队。
- 保留对象锁、物品 count 为零时的删除保护，以及经济预约的 majority + journal 同步确认。
- 保存与删除物品使用相同的物品队列。Morphia 异常最终会被记录，失败次数可查询。
- 停机同时关闭四类队列，等待已接受任务，包括满载时在调用线程上执行的写入。
  正常停机不丢弃排队任务；显式强制关闭会取消排队的 future 并记录取消数。
- 四类队列的容量、线程数及停机等待时间可在 `databaseInfo.asyncWrites` 设置。

默认配置示例（旧 config.json 省略这一节时会使用默认值）：

```json
{
  "defaults": {"threads": 2, "capacity": 1024},
  "accounts": {"threads": 1, "capacity": 256},
  "items": {"threads": 2, "capacity": 2048},
  "groups": {"threads": 1, "capacity": 1024},
  "shutdownTimeoutSeconds": 30
}
```

数据库永久不可用时，写入仍可能失败；队列限制和错误观测并不等于离线持久化日志。
超过停机等待时间会报告尚未完成的写入，外部强制结束进程仍可能丢失这些未完成操作。
第 34 批进一步固定保存、重试和内置删除的提交目标，双实例验证见
[数据库写入目标](DATABASE_DATASTORE_SCOPE_2026-10-09.md)。
