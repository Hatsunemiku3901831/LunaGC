# 深秘降福三选一修复

2026-10-23 修复说明。本次按用户指定范围修复每间三选一「深秘降福」，使用本仓库 7.1 客户端对应的卡片与关卡资源。渊月祝福和地脉异常不在本次范围。部署与回归结果见 [验证记录](data/tower-blessing-validation-2026-10-23.json)。

## 深秘降福：每间三选一

旧实现只在入场包中固定发送 `[4,28,18]`，没有选卡处理器，选择不会成为服务端有效状态。

现在加载全部 36 张 `TowerBuffExcelConfigData`，按每间 `towerBuffConfigStrList` 的三个候选池及各项权重各抽一张。候选使用 UID、楼层、间号和国服每日刷新日生成；同日退出重进、重开本层或重新登录不会反复洗牌，国服 `Asia/Shanghai` 04:00 后未选卡的候选可刷新。已经选择的卡不会随日期改变。无效编号、非正权重或缺失能力不会进入候选。

作用期严格分开：

| 配置 | 行为 |
| --- | --- |
| `TOWER_BUFF_LASTING_FLOOR` | 保留到本层结束，后续各间可叠加相同卡片 |
| `TOWER_BUFF_LASTING_LEVEL` | 上下半共同生效，下一间不再应用 |
| `TOWER_BUFF_LASTING_IMMEDIATE` | 选择时对两队执行一次即时恢复，重复请求不再结算 |

只能在当前上半准备阶段选择当前候选。场景、楼层、间号、副本和稳定队伍身份必须吻合；开战后、下半、结算推进后、其他场景均拒绝新选择。重发同一选择为幂等成功，改选其他卡失败。

`TowerBlessingState` 随 `TowerData` 保存候选和每间选择；旧档缺失字段按空状态处理。新选队重开本层会清掉旧轮次选择。当前记录与全量响应同步已选有效卡、双队和半场，GUID 从稳定角色身份重新绑定。

## 效果与生命周期

每张有效卡有独立的服务端 buff UID 和属性来源，不经过食物按组覆盖及定时过期的逻辑。相同本层卡可累加；刷新和原生回调不会另加一层。上下半切队为新半场的全部角色安装效果，移除离队实体的旧来源。退出、换场景和新轮次均移除旧效果。

卡片属性取自 `BuffExcelConfigData` 指向的原始 Ability/modifier。暴击、攻击、防御、精通、能量恢复、生命等使用现有可移除属性层；生命比例条件随各角色 HP 更新。攻击类别、移动速度、动画状态与其他客户端能力通过原生 `ServerBuffChangeNotify` 安装。服务器 buff 回调按 UID 与角色单独路由，不混入普通技能的 modifier ID 空间，不接受同一 Ability 下未选择的兄弟 modifier。

击杀回血、施放爆发回血和击杀重置战技冷却由实际服务端事件触发。击杀归属追踪到角色及其投射物，重复死亡事件不再次回血；重置冷却遵循资源的 50% 几率、20 秒触发间隔及战技槽，保留爆发和后续未恢复的技能充能。爆发恢复使用当前资源的 `HMBEKPDBCEK` 回调别名，并去除同次成功消息的紧接重发。

选卡后重建本间入口检查点，包含立即回血或 HP% 改变后的状态。重试保留选择并恢复该检查点，不重新支付即时卡；重新进入同一未完成间也恢复入口状态。进入下一间保留前间消耗与本层卡，不重新满血满能。新楼层仍走既有的新层恢复链。

## 验证与实机边界

单元测试遍历全部 423 个关卡的候选池，验证作用期、日刷新、重复卡、存读档、属性叠加、生命条件、两队即时恢复、原生 UID 回调隔离、击杀与爆发回血、战技重置间隔，以及换半场和退出移除。独立 MongoDB 测试覆盖实际 Morphia 存读档；深渊、组状态、登录恢复、食物和技能冷却回归同时运行。

服务器测试不等于原生实战全部通过。仍需在运行本次 JAR 的真实客户端确认三张卡的展示、上下半与连续三间、退出继续和重试、属性面板，以及攻击类别、移动和动画相关卡片的实际战斗表现。

本机交付按 portable 流程更新，保留 `mongodata/`、`local/data/` 和本机配置；不部署 Docker/WSL，不推送远端。
