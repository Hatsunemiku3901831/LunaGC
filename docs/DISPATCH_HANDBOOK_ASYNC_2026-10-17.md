# 分离模式后台操作的异步执行

## 问题复现

接续[定向请求与异步回复接口](DISPATCH_PEER_REQUESTS_2026-10-17.md)，
核对本地及固定版本 AstaPS 的默认后台处理器。
本地账号刷新已读取远端当前状态，但 `GmTalkReq` 原先直接在 WebSocket 接包线程执行操作。
操作等待账号回复时，同一接包线程无法处理该回复，直到请求超时。

失败对照使用实际处理器、JSON／XOR 编解码和独立 Mongo：
单个接收执行器处理 GM 请求后，账号请求已经发出，但排在其后的账号回复无法处理，断言超时。
迁移到工作线程后，同一个接收执行器可以处理回复，GM 请求保留自己的响应标识。

## 当前处理方式

- 默认后台处理器在接包线程捕获回复上下文，完成在线玩家归属检查后，将操作交给执行器。
  默认最多四个工作线程，直接交付任务，不在执行器中排队；忙碌时返回关联的 `503` 结果。
  空闲线程 30 秒后回收，线程为守护线程。
- 广播到未持有目标在线玩家的游戏服时，不占用工作线程，也不返回其他玩家的结果。
  原有认证失败／玩家不存在时的静默行为保留。
- 同一 `DispatchClient` 中，同一玩家只允许一个后台操作正在执行。
  重叠请求返回 `503`，正常结束、执行器拒绝、上下文失效及异常路径均释放占用。
  不同玩家可以并行处理，避免把原先串行的同玩家操作改成并行修改背包或场景。
- 执行前重新检查连接代次、所属游戏服、当前 Dispatch 客户端、运行模式、
  游戏／账号 Datastore 和在线玩家对象。失效连接不执行；其他上下文变更返回关联的 `503`。
- 业务继续调用原有后台动作与当前账号认证；不使用旧缓存代替失败的认证。
  非法玩家编号和未知动作返回关联的 `400`，其他未完成操作返回 `500`。
  回复使用接包时捕获的原请求上下文。

新增 `DispatchReply.isCurrent()` 供延后工作做预检查。
它不代表账号已经授权，也不取消已经开始执行的业务。

## 验证

- 新增 16 项检查：默认处理器的嵌套账号查询、两名玩家反序收到账号回复、
  忙碌与拒绝后的重试、同玩家重叠操作及完成后重试、非本地玩家、失效客户端、非法输入，
  七类执行上下文变更，以及执行前密码重置不能使用旧缓存认证。
- 迁移过程中还用单项失败对照复现了同玩家两个任务同时被接收，随后补齐占用保护。
- 最终通信专项七套、145 项通过；相关回归 27 套、537 项通过，失败、错误与跳过均为零。
  早期通过记录使用尚未加入占用保护的中间版本，最终结果以 `flows-final` 和 `gate-final` 为准。
- 测试使用实际客户端／服务端处理器和独立 Mongo，字节传输及单接收线程由可控替身提供。
  需要控制任务开始时机的用例注入受控执行器；生产执行器不排队。
  嵌套认证的正向链路在校验账号后返回无效物品结果，没有执行实际奖励、传送或生成实体。
- 2,709 份 Java 主代码与测试文件匹配构建副本（允许换行差异），应用类匹配编译输出。
  相对上一构建，类改动只属于本批两个生产源码，没有新增类文件，默认资源不变。
  资源子模块、外部开发资源和九个参考库保持原固定提交且工作区干净。

失败对照、最终报告与构建指纹保存在本地忽略目录 `debug/aster-mid-20261011/batch358`。
