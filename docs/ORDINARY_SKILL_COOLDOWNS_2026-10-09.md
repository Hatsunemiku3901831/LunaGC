# 普通技能冷却接入

## 已接入

当前资源的九条 `ModifySkillCD` 天赋配置，按实际技能 ID 从资源基础冷却计算：

`(基础秒数 + 各天赋增量之和) × (1 + 各天赋比例之和)`

配置兼容导出字段 `__exp_healTag`，支持有限数字、带符号参数引用及单值包装。
仅无条件配置或 `talentFilter = All` 生效；缺失参数、非法值和未知条件不会修改冷却。
天赋变化只影响下一次使用，已开始的恢复队列保留当时实际时长。

`AvatarSkillStart` 再乘此次动作的释放倍率。导出字段 `BGNJBEPEJBO` 在此动作中
是释放倍率，在 `ModifyAvatarSkillCD` 中是剩余时长修改比例，两者分别读取。
显式规范字段优先于导出字段，不依赖 JSON 成员顺序。班尼特、万叶不同释放方式，
以及公子按持续时长计算的表达式，均保留资源中的倍率。
体力字段不用于冷却；活动开始动作中的 `cdDelta: true` 也不解释为增加一秒。

普通技能恢复记录归属玩家会话及角色对象，切场景替换角色实体后继续恢复。
使用 `PlayerTimeNotify` 同步的玩家时钟，暂停时不推进。每次消耗保存独立完整时长，
多次充能依次恢复；会话替换或玩家时钟回退清除旧记录。共享冷却继续走原共享组模块。

角色序列化、临时技能信息、主动次数同步和场景进入同步均携带完整恢复状态，
避免只更新最大次数时抹掉正在进行的冷却。协议保持现有 7.1 包号与字段，
`pass_cd_time` 和 `full_cd_time_list` 使用毫秒。

已核实的、按明确技能 ID 修改剩余时长的运行时动作计算为：

`剩余秒数 = max(0, (剩余秒数 + 增量) × (1 + 比例))`

修改仅作用于队首。清零一项恢复不会同时返还所有已消耗次数；延长冷却时补足
完整时长，避免无符号已流逝时长溢出。动作开始和剩余时长修改只记录服务端状态，
重同步时才发送状态，避免客户端本地动作再消耗一次。

## 覆盖范围

服务端实际执行开始动作时记录冷却。自主 `onAdded` 回调接入单次充能技能的开始，
此路径只记冷却；额外体力消耗、特殊能量和任务事件沿用客户端请求的原路径。
同一恢复尚未结束时重复回调不会增加或延长单次冷却。

自主回调暂不消费多次充能技能：需要补齐客户端实例身份和确认消息的去重，
以免一次使用被算成两次。明确执行的开始动作与多次恢复队列已接入、已检查。
按槽位修改、`cdMin`、绝对时长字段 `FBGLBGFMOHC` 的分支拒绝按 ID 增量路径处理。
145 个运行时动作仍需逐个核对，不将这些分支记为全部还原。

当前客户端的构造、计算、消费和恢复路径提供了限定地址证据；
[继承关系记录](CLIENT_INHERITANCE_AND_SKILL_COOLDOWNS_2026-10-09.md) 中保留具体地址。
公开参考库的固定版本只有 `ModifySkillCD` 声明，不能提供完整执行逻辑。
