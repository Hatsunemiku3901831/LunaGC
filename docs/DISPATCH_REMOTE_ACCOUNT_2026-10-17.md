# 远端账号副本的版本写入

## 复现

在请求匹配和 JSON 字面值修复之后，继续核对分离服务的账号保存路径。
`GAME_ONLY` 查询和游戏令牌校验返回的账号经过 JSON 反序列化，原先没有已确认的保存绑定；
调用保存会被版本保护拒绝。首轮 9 项检查中 5 项断言失败，4 项保护对照通过。

## 保存绑定

账号查询与成功的游戏令牌校验现在为返回副本绑定原 `DispatchClient`。
查询还会核对账号 ID；令牌校验保留账号与本次令牌检查。

- 账号 ID、读取版本、原连接及本地编解码 Datastore 在绑定后固定。
  更换全局客户端不会把旧副本交给新连接，改变保存目标 Datastore 会被拒绝。
- 本地 Datastore 只用于原有映射和来源核对，远端账号写入经过原连接回到账号服务。
  同 ID 的本地账号文档不会被修改。
- 同步和排队保存均使用现有 `AccountSaveGuard`。普通 JSON 复制没有自动写权限，
  已有绑定也不能再次安装。新连接需要重新读取副本；本次没有完成缓存刷新或重连接管。

## 内部协议

新增内部请求 `13`、响应 `14`，沿用请求 UUID、预期包号和现有连接鉴权。
账号服务在处理请求时固定自身账号 Datastore，只提供：

| 操作 | 行为 |
| --- | --- |
| `read` | 读取指定账号的 ID 与保存版本，供未知结果核对 |
| `replace` | 以准确 ID、旧版本和写入标识为条件替换原文档 |
| `advance` | 只推进保存元数据，使迟到的旧写入失去匹配条件 |

服务端拒绝无版本条件、额外筛选操作、不同 ID、非法版本类型／UUID、跳版本、
复用写入标识、额外字段以及插入请求。替换没有 upsert，不会重新创建删除的账号。
合法旧档使用原有空版本条件，首次成功保存后带版本。
数据库仍使用主节点、majority 与 journal 确认，写入纳入既有进程内维护屏障。

文档、条件和保存元数据以 BSON Extended JSON 字符串传输，保留 int64 类型及精度。
接近 int64 上限的版本仍准确，编号溢出会在发包前失败。
分离部署需同时升级两端；这些改动没有新增跨服身份体系，也没有约束任意插件的原始数据库直写。

## 未确认结果

每次远端请求默认上限 5 秒。超时、断连或错误响应表示没有得到确认，不能当成账号不存在或写入未执行。

后续保存先核对原尝试：已经写入的结果只按本次标识确认；尚未执行的旧写入先通过版本条件作废，
再保存新意图。其他写入者的版本不会被旧副本接管，缺失／已重建账号也不能由旧副本覆盖。

新增检查还复现了原等待忽略线程中断的两项失败。
修复后，已中断的调用不发包；等待中的中断保留标记、取消本次回调并保留待核对尝试。
取消等待不等于取消远端副作用，恢复仍使用上述版本核对。

## 验证

- 远端账号专项 34 项，包含查询／校验返回的副本、同步／排队写入、旧档、
  删除／重建、ID／目标／连接变更、确认丢失、迟到写入、读服务不可用、外部版本、
  中断、int64 边界和 14 种非法请求。
- 最终专项合计 3 套、73 项通过；相关回归 22 套、421 项通过，失败、错误与跳过均为零。
- 使用实际客户端／服务端编解码和处理器，传输由可控字节连接替身提供。
  数据写入独立 Mongo 测试库，并保留同 ID 本地文档作对照。
  没有启动独立 WebSocket 集群，也没有对真实账号执行登录、重置或测试写入。
- 2,700 份 Java 主代码与测试匹配构建副本（允许换行差异）；应用类匹配编译输出，
  类改动仅属于本轮六个生产源码，默认资源和固定参考库未变。
