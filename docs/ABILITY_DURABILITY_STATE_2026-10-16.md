# 护盾条与修饰器耐久的服务端记录

## 本次接入

`AbilityManager` 现在接收实时消息 16 和 107，把已绑定普通实例的报告存入
`GameEntity.getAbilityDurability()`。读取 `snapshot()` 可取得不可修改的当前记录：

- 修饰器记录保留实际父能力实体、父能力名称、消息头及两个独立浮点字段。
- 护盾条按修饰器实例与 mixin local ID 分开保存，包含当前值、最大值、玩家数和元素。
- 同一实例的新报告覆盖旧报告，不保存无限增长的历史列表；未知 protobuf 字段保留。
- 零值和有限的负数／超出最大值的报告原样保存。NaN、无穷值和损坏编码在转发前拒绝。
- 107 只报告数值，不触发破盾动作。16 即使带 local ID，也不会被误派发到子动作。

记录绑定实际能力对象、修饰器控制器、所属场景和实体生命周期。
实例移除／替换、父能力替换、施法者离场或实体编号换成其他对象后，旧记录不能继续读取。
实体生命周期结束时清空记录。重复确认同一个仍在使用的控制器保留当前报告；
真正替换或删除实例才清除该实例的数据。

这是服务端内存中的当前状态，重启后不保留。返回的 `Snapshot` 是 Java 数据对象。

## 普通与其他来源的隔离

原先 `handleModifierChange` 中的来源分支写成 `if (false)`，
serverbuff／server 来源的增删消息可以操作普通修饰器的同一个实例 ID。
现在只有消息头 source=0 才进入普通控制器表；其他来源继续沿现有包处理器转发。
耐久消息自身的 serverbuff 标志为 true 时，也不会写入普通实例的记录。
目前尚未建立其他来源对应的服务端实例表。

这项判断使用当前客户端的 `OIAPAJELNJP`（类型 52881）原生解析／写入函数核对：

| 内容 | 原生偏移 | 编号 |
| --- | --- | --- |
| instanced_modifier_id | 0x28 | 3 |
| instanced_ability_id | 0x24 | 4 |
| source，枚举 CJBHMMGAICK | 0x1c | 10 |

写入函数 `0x14c641cb0` 使用 tag `0x50` 写 source；解析函数 `0x14c641810`
在相同 tag 下写入 `0x1c`。类型 52029 的 AppliedModifier 接入函数
`0x14a8156e0` 只剩 ILFix 包装器入口，尚未取得其实际消费代码。
