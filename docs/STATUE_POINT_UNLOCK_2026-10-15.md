# 神像点位识别与解锁奖励

参考 AstaPS 固定提交 `7cc148d1f752a43d4b9146b3b73f26875902546f` 的
`StatueTalkQuests`、`ExecUnlockPoint` 和解锁请求处理器，补齐按实际点位识别神像的行为。

## 接入

- `PointData.isStatue()` 统一识别：优先使用正的泉水容量；缺少时读取该点的 `gadgetId`，
  并核对当前 `GadgetExcelConfigData` 中的真实 `TransPointFirst` 类别。
- 普通解锁请求、任务执行器和管理命令共用进度管理器的资源分类。
  首次神像解锁奖励为既有的 5 原石、50 冒险阅历，普通锚点仍为 5 原石、10 冒险阅历。
- 任务不再依靠主任务 303／352 猜测点位类型。保留旧三参数接口供插件调用，
  但调用者的布尔提示不能改变真实点位奖励。
- 管理命令和距离回复使用相同识别规则，缺少泉水字段时不再丢失神像。
- 当前资源的 1515／1516／1517 点确实已有泉水字段；参考库注释所说的省略字段属于其他导出状态，
  不将其误报为本地三个点目前全部无法识别。
- 不使用固定新地区 gadget ID 清单或混淆类型名，也不在首次读取后永久缓存类别。

任务强锁仍拒绝客户端直接解锁。任务解除锁定、管理命令重复锁定／解锁均保留永久发现记录，
只有首次发现发放奖励。未接入参考库在登录时直接伪造全部神像对话任务完成的处理。
