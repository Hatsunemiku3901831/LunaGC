# 随机分支与回调目标

核对 AstaPS 和 LunaGC 7.1 的 `ActionRandomed` 参考实现，保留按配置概率选择分支的方式，
补齐条件、无效数值、子动作目标及服务端计时链处理。
当前角色资源有 195 个 `Randomed` 节点，其中 42 个带条件，12 个位于周期回调树中。
许多分支包含子弹、特效或未知条件，这些数量不代表玩法已经全部还原。

## 行为

- 原生随机分支先检查资源条件，条件不成立时不抽取概率，也不执行失败分支。
- 概率读取所属技能参数、战斗属性和全局值；合法范围是 0 到 1。
  除零、非有限数值及越界概率不执行任一分支，避免把无效计算变成失败分支的副作用。
- 概率 0 和 1 分别选择失败、成功分支；中间概率沿用参考实现的随机采样，
  一次调用只执行一个分支。没有把自动化用例描述为概率分布的统计验收。
- 原生随机、条件分支与 mixin 回调共用有序子动作分发：`Self` 保留在载体上，
  `Caster` 指向技能所属实体，`Target` 保留条件选择器实际选中的对象。
  全队动作使用队伍快照，逐个检查生命周期与子动作条件。
- 原生条件分支也检查父动作条件。条件不成立时不会通过默认成功分支改写状态。
- 子动作按配置顺序执行，前面的参数写入可被后面的治疗或数值动作读取。
  已移除或切场景的载体停止后续动作；原生嵌套回调限制到 32 层，退出后恢复线程状态。
- 完整动作树可识别时，随机分支可以参与周期、状态初始化与结束动作。
  验证同时包含成功和失败分支；即使概率恰好为 1，未选中的未知分支仍阻止服务端接管。
- 已由服务端执行的树包含两个分支的回调归属，客户端补发父节点或任一子节点不会重复结算。
  初始化与结束效果仍按实际变化发送数值通知。

没有扩大盲场景推测链的动作权限；其治疗子动作继续被拒绝，数值记录沿用通知抑制规则。
普通服务端定时效果与这条推测路径的通知行为不同，本批测试分别验证。

原生路径中的未知谓词、目标名和选择器仍沿用现有回退行为，没有宣称其语义全部已识别。
严格验证的服务端树继续拒绝未知动作或条件。
本批没有实现 `RandomAction`、丽莎的 `randomInRange` 抽样、完整元素球／子弹／特效链，
也没有据此宣布所有随机技能或全部角色完成。
