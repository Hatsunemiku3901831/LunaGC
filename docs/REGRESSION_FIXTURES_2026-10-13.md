# 全量回归夹具与独立启动检查

## 问题与修正

上一批全项目运行发现的剩余失败，本批逐项修复测试条件，未改动游戏生产代码。

| 测试 | 已确认原因 | 修正 |
| --- | --- | --- |
| 活动每日刷新两项 | 夹具没有世界、当前活动管理器及启用的任务系统，无法满足现有条件触发前提；固定旧包也失败 | 建立完整前提并恢复全局配置；额外覆盖无世界、关闭任务和替换管理器三种拒绝触发场景 |
| 班尼特实际治疗 | 夹具使用普通 GameEntity，真实资源只允许 Avatar；固定旧包也失败 | 使用 EntityAvatar，保留 70% 临界值、治疗量与高于临界值不治疗的断言 |
| 并发实体编号 | 已有第九种 PLAY_TEAM，测试仍断言八类共 1,600 次；旧包同样为 1,800 次 | 按所有实体类型计算总量，仍检查所有工作线程到达屏障、类型高位、共享序号唯一及连续范围 |
| 服务启动检查 | 与 Lua 资源测试共享 JVM，ScriptLoader 已初始化，启动失败 | 移至独立 serverSmokeTest JVM；按检查意图启动 dispatch，设置测试区服和临时 HTTP 端口，结束关闭 HTTP 与 Dispatch |

启动检查首次拆分后补齐区服，并先初始化 Grasscutter 再读取配置静态别名，避免测试设置产生初始化循环。
这些中间失败日志保留在 `debug/aster-mid-20261011/batch198/`，没有修改生产初始化语义。

## 执行方式

配置隔离测试 Mongo 后运行：

```powershell
.\gradlew.bat test serverSmokeTest -PskipHandbook=1 --console=plain
```

`test` 运行资源与 Java 测试；`serverSmokeTest` 运行原有两个实际 HTTP 检查。
`check` 依赖两者并保留原有格式检查。本批核对依赖图，不声称实际执行过完整 check。
