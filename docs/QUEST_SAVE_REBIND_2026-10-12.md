# 旧任务存档与资源条件重新绑定

## 本批范围

在任务加载时修复旧进度数组，并记录条件身份。资源调整目标顺序或增删目标后，
已识别的进度仍归属原目标。完成、失败条件分别处理，任务状态、时间戳和章节变量保持原值。
重新绑定只调整存档结构，不执行接取、完成、失败、发奖或数量条件刷新。
玩家的任务加载早于背包加载，因此不能在此阶段读取背包判定任务完成。

| 存档情况 | 处理方式 |
| --- | --- |
| 数组缺失 | 初始化为当前条件数量的零数组 |
| 旧数组没有条件身份，长度与当前一致 | 沿用原位置并补写身份 |
| 旧数组没有条件身份，长度不同 | 原值保存为旧数组备份；当前目标从零开始 |
| 已记录身份，目标重排 | 按身份移动进度 |
| 增加或替换目标 | 保留匹配目标，新目标从零开始 |
| 移除已识别目标 | 非零进度保存在暂存列表；相同目标恢复时可取回 |
| 显式重置任务 | 清空当前进度、暂存列表及旧数组备份 |

条件身份包含条件类型的数值、完整数字参数、规范化的目标次数及原字符串参数。
省略次数与明确的 `count: 1` 含义相同。相同条件重复出现时，按各自出现序号区分。
字符串身份保存在 BSON 字符串值中，含点号、美元符号和中文也可以往返保存。

**旧数组与当前长度相同，并不能证明条件没有变过。** 旧格式缺少身份信息，无法追溯
同长度的历史目标替换；本批保留既有位置约定。补写身份后的后续调整才可可靠匹配。
条件参数或目标次数改变会形成新身份，不能把此前计数直接赋给新目标。

## 章节加载与存档保护

先核对章节定义及全部已存子任务的 ID、章节归属，再安装运行对象和重新绑定进度。
缺少章节或子任务资源、ID 不一致时，整章暂缓加载，保留数据库原文档并记录警告。
暂缓期间，直接创建与重新接取入口均拒绝将该章节当成新任务，避免产生重复存档或新进度。
资源恢复后重新登录或重新加载可继续原进度。

冷读取时恢复章节的玩家与任务管理器引用。结构修复成功后，通过既有任务保存队列
写回新字段；未变化的记录不额外写入。本批沿用异步保存语义，数据库验证会等待队列完成。

本地在此基础上补充条件身份、已移除目标的进度保留、旧值备份与章节加载保护。
