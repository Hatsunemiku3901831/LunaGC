# 千星资产 GUID 复制与重新编号

GM「千星资产」中的 GIA 与节点结构 `.gia.json` 增加「复制并重新编号」。
原文件保留，副本单独按 SHA-256 归档；这项操作不会发布资产或执行节点。
导出的副本仍需在编辑器检查，并验证当前客户端是否支持。

## 使用

1. 导入文件，或找到已有归档。
2. 「复制 GUID 起点」留空时自动分配；也可填写正 int32 起点。
3. 点击「复制并重新编号」，查看数量、诊断和新文件。
4. 导出副本。重复相同操作会复用经过内容校验的副本，重启后仍可去重。

自动分配从 `1078000000` 与已知占用编号的最大值之后开始，
为本文件的完整资产顺序分配连续编号。检查整个归档，不受列表的前 100 项预览限制。
归档中的元数据、关联资产、依赖和已识别的类型引用都会参与冲突检查。
指定范围冲突或超过 int32 上限时显示原因，不写入副本。
同一 `MiliastraAssetStore` 实例串行处理并发请求；外部文件和其他进程的并发写入不在其分配保证内。

## 已识别的字段

| 内容 | 处理 |
|---|---|
| 实体 | `AssetMeta.asset_id` 与 `EntityData.entity_id` 一起更新 |
| 镜头 | 元数据编号及全部 `CameraDetail.camera_id` 一起更新 |
| 普通节点图 | 主编号、内层用户图编号和已知用户节点引用更新 |
| 关联与依赖 | 元数据编号仅在本次映射中存在时更新，外部引用保留 |
| 常量与变量 | 类型明确的服务端／客户端 GUID、GUID 列表、字典键值及具体类型包装中的 GUID 更新 |
| 结构引用 | 已知的 `structId` 字段按本次映射处理；结构定义资产本身暂不复制 |
| 其他编号 | 内置节点编号、节点索引、连接索引、模板号、普通整数、配置号和字符串按原义保留 |

仅支持版本 1 的实体（类型 3）、镜头（类型 13）及普通节点图
（9、10、11、22、23、46、47）。完整关联资产同样处理；仅含元数据的关联条目作为引用处理。
内外编号不一致、重复定义、未知资产类型、复合图（12）、结构定义（29）或不完整内容会被拒绝。
GIL／GIP／GIR 继续支持原文件归档与导出，尚不支持重新编号。

未知 protobuf 字段和不透明字节字段保留，不推测其中的 GUID。
根层不解释的字段按原始字节复制；修改过的资产单元重新编码，未知字段保留语义，
不承诺非规范 varint 或字段顺序保持原字节。恒等映射恢复完整原字节。
有不透明内容时显示检查关联引用的提示，因此不能把副本理解为所有隐藏引用均已重映射。

## 接口

`POST /gm/api/miliastra/{sha256}/remap?firstGuid=1100000000`

省略 `firstGuid` 即自动分配，沿用 GM token 和来源限制。新副本返回 201，复用返回 200。
返回 `asset`、`duplicate`、`guidCount`、`changedFields`、`mapping` 与 `warnings`。
`mapping` 只预览前 100 对，`guidCount` 和文件内处理覆盖全部定义；
映射预览没有作为独立完整清单持久化。原文件可继续通过原 SHA-256 下载。
参数或内容不支持返回 400，缺少权限返回 403，不存在返回 404，损坏的已存归档返回 500。
