# 天赋配置、技能次数与资源优先级

## 本批修复

额外技能等级现在读取配置中的实际增量，并保留同一配置中的多项增级。
原实现只保存最后一个技能位置，运行时固定加 3；例如当前 EnergyDisk 的
`Talent_RogueV2` 同时给元素战技与爆发加 1，原实现会丢失其中一项并使用错误增量。
普通攻击、元素战技、元素爆发继续按自己的技能组计算，遵守已有资源等级上限。

效果类型使用已核对的完整名称与现有混淆别名匹配。
未知类型即使带 `talentIndex` 也不会增级，名字包含已知类型的未知类型不会借此激活效果。
不支持的天赋类型、缺失增量、零 / 负增量、未知技能位置不会猜为加 3。
旧编译缓存只含 `extraTalentIndex` 时保留原有加 3 兼容行为；当前资源会覆盖同名缓存。
新编译缓存保留全部位置和增量，兼容项目现用的 Gson 2.9.0。

技能次数调整累加到当前角色的对应技能次数，不再让后一条覆盖前一条。
只接受当前技能库的主技能与子技能，保留魈的两处技能次数调整。
产生负次数或整数溢出的调整不生效。
多个已解锁命座一起重算；重复解锁与重算不叠加残留贡献。
命座重置立即恢复等级和技能次数，并通知客户端实际总加成或基础次数。
切换旅行者元素后按当前技能库重新计算，保存的其他元素命座仍保留。
登录数据公布前不发送增量等级或次数通知。

## 资源加载

启动时读取当前四个天赋目录：`EquipTalents`、`AvatarTalents`、`RelicTalents`、`TeamTalents`。
过去只读取前两个目录；存在 `OpenConfig.json` 时还会完全跳过当前源文件。
当前源定义优先，缓存中的独立扩展名称继续保留。
缓存与源文件的错误按行、定义、文件或目录隔离，缺少一个目录仍读取其余目录。

明确的空定义清除该名称的旧效果；整项不可读时保留其有效缓存后备。
未知类型的有效当前定义可以替换旧缓存，防止旧的增级字段重新生效。
文件按名字排序，按上述目录顺序读取，重名时使用后面的有效定义。
成功重读移除仅在旧内存中存在的条目；完全没有有效条目时保留此前目录并报错。
原缓存文件不会被重写。

这使更新后的源文件在下一次启动 / 显式加载时参与配置构建。
本批没有接入游戏在线期间的自动资源重载或已有角色状态自动刷新。
